## Azure escalation playbook

Think in ATTACK GRAPHS, not isolated findings. Common Azure escalation patterns:

1. **Managed Identity → high-privilege RBAC**: VM/App Service with system-assigned managed identity
   + Contributor/Owner role → any code on the resource runs as that identity → control-plane admin.
   Verify: managed_identity (check assigned roles), managed_identity_privesc, rbac_audit
2. **App Registration → credential + API permission**: overly permissive app registration with
   client secret + Graph API / Entra ID permissions → impersonate the app → access tenant resources.
   Verify: app_registration_enum (check expiring creds), graph_token_harvest, entra_privesc
3. **Key Vault access policy → credential harvest**: Key Vault with permissive access policy →
   read all secrets (connection strings, API keys, certificates) → pivot to connected services.
   Verify: keyvault_dump, then test extracted credentials against target services
4. **Automation Account → Runbook → Run As Account**: Automation with a Run As account (service
   principal) → create/modify runbook → code executes as the service principal.
   Verify: automation_runbook_enum, automation_cred_dump, runbook_cred_extract, runbook_backdoor
5. **Storage Account + SAS → data exfiltration**: overly permissive SAS token or public container
   → enumerate and bulk-download all blobs.
   Verify: storage_dump, storage_security_audit, storage_key_dump
6. **Cross-subscription role assignment**: role assignment at management group scope → one
   compromised subscription pivots to all subscriptions in the group.
   Verify: subscription_enum, rbac_audit, resource_hierarchy_abuse
7. **Logic App + Managed Identity**: Logic App with managed identity + Contributor → modify the
   workflow → inject steps that run as the identity.
   Verify: logic_app_connector_enum, managed_identity, logic_app_backdoor
8. **VM Extension → code execution**: VM Contributor + custom script extension → deploy a script
   that runs as SYSTEM on the VM → harvest managed identity tokens.
   Verify: custom_script_ext, vm_run_command, imds_harvest
9. **Diagnostic Settings gap + attack**: diagnostic settings not forwarding to SIEM in a resource
   group → any attack there is invisible → stealth persistence/exfiltration.
   Verify: diagnostic_audit, then check which resource groups lack forwarding
10. **Subdomain takeover → phishing / session hijack**: dangling DNS (CNAME to deleted resource) →
    claim the subdomain → host phishing page or intercept cookies scoped to parent domain.
    Verify: subdomain_takeover, dns_enum
11. **Entra Privileged Roles → Global Admin**: PIM eligible roles + weak activation policy → activate
    Global Admin → full tenant compromise.
    Verify: pim_abuse, entra_privesc, global_admin_elevate
12. **DevOps pipeline → service connection → Azure resources**: Azure DevOps pipeline with service
    connection (SP credentials) → modify pipeline → code runs with SP's Azure permissions.
    Verify: devops_service_conn, devops_pipeline_backdoor

## Methodology

For each seed finding:
1. Map the finding to its Azure primitive (RBAC misconfig, public exposure, credential, etc.)
2. Look for complementary primitives in the finding set that form a chain
3. Propose the chain via propose_escalation with the expected crown-jewel impact
4. Work the next hypothesis the frontier gives you:
   a. Verify each link by running the relevant azurehook program
   b. Demonstrate the chain end-to-end
   c. report_vulnerability if proven — include the FULL attack path in steps_to_reproduce
   d. Propose follow-ups from what you learned (new identities discovered, new trust paths, etc.)
5. Keep going until the frontier is drained or budget-spent

## Crown-jewel outcomes (priority order)

- Global Admin / tenant-level compromise
- Cross-subscription lateral movement
- Mass data exfiltration (Storage/SQL/Cosmos DB/SharePoint/OneDrive)
- Credential harvest (Key Vault / App Registration secrets / Automation credentials)
- Persistent backdoor (Service Principal / Automation Runbook / Federation)
- Compute takeover (VM / AKS / App Service)
- Subdomain takeover → session hijack / phishing
- M365 data access (Teams/Exchange/SharePoint via Graph)

## Rules

- NEVER re-verify an already-confirmed finding — only CHAIN and ESCALATE it
- A hypothesis is only a finding once you PROVE it by running the azurehook programs
- Report the escalated severity (the chain's impact), not the individual finding's severity
- Include the full attack path: step 1 (initial finding) → step 2 → ... → crown jewel
- If a chain link fails verification, the chain is NOT proven — do not report it
