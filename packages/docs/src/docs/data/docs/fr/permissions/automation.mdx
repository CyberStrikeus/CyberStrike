Lors des exécutions non interactives (`cyberstrike run`), personne ne peut répondre aux invites de permission — donc tout outil qui *demanderait* une approbation est **automatiquement rejeté**. Pour permettre à un pipeline de faire un travail réel, pré-approuvez les outils dont il a besoin.

<img src="/docs/images/diagrams/cicd-workflow.svg" alt="Flux de permission en mode headless : un outil pré-approuvé via CYBERSTRIKE_PERMISSION ou la configuration s'exécute ; un outil qui demanderait une approbation est automatiquement rejeté ; les résultats vont vers stdout en JSON" className="my-6 mx-auto max-w-sm" />

## Pré-approuver les outils

Il n'existe pas de drapeau « mode automatique ». Accordez les permissions de deux façons :

**1. Variable d'environnement `CYBERSTRIKE_PERMISSION`** — une map de permissions en JSON (même format que le champ de configuration `permission`) :

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
cyberstrike run "scan this codebase for security issues" --format json > report.json
```

**2. Configuration `permission`** — committez des valeurs par défaut sûres, refusez les parties dangereuses (voir [Motifs](/docs/permissions/patterns)) :

```json title="cyberstrike.json"
{
  "permission": {
    "read": "allow",
    "bash": { "*": "allow", "rm -rf *": "deny", "sudo *": "deny" },
    "edit": { "reports/**": "allow", ".env*": "deny" }
  }
}
```

La sortie va vers stdout ; utilisez `--format json` pour des résultats lisibles par machine.

## Intégration CI/CD

### GitHub Actions

```yaml title=".github/workflows/security-scan.yml"
name: Security Scan
on:
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @cyberstrike-io/cyberstrike@latest
      - name: Run Security Scan
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
        run: cyberstrike run "scan this codebase for security vulnerabilities" --format json > security-report.json
      - uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: security-report.json
```

### GitLab CI

```yaml title=".gitlab-ci.yml"
security-scan:
  image: node:20
  variables:
    CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'
  script:
    - npm install -g @cyberstrike-io/cyberstrike@latest
    - cyberstrike run "analyze code for vulnerabilities" --format json > report.json
  artifacts:
    paths:
      - report.json
```

## Exécutions par lots et planifiées

Bouclez sur les cibles, ou pilotez-le depuis cron — les mêmes règles `CYBERSTRIKE_PERMISSION` (ou de configuration) s'appliquent :

```bash title="scan-targets.sh"
#!/bin/bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow"}'
while read -r target; do
  cyberstrike run "scan $target for open ports and services" --format json > "reports/${target}.json"
done < targets.txt
```

```bash
# Scan quotidien à 02h00
0 2 * * * CYBERSTRIKE_PERMISSION='{"bash":"allow"}' /usr/local/bin/cyberstrike run "daily security scan" >> /var/log/cyberstrike.log 2>&1
```

## Codes de sortie et sortie

`cyberstrike run` écrit les résultats sur stdout (`--format json` pour le JSON) et retourne `0` en cas de succès, un code non nul en cas d'erreur ou d'interruption. Analysez le JSON pour les résultats :

```bash
cyberstrike run "scan target" --format json | jq '.'
```

## Considérations de sécurité

- **Moindre privilège** — n'autorisez (`allow`) que les outils nécessaires au travail ; gardez un `deny` explicite pour `rm -rf *`, `sudo *` et les chemins contenant des secrets.
- **Secrets** — injectez les clés API depuis le magasin de secrets de votre CI, ne les committez jamais.
- **Isolation** — exécutez dans un conteneur avec un réseau restreint si possible.

<Aside variant="caution">
  Gardez toujours des règles deny pour les commandes destructrices lorsque vous pré-approuvez `bash` en automatisation.
</Aside>
