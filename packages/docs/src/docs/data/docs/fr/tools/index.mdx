## Operations sur les fichiers

### Read

Lit le contenu d'un fichier avec les numeros de ligne. Prend en charge les fichiers texte, les images et les PDF.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `filePath` | string | Oui | Chemin vers le fichier (absolu ou relatif) |
| `offset` | number | Non | Numero de ligne de depart (indexe a 1) |
| `limit` | number | Non | Nombre de lignes a lire (defaut : 2000) |

#### Exemple

```json
{
  "filePath": "/path/to/file.txt",
  "offset": 100,
  "limit": 500
}
```

#### Format de sortie

```
00001| Premiere ligne de contenu
00002| Deuxieme ligne de contenu
00003| Troisieme ligne de contenu

(Fin du fichier - total 3 lignes)
```

#### Fonctionnalites

- Detection automatique des fichiers binaires
- Prise en charge des images et PDF (renvoie le contenu encode en base64)
- Troncature des lignes a 2000 caracteres
- Maximum 50 Ko par operation de lecture
- Suggestions intelligentes de fichiers en cas d'erreur de fichier introuvable

---

### Write

Cree ou ecrase un fichier avec un nouveau contenu.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `filePath` | string | Oui | Chemin absolu vers le fichier |
| `content` | string | Oui | Contenu a ecrire |

#### Exemple

```json
{
  "filePath": "/path/to/new-file.txt",
  "content": "Contenu du fichier ici"
}
```

#### Fonctionnalites

- Cree les repertoires parents si necessaire
- Genere un diff unifie pour revision
- Diagnostics LSP apres l'ecriture
- Suivi du temps de fichier pour la detection de conflits

---

### Edit

Effectue des operations de recherche et remplacement sur les fichiers avec correspondance intelligente.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `filePath` | string | Oui | Chemin absolu vers le fichier |
| `oldString` | string | Oui | Texte a rechercher et remplacer |
| `newString` | string | Oui | Texte de remplacement |
| `replaceAll` | boolean | Non | Remplacer toutes les occurrences (defaut : false) |

#### Exemple

```json
{
  "filePath": "/path/to/file.ts",
  "oldString": "function oldName(",
  "newString": "function newName(",
  "replaceAll": false
}
```

#### Correspondance intelligente

L'outil Edit utilise plusieurs strategies de correspondance :

1. **Remplacement simple** : Correspondance exacte de chaine
2. **Lignes ajustees** : Ignore les espaces en debut/fin de ligne
3. **Ancrage de bloc** : Correspond aux premiere et derniere lignes, milieu flou
4. **Espaces normalises** : Reduit les espaces multiples
5. **Indentation flexible** : Ignore les differences d'indentation
6. **Echappement normalise** : Gere les sequences d'echappement
7. **Sensible au contexte** : Utilise le contexte environnant pour la correspondance

#### Fonctionnalites

- Generation de diff unifie
- Diagnostics LSP apres l'edition
- Detection des occurrences multiples
- Prevention des conflits via le suivi du temps de fichier

---

### Glob

Trouve les fichiers correspondant a un motif glob.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `pattern` | string | Oui | Motif glob (ex. `**/*.ts`) |
| `path` | string | Non | Repertoire de recherche (defaut : repertoire courant) |

#### Exemple

```json
{
  "pattern": "**/*.{ts,tsx}",
  "path": "/path/to/project"
}
```

#### Sortie

Renvoie les chemins de fichiers tries par date de modification (plus recent en premier), limites a 100 resultats.

#### Exemples de motifs

| Motif | Correspondances |
|-------|-----------------|
| `*.ts` | Fichiers TypeScript dans le repertoire courant |
| `**/*.ts` | Fichiers TypeScript recursivement |
| `src/**/*.{ts,tsx}` | Fichiers TS/TSX dans le repertoire src |
| `!**/node_modules/**` | Exclure node_modules |

---

### Grep

Recherche dans le contenu des fichiers a l'aide de motifs regex. Base sur ripgrep.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `pattern` | string | Oui | Motif regex a rechercher |
| `path` | string | Non | Repertoire de recherche (defaut : repertoire courant) |
| `include` | string | Non | Filtre de motif de fichier (ex. `*.js`) |

#### Exemple

```json
{
  "pattern": "password|secret|api_key",
  "path": "/path/to/project",
  "include": "*.{js,ts,py}"
}
```

#### Format de sortie

```
5 correspondances trouvees

/path/to/file.ts:
  Ligne 42: const apiKey = process.env.API_KEY
  Ligne 85: // TODO: supprimer le secret code en dur

/path/to/config.js:
  Ligne 12: password: "changeme"
```

#### Fonctionnalites

- Support regex (syntaxe ripgrep)
- Recherche dans les fichiers caches
- Suivi des liens symboliques
- Resultats tries par date de modification
- Maximum 100 resultats

## Execution de commandes

### Bash

Execute des commandes shell avec timeout et capture de sortie.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `command` | string | Oui | Commande a executer |
| `timeout` | number | Non | Timeout en millisecondes (defaut : 120000) |
| `workdir` | string | Non | Repertoire de travail |
| `description` | string | Oui | Breve description de l'objectif de la commande |

#### Exemple

```json
{
  "command": "nmap -sV -sC target.com",
  "timeout": 300000,
  "workdir": "/path/to/project",
  "description": "Scanner la cible pour les ports ouverts et les services"
}
```

#### Fonctionnalites

- Detection du shell (bash/zsh/sh)
- Arret de l'arbre de processus en cas de timeout
- Integration du systeme de permissions
- Streaming de sortie en temps reel
- Controle d'acces aux repertoires externes

#### Considerations de securite

Les commandes sont analysees avec tree-sitter pour detecter :
- L'acces aux repertoires en dehors du projet
- Les motifs de commandes dangereux
- Les modifications du systeme de fichiers

## Systeme de memoire

Cyberstrike inclut un systeme de memoire persistante pour stocker le contexte entre les sessions.

### Memory Write

Stocke des informations dans la memoire persistante.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `content` | string | Oui | Contenu a stocker |
| `type` | string | Non | `long_term` pour MEMORY.md, `daily` pour les notes datees |
| `title` | string | Non | Titre optionnel pour l'entree |

#### Exemple

```json
{
  "content": "La cible utilise PostgreSQL 14.2 sur le port 5432",
  "type": "long_term",
  "title": "Configuration de la base de donnees"
}
```

#### Types de memoire

| Type | Stockage | Objectif |
|------|----------|----------|
| `long_term` | `.cyberstrike/MEMORY.md` | Decisions, preferences, faits importants |
| `daily` | `.cyberstrike/memory/YYYY-MM-DD.md` | Notes de session, contexte temporaire |

---

### Memory Search

Recherche dans la memoire stockee.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `query` | string | Oui | Mots-cles ou phrases de recherche |

#### Exemple

```json
{
  "query": "identifiants de la base de donnees"
}
```

---

### Memory Read

Lit des fichiers de memoire specifiques.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `file` | string | Oui | Identifiant du fichier |

#### Identifiants de fichiers

| Identifiant | Description |
|-------------|-------------|
| `long_term` | Memoire a long terme (MEMORY.md) |
| `today` | Notes quotidiennes du jour |
| `yesterday` | Notes de la veille |
| `YYYY-MM-DD` | Notes d'une date specifique |
| `list` | Lister tous les fichiers de memoire |

---

### Memory Context

Recupere le contexte complet de la memoire pour la session.

#### Parametres

Aucun requis.

#### Exemple

```json
{}
```

Renvoie la memoire a long terme combinee avec les notes quotidiennes recentes.

## Chargement dynamique d'outils

<img src="/docs/images/diagrams/tool-interaction-flow.svg" alt="Comment un outil devient disponible : les outils integres sont appeles directement ; les outils MCP sont trouves avec tool_search, charges avec load_tools, puis appelables, et liberes avec unload_tools" className="my-6 mx-auto max-w-sm" />

Cyberstrike prend en charge le chargement dynamique d'outils pour les serveurs MCP (Model Context Protocol). Cela permet d'acceder a des centaines d'outils sans surcharger la fenetre de contexte.

### Tool Search

Recherche les outils MCP disponibles par capacite.

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `query` | string | Oui | Description de la capacite |
| `limit` | number | Non | Nombre maximum de resultats (defaut : 5) |

#### Exemple

```json
{
  "query": "test d'injection SQL",
  "limit": 10
}
```

#### Sortie

```
3 outils trouves :

1. sqlmap_scan
   Scanner d'injection SQL utilisant sqlmap
   Tokens estimes : ~500

2. nuclei_sqli
   Templates Nuclei pour l'injection SQL
   Tokens estimes : ~300

3. manual_sqli
   Payloads d'injection SQL manuels
   Tokens estimes : ~200
```

## Gestion des taches

### Task

Delegue le travail a un sous-agent. C'est ainsi que l'agent principal envoie des sous-agents specialises (voir [Agents](/docs/agents)).

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `description` | string | Oui | Breve description de la tache (3-5 mots) |
| `prompt` | string | Oui | La tache que le sous-agent doit effectuer |
| `subagent_type` | string | Oui | Quel sous-agent envoyer (ex. `web-application`, `general`) |

---

### TodoWrite

#### Parametres

| Parametre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `tasks` | array | Oui | Tableau d'objets de tache |

#### Objet de tache

```json
{
  "id": "1",
  "content": "Scanner les ports ouverts",
  "status": "pending",
  "priority": "high"

```

## Permissions des outils

Chaque outil necessite des permissions specifiques qui peuvent etre configurees :

| Permission | Outils | Defaut |
|------------|--------|--------|
| `read` | Read | ask |
| `edit` | Write, Edit | ask |
| `glob` | Glob | allow |
| `grep` | Grep | allow |
| `bash` | Bash | ask |
| `websearch` | WebSearch | ask |
| `webfetch` | WebFetch | ask |
| `codesearch` | CodeSearch | ask |
| `task` | Task | ask |
| `external_directory` | Acces en dehors du projet | ask |

### Configuration

```json
{
  "permission": {
    "bash": "ask",
    "edit": "allow",
    "read": "allow",
    "glob": "allow",
    "grep": "allow"
  }
}
```

### Actions de permission

| Action | Description |
|--------|-------------|
| `ask` | Demander l'approbation de l'utilisateur |
| `allow` | Approuver automatiquement sans demander |
| `deny` | Bloquer l'utilisation de l'outil |

Voir [Permissions](/docs/permissions) pour le modele complet et les motifs glob.

## Creer des outils personnalises

Ajoutez des outils personnalises en creant des fichiers dans `.cyberstrike/tools/` :

```typescript title=".cyberstrike/tools/custom-scanner.ts"
import { z } from "zod"

export default {
  description: "Scanner de vulnerabilites personnalise",
  args: {
    target: z.string().describe("URL cible a scanner"),
    depth: z.number().default(3).describe("Profondeur du scan"),
  },
  async execute(args, ctx): Promise<string> {
    const { target, depth } = args
    // Logique de scan personnalisee
    return `Scanne ${target} jusqu'a la profondeur ${depth}`
  },
}
```

Les fichiers dans un repertoire `tool/` ou `tools/` a l'interieur de tout dossier `.cyberstrike/` sont charges automatiquement.

### Schema de definition d'outil

| Champ | Type | Description |
|-------|------|-------------|
| `description` | string | Description de l'outil montree au modele |
| `args` | object | Correspondance nom de parametre vers schema Zod |
| `execute` | function | `async (args, ctx) => string` |

## Outils de serveurs MCP

Cyberstrike peut charger des outils depuis des serveurs MCP. L'approche recommandee est [Bolt](/docs/features/bolt), qui fournit des outils de securite via un conteneur Docker avec un systeme de plugins :

```json title="cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true
    }
  }
}
```

Les outils MCP deviennent disponibles comme appels d'outils directs -- chaque plugin est appele directement par son nom (ex. `nmap`, `nuclei`, `ffuf`).

<Aside variant="tip">
  Voir [Bolt](/docs/features/bolt) pour la configuration recommandee des outils de securite — 7 plugins plus environ 26 serveurs MCP agreges, tous disponibles comme appels d'outils directs.
</Aside>
