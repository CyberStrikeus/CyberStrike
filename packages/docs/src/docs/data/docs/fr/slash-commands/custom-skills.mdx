Une skill est un fichier Markdown de méthodologie réutilisable que l'agent peut intégrer à la demande. Les skills sont découvertes par leur nom de fichier — chaque skill réside dans un fichier nommé **`SKILL.md`**.

## Fichier et emplacement

Le fichier doit être nommé `SKILL.md`. Cyberstrike recherche les `**/SKILL.md` dans un répertoire `skill/` ou `skills/` à l'intérieur de `.cyberstrike/`, ainsi que dans `skills/` (disposition Claude Code) :

```
.cyberstrike/
└── skills/
    └── sql-injection/
        └── SKILL.md
```

## Frontmatter

Seuls `name` et `description` sont obligatoires. Le reste est constitué de métadonnées optionnelles utilisées pour la catégorisation et le chaînage dans la kill-chain :

```markdown title="SKILL.md"
---
name: sql-injection
description: Methodology for testing SQL injection
version: "1.0.0"
author: you
tags: [injection, database]
category: injection
owasp_id: WSTG-INPV-05
tech_stack: [postgres, mysql]
cwe_ids: [CWE-89]
chains_with: [auth-bypass]
prerequisites: [request-capture]
---

Walk the tester through boolean-, error-, time-, and union-based SQLi:
1. Identify injectable parameters …
2. …
```

<Aside variant="caution">
  Le corps est du Markdown simple — il n'y a **pas** de templating (pas de `{{target}}`, `{% if %}`, `{% for %}` ou `$ARGUMENTS`). Le frontmatter ne prend **pas** en charge les champs `args`, `model`, `agent` ou `permission`, et le fichier doit être littéralement nommé `SKILL.md` (les noms arbitraires comme `my-skill.md` ne sont pas chargés).
</Aside>

Le `name` dans le frontmatter doit correspondre à l'identité de la skill — une incompatibilité est signalée comme une erreur.

## Utiliser les skills

Les skills chargées sont disponibles pour l'agent et peuvent être parcourues avec la commande `/skills`. L'agent intègre la méthodologie d'une skill dans le contexte lorsqu'elle est pertinente pour la tâche.
