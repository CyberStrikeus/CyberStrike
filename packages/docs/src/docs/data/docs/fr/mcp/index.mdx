Cyberstrike utilise le Model Context Protocol (MCP) pour integrer des outils externes. **Bolt** est notre serveur d'outils conteneurise qui fournit un large ensemble d'outils de securite ; vous pouvez egalement connecter tout serveur MCP local ou distant.

## Deux facons d'ajouter des outils

| Approche | Transport | Avantages | Inconvenients |
|----------|-----------|-----------|---------------|
| **Bolt** (recommande) | StreamableHTTP | Outils pre-installes, isolation par conteneur, configuration facile | Docker requis, latence reseau |
| **MCP local / distant** | stdio / StreamableHTTP | N'importe quel serveur MCP ; latence nulle en local | Vous installez et executez le serveur |

Cyberstrike est egalement livre avec trois serveurs MCP actives par defaut : `github-security`, `cve` et `osint`. Votre propre configuration est fusionnee par-dessus.

## Bolt

Bolt execute des outils de securite dans un conteneur Docker (Ubuntu 24.04, port 3001). Il expose **7 plugins natifs** (`subfinder`, `nmap`, `nuclei`, `httpx`, `ffuf`, `run-command`, `wordlist`) plus **~26 serveurs MCP stdio agreges** (`dnsx`, `amass`, `katana`, `sqlmap`, `wpscan`, `hydra`, `hashcat`, et plus). Chaque outil est directement appelable — l'agent l'invoque en un seul tour.

Bolt est configure sous sa **propre cle de premier niveau `bolt`** (pas `mcp`) et authentifie par appairage Ed25519 :

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": { "url": "http://localhost:3001" }
  }
}
```

Voir la page [Bolt](/fr/docs/mcp/bolt) pour la configuration et l'appairage.

## MCP local / distant

Tout autre serveur MCP va sous la map plate `mcp`, identifie par nom :

```json title="cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["your-mcp-server"]
    }
  }
}
```

- [Serveurs locaux](/fr/docs/mcp/local-servers) — processus enfants stdio
- [Serveurs distants](/fr/docs/mcp/remote-servers) — StreamableHTTP/SSE, avec [OAuth](/fr/docs/mcp/oauth) optionnel

## Gestion TUI

Deux boites de dialogue separees :

- **`/bolt`** — gerer les serveurs Bolt (ajouter et appairer, basculer, supprimer).
- **`/mcps`** — gerer les serveurs MCP locaux/distants.

Dans les deux : **a** pour ajouter, **espace** pour basculer un serveur, **esc** pour fermer.

## Compatibilite des modeles

<Aside variant="caution">
  Les modeles bases sur des sous-processus ne peuvent pas acceder aux outils MCP. Utilisez un modele a API directe pour une integration complete Bolt/MCP.
</Aside>

Les modeles a API directe (par ex. `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`) s'executent au sein de Cyberstrike et ont un acces complet au MCP. Les modeles qui delegent a un processus CLI separe ne l'ont pas.

## Priorite de configuration

Les entrees MCP et Bolt suivent la [hierarchie de configuration](/fr/docs/configuration#configuration-hierarchy) standard : le repertoire `.cyberstrike/` du projet prime sur le `cyberstrike.json` du projet, qui prime sur la configuration globale `~/.config/cyberstrike/`, qui prime sur les serveurs integres.
