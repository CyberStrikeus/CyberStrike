## Fichier et emplacement

Les agents personnalises sont des fichiers `*.md` dans un repertoire `agent/` ou `agents/` a l'interieur de n'importe quel dossier `.cyberstrike/` (projet ou `~/.cyberstrike/`). L'identifiant de l'agent est son nom de fichier.

```
.cyberstrike/
└── agents/
    ├── api-security.md
    └── compliance-audit.md
```

## En-tete (frontmatter)

```markdown title=".cyberstrike/agents/api-security.md"
---
description: Specialized agent for REST and GraphQL API testing
mode: primary
model: anthropic/claude-sonnet-4-20250514
permission:
  bash: { "*": "ask", "rm -rf *": "deny" }
  edit: allow
---

You are an expert API security tester specializing in REST and GraphQL APIs.
Follow the OWASP API Security Top 10 …
```

Le corps (apres l'en-tete) est le prompt systeme.

| Champ | Type | Description |
|-------|------|-------------|
| `description` | string | A quoi sert l'agent |
| `mode` | `primary` \| `subagent` \| `all` | Les agents `primary` peuvent etre executes directement ; les agents `subagent` sont delegues via l'outil de taches |
| `model` | string | Remplacement `fournisseur/modele` |
| `temperature`, `top_p` | number | Controles d'echantillonnage |
| `steps` | number | Nombre maximal d'iterations agentiques |
| `color` | string | Couleur hexadecimale ou couleur du theme |
| `permission` | object | Permissions par outil (voir [Permissions](/docs/permissions)) |
| `hidden`, `disable` | boolean | Masquer du selecteur / desactiver |

<Aside variant="caution">
  Restreignez les outils avec le champ `permission`. L'ancienne map `tools:` est **obsolete**, et il n'existe pas de champ `allowedCommands` -- les restrictions de commandes sont des regles glob `permission.bash` (ex. `bash: { "nmap *": "allow" }`).
</Aside>

## Primaire vs sous-agent

Seuls les agents **primaires** peuvent etre selectionnes avec `--agent` ou `default_agent`. Si vous voulez que votre agent soit executable directement, definissez `mode: primary`. Sinon, il se comporte comme un sous-agent auquel l'agent `cyberstrike` peut deleguer.

```markdown
---
description: Read-only auditor
mode: primary
permission:
  edit: deny
  bash: deny
  read: allow
  glob: allow
  grep: allow
---

You are a read-only security auditor …
```

## Utiliser un agent personnalise

Une fois que c'est un agent primaire, selectionnez-le :

```bash
cyberstrike --agent api-security
```

Ou definissez-le comme agent par defaut dans `cyberstrike.json` :

```json
{
  "default_agent": "api-security"
}
```

Parcourez les agents dans le TUI avec `/agents`.

## Bonnes pratiques

1. **Perimetre cible** -- un seul objectif clair par agent.
2. **Moindre privilege** -- n'autorisez que les outils dont l'agent a besoin via `permission`.
3. **Prompt clair** -- soyez precis sur la methodologie et le format de sortie.
4. **Controle de version** -- commitez `.cyberstrike/agents/` avec le projet.
