OAuth Cyberstrike को लंबे समय तक चलने वाले क्रेडेंशियल्स संग्रहित किए बिना रिमोट MCP सर्वर के साथ प्रमाणित करने देता है। Cyberstrike सर्वर के OAuth एंडपॉइंट्स को स्वचालित रूप से खोजता है — आप केवल तब क्लाइंट विवरण प्रदान करते हैं जब सर्वर को उनकी आवश्यकता हो।

## कॉन्फ़िगरेशन स्कीमा

OAuth एक **remote** MCP सर्वर पर एक वैकल्पिक ब्लॉक है। पूर्ण स्कीमा में केवल तीन वैकल्पिक फ़ील्ड हैं:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "clientId": "{env:OAUTH_CLIENT_ID}",
        "clientSecret": "{env:OAUTH_CLIENT_SECRET}",
        "scope": "read write"
      }
    }
  }
}
```

| फ़ील्ड | टाइप | विवरण |
|-------|------|-------------|
| `clientId` | string | वैकल्पिक। यदि छोड़ दिया जाए, तो **डायनामिक क्लाइंट पंजीकरण (RFC 7591)** का प्रयास किया जाता है। |
| `clientSecret` | string | वैकल्पिक। केवल तब जब प्राधिकरण सर्वर को गोपनीय क्लाइंट की आवश्यकता हो। |
| `scope` | string | वैकल्पिक। प्राधिकरण के दौरान अनुरोध किए जाने वाले स्कोप। |

<Aside variant="caution">
  प्राधिकरण और टोकन URL यहाँ कॉन्फ़िगर **नहीं** किए जाते — Cyberstrike उन्हें सर्वर के OAuth मेटाडेटा से खोजता है। `authorizationUrl`, `tokenUrl`, `pkce`, `deviceAuthorizationUrl`, `grantType`, और `callbackPort`/`callbackPath` जैसे फ़ील्ड स्कीमा में **मौजूद नहीं** हैं (केवल `clientId`, `clientSecret`, `scope`)।
</Aside>

## यह कैसे काम करता है

1. Cyberstrike डिटेक्ट करता है कि रिमोट सर्वर को OAuth की आवश्यकता है (इसके मेटाडेटा से)।
2. यदि कोई `clientId` सेट नहीं है, तो यह डायनामिक रूप से एक क्लाइंट पंजीकृत करता है (RFC 7591)।
3. यह आपके ब्राउज़र को प्राधिकरण URL पर खोलता है; आप लॉग इन करते हैं और पहुँच प्रदान करते हैं।
4. प्राधिकरण कोड का आंतरिक रूप से संभाले गए स्थानीय कॉलबैक पर टोकन के लिए आदान-प्रदान किया जाता है।
5. टोकन Cyberstrike द्वारा संग्रहित किए जाते हैं और समाप्त होने पर स्वचालित रूप से रिफ्रेश किए जाते हैं।

OAuth ऑटो-डिटेक्शन से पूरी तरह बाहर निकलने के लिए सर्वर पर `"oauth": false` सेट करें।

## सर्वर को प्राधिकृत करना

CLI से प्राधिकरण ट्रिगर करें:

```bash
cyberstrike mcp auth <name>       # सर्वर को प्राधिकृत करें
cyberstrike mcp auth list         # OAuth-प्राधिकृत सर्वर सूचीबद्ध करें
cyberstrike mcp logout <name>     # संग्रहित OAuth क्रेडेंशियल्स हटाएं
```

Cyberstrike पहली बार OAuth-संरक्षित सर्वर का उपयोग करते समय स्वचालित रूप से प्राधिकरण का अनुरोध भी करता है। टोकन रिफ्रेश स्वचालित है — कोई मैनुअल रिफ्रेश कमांड नहीं है।

## उदाहरण: एक स्कोप्ड सर्वर

```json
{
  "mcp": {
    "example-mcp": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "scope": "openid profile email"
      }
    }
  }
}
```

बिना `clientId` के, Cyberstrike डायनामिक रूप से एक क्लाइंट पंजीकृत करता है, फिर अनुरोधित स्कोप के साथ प्राधिकृत करता है।

## सुरक्षा नोट्स

- `{env:VAR}` से सीक्रेट्स का संदर्भ दें — `clientSecret` को कभी संस्करण नियंत्रण में कमिट न करें।
- सर्वर को जिन न्यूनतम स्कोप की आवश्यकता है, उनका अनुरोध करें।
- जब क्रेडेंशियल्स की अब आवश्यकता न हो तो `cyberstrike mcp logout <name>` से हटाएं।

## समस्या निवारण

- **प्राधिकरण विफल** — पुष्टि करें कि सर्वर URL पहुँच योग्य है और (यदि सर्वर को गोपनीय क्लाइंट की आवश्यकता है) `clientId`/`clientSecret` सही हैं।
- **बार-बार प्रमाणीकरण अनुरोध** — संग्रहित टोकन सर्वर-साइड रद्द किया गया हो सकता है; फिर से `cyberstrike mcp auth <name>` चलाएं।
- **कॉलबैक टाइमआउट** — सुनिश्चित करें कि आपके ब्राउज़र ने लॉगिन पूरा किया और कोई स्थानीय फ़ायरवॉल लूपबैक कॉलबैक को ब्लॉक नहीं कर रहा।
- `cyberstrike mcp debug <name>` से सर्वर के कनेक्शन का निरीक्षण करें।
