## शुरू करना

वेब इंटरफ़ेस लॉन्च करें:

```bash
cyberstrike web
```

यह `127.0.0.1` पर एक लोकल सर्वर शुरू करता है (डिफ़ॉल्ट पोर्ट `4096`) और आपके डिफ़ॉल्ट ब्राउज़र में CyberStrike खोलता है।

<Aside variant="caution">
  **सुरक्षा:** यदि `CYBERSTRIKE_SERVER_PASSWORD` सेट नहीं है, तो सर्वर असुरक्षित होगा। लोकल उपयोग के लिए यह ठीक है लेकिन नेटवर्क एक्सेस के लिए इसे **अवश्य सेट करें**।
</Aside>

<Aside variant="info">
  **Windows:** उचित फ़ाइल सिस्टम और टर्मिनल एकीकरण के लिए इस कमांड को PowerShell के बजाय WSL से चलाएँ।
</Aside>

## कॉन्फ़िगरेशन

### पोर्ट

```bash
cyberstrike web --port 4096
```

डिफ़ॉल्ट रूप से, सिस्टम स्वचालित रूप से एक उपलब्ध पोर्ट चुनता है।

### होस्टनेम

```bash
# केवल Localhost (डिफ़ॉल्ट)
cyberstrike web --hostname 127.0.0.1

# आपके नेटवर्क में एक्सेसिबल
cyberstrike web --hostname 0.0.0.0
```

### mDNS डिस्कवरी

लोकल नेटवर्क डिस्कवरेबिलिटी सक्षम करें। स्वचालित रूप से होस्टनेम `0.0.0.0` पर सेट करता है।

```bash
cyberstrike web --mdns
```

कस्टम डोमेन के साथ:

```bash
cyberstrike web --mdns --mdns-domain myproject.local
```

### CORS

विशिष्ट डोमेन से क्रॉस-ऑरिजिन रिक्वेस्ट की अनुमति दें:

```bash
cyberstrike web --cors https://example.com
```

### प्रमाणीकरण

```bash
CYBERSTRIKE_SERVER_PASSWORD=secret cyberstrike web
```

डिफ़ॉल्ट उपयोगकर्ता नाम `cyberstrike` है, `CYBERSTRIKE_SERVER_USERNAME` के माध्यम से बदला जा सकता है।

## सुविधाएँ

वेब इंटरफ़ेस में शामिल हैं:

- **सेशन प्रबंधन** -- सेशन बनाएँ, स्विच करें, आर्काइव करें और हटाएँ
- **साइड पैनल टैब्स** -- MCP, Bolt, भेद्यताएँ, Web Context और Todo ट्रैकिंग
- **फ़ाइल ब्राउज़र** -- डिफ़ हाइलाइटिंग के साथ प्रोजेक्ट फ़ाइलें देखें और नेविगेट करें
- **रिव्यू पैनल** -- स्वीकार करने से पहले AI-जनित कोड परिवर्तनों की समीक्षा करें
- **टर्मिनल** -- ब्राउज़र के भीतर एकीकृत टर्मिनल टैब्स
- **रियल-टाइम अपडेट** -- लाइव एजेंट आउटपुट के लिए SSE स्ट्रीमिंग
- **अपडेट सूचनाएँ** -- नई CyberStrike रिलीज़ के लिए स्वचालित पोलिंग

### Web Context पैनल

[Chrome Capture एक्सटेंशन](https://github.com/CyberStrikeus/cyberstrike-chrome-ext) के साथ पेयर करने पर, साइड पैनल में Web टैब प्रदर्शित करता है:

- **एंडपॉइंट्स** -- मेथड और पथ के साथ कैप्चर किए गए HTTP रिक्वेस्ट
- **भूमिकाएँ** -- पहचानी गई उपयोगकर्ता भूमिकाएँ और अनुमति स्तर
- **क्रेडेंशियल्स** -- प्रमाणीकरण टोकन और सेशन पहचानकर्ता
- **ऑब्जेक्ट्स** -- API रिस्पॉन्स में खोजे गए डेटा ऑब्जेक्ट
- **फ़ंक्शन** -- ट्रैफ़िक पैटर्न से मैप किए गए CRUD ऑपरेशन

## टर्मिनल अटैचमेंट

वेब सर्वर और TUI को एक साथ चलाएँ, समान सेशन शेयर करते हुए:

```bash
# टर्मिनल 1: वेब सर्वर शुरू करें
cyberstrike web --port 4096

# टर्मिनल 2: उसी सर्वर से TUI अटैच करें
cyberstrike attach http://localhost:4096
```

दोनों इंटरफ़ेस रियल-टाइम में समान सेशन, संदेश और एजेंट गतिविधि देखते हैं।

## रिमोट एक्सेस

CyberStrike सुरक्षित रिमोट एक्सेस का समर्थन करता है, जिससे आप एक मशीन पर सर्वर चला सकते हैं और कहीं से भी कनेक्ट कर सकते हैं। यह इसके लिए उपयोगी है:

- लैपटॉप से नियंत्रण करते हुए शक्तिशाली वर्कस्टेशन पर मूल्यांकन चलाना
- शेयर्ड सर्वर के माध्यम से टीम सहयोग
- स्थानीय इंस्टॉलेशन के बिना `app.cyberstrike.io` से CyberStrike एक्सेस करना
- हल्की मशीन से ऑपरेट करते हुए GPU सर्वर पर स्थानीय LLM (Ollama, vLLM) का उपयोग करना

### Cloudflare Tunnel (अनुशंसित)

[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) आपके CyberStrike सर्वर और इंटरनेट के बीच बिना किसी पोर्ट एक्सपोज़ किए एक सुरक्षित, एन्क्रिप्टेड कनेक्शन बनाता है।

#### Quick Tunnel

शुरू करने का सबसे तेज़ तरीका -- Cloudflare अकाउंट आवश्यक नहीं:

```bash
# टर्मिनल 1: पासवर्ड के साथ CyberStrike शुरू करें
CYBERSTRIKE_SERVER_PASSWORD=your-secret cyberstrike web --port 4096

# टर्मिनल 2: क्विक टनल बनाएँ
cloudflared tunnel --url http://localhost:4096
```

`cloudflared` एक पब्लिक URL आउटपुट करता है जैसे `https://random-words.trycloudflare.com`। किसी भी ब्राउज़र से CyberStrike एक्सेस करने के लिए इस URL को अपने क्रेडेंशियल्स के साथ शेयर करें।

<Aside variant="caution">
  **पासवर्ड आवश्यक।** CyberStrike `CYBERSTRIKE_SERVER_PASSWORD` के बिना सर्वर मोड में शुरू होने से मना करता है। यह डिज़ाइन द्वारा लागू है -- सर्वर इसके बिना नहीं चलेगा।
</Aside>

#### कस्टम डोमेन के साथ Named Tunnel

स्थायी एक्सेस के लिए, अपने डोमेन से जुड़ा नेम्ड टनल बनाएँ:

```bash
# टर्मिनल 1: पासवर्ड के साथ CyberStrike शुरू करें
CYBERSTRIKE_SERVER_PASSWORD=your-secret cyberstrike web --port 4096

# टर्मिनल 2: एक बार का सेटअप
cloudflared tunnel login
cloudflared tunnel create cyberstrike
cloudflared tunnel route dns cyberstrike pentest.your-domain.com

# टनल चलाएँ
cloudflared tunnel run --url http://localhost:4096 cyberstrike
```

<Aside variant="caution">
  **`pentest.your-domain.com` को बदलें** उस डोमेन के सबडोमेन से जो आपने Cloudflare में जोड़ा है। उदाहरण: `pentest.example.com` → `pentest.mydomain.com`। Cloudflare द्वारा प्रबंधित न किए जाने वाले डोमेन का उपयोग करने से DNS रिज़ॉल्यूशन विफलताएँ होंगी।
</Aside>

<Aside variant="info">
  **नया डोमेन?** यदि आपने हाल ही में अपना डोमेन Cloudflare में जोड़ा है, तो नेमसर्वर प्रोपेगेशन आपके रजिस्ट्रार के आधार पर 1-24 घंटे ले सकता है। प्रोपेगेशन पूरा होने तक DNS रूट रिज़ॉल्व नहीं होंगे। अपने Cloudflare डैशबोर्ड में **Overview** के तहत स्थिति जाँचें।
</Aside>

यह आपको `https://pentest.your-domain.com` पर एक स्थिर URL देता है जो रीस्टार्ट के बाद भी बना रहता है।

अपना सेटअप काम कर रहा है यह सत्यापित करने के लिए:

```bash
# टनल कनेक्शन स्थिति जाँचें
cloudflared tunnel info cyberstrike

# DNS रिज़ॉल्व हो रहा है जाँचें
dig pentest.your-domain.com CNAME
```

<Aside variant="info">
  **cloudflared इंस्टॉल करें:** `brew install cloudflared` (macOS), `apt install cloudflared` (Debian/Ubuntu), या [Cloudflare की रिलीज़](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) से डाउनलोड करें।
</Aside>

#### टनल के साथ प्रमाणीकरण कैसे काम करता है

CyberStrike का auth मिडलवेयर टनल-अवेयर है। भले ही `cloudflared` `127.0.0.1` से कनेक्ट होता है, सर्वर प्रॉक्सी हेडर्स का पता लगाता है और प्रमाणीकरण लागू करता है:

1. `cloudflared` इंटरनेट से रिक्वेस्ट `localhost:4096` पर फ़ॉरवर्ड करता है
2. यह हर रिक्वेस्ट में `CF-Connecting-IP` और `X-Forwarded-For` हेडर्स जोड़ता है
3. CyberStrike इन हेडर्स का पता लगाता है और रिक्वेस्ट को **रिमोट** मानता है
4. HTTP Basic Auth लागू होता है -- वेब UI उपयोगकर्ता नाम और पासवर्ड के लिए प्रॉम्प्ट करता है
5. सीधे लोकल रिक्वेस्ट (प्रॉक्सी हेडर्स के बिना) सुविधा के लिए auth बायपास करते हैं

इसका मतलब है कि लोकल `cyberstrike attach` कनेक्शन पासवर्ड के बिना काम करते हैं, जबकि सभी टनल ट्रैफ़िक के लिए क्रेडेंशियल्स आवश्यक हैं।

### app.cyberstrike.io से कनेक्ट करना

`app.cyberstrike.io` CyberStrike का होस्टेड वेब UI है। वेब इंटरफ़ेस को स्थानीय रूप से चलाने के बजाय, आप इसका उपयोग किसी भी रिमोट CyberStrike सर्वर से कनेक्ट करने के लिए कर सकते हैं।

1. अपने ब्राउज़र में [app.cyberstrike.io](https://app.cyberstrike.io) खोलें
2. सर्वर सिलेक्टर पर क्लिक करें (ऊपरी-बाएँ कोने में)
3. अपना टनल URL दर्ज करें (जैसे, `https://pentest.example.com`)
4. उपयोगकर्ता नाम (डिफ़ॉल्ट रूप से `cyberstrike`) और पासवर्ड दर्ज करें
5. हरा हेल्थ इंडिकेटर कनेक्शन की पुष्टि करता है

कनेक्ट होने के बाद, आपको पूर्ण CyberStrike अनुभव मिलता है -- सेशन, एजेंट्स, MCP टूल्स, साइड पैनल, और रियल-टाइम स्ट्रीमिंग -- सब आपके टनल के माध्यम से।

<Aside variant="info">
  **स्थानीय AI प्रदाता:** यदि आपका सर्वर Ollama या अन्य स्थानीय LLM चलाता है, तो `app.cyberstrike.io` उन्हें पारदर्शी रूप से उपयोग करता है। AI अनुमान सर्वर साइड पर होता है -- वेब UI केवल प्रदर्शन और इनपुट को संभालता है।
</Aside>

### सेल्फ-होस्टेड वेब UI

आप CyberStrike वेब इंटरफ़ेस का अपना इंस्टेंस बना और डिप्लॉय कर सकते हैं, फिर इसे किसी भी CyberStrike सर्वर पर पॉइंट कर सकते हैं।

```bash
# वेब UI क्लोन और बिल्ड करें
git clone https://github.com/CyberStrikeus/CyberStrike.git
cd CyberStrike/packages/app
bun install && bun run build
```

`dist/` फ़ोल्डर को किसी भी स्टैटिक होस्टिंग (Vercel, Netlify, Cloudflare Pages, आदि) पर डिप्लॉय करें। फिर अपने CyberStrike सर्वर पर CORS कॉन्फ़िगर करें ताकि आपके डोमेन की अनुमति हो:

```bash
cyberstrike web --cors https://my-pentest-ui.example.com
```

या `cyberstrike.json` में:

```json
{
  "server": {
    "cors": ["https://my-pentest-ui.example.com"]
  }
}
```

### सुरक्षा आर्किटेक्चर

CyberStrike रिमोट एक्सेस के लिए कई सुरक्षा परतें लागू करता है:

| परत | सुरक्षा |
|-------|------------|
| **TLS एन्क्रिप्शन** | Cloudflare Tunnel सभी ट्रैफ़िक को एंड-टू-एंड एन्क्रिप्ट करता है। इंटरनेट पर कोई प्लेनटेक्स्ट डेटा नहीं गुज़रता। |
| **HTTP Basic Auth** | हर रिमोट रिक्वेस्ट के लिए वैध उपयोगकर्ता नाम और पासवर्ड आवश्यक है। क्रेडेंशियल्स `Authorization` हेडर के माध्यम से भेजे जाते हैं। |
| **प्रॉक्सी डिटेक्शन** | सर्वर `CF-Connecting-IP` और `X-Forwarded-For` हेडर्स का निरीक्षण करता है। लूपबैक से प्रॉक्सीड रिक्वेस्ट भी प्रमाणित होते हैं। |
| **अनिवार्य पासवर्ड** | `cyberstrike serve` और `cyberstrike web` `CYBERSTRIKE_SERVER_PASSWORD` के बिना शुरू होने से मना करते हैं। |
| **कोई पोर्ट एक्सपोज़र नहीं** | Cloudflare Tunnel के लिए कोई इनबाउंड पोर्ट आवश्यक नहीं। सर्वर केवल Cloudflare के एज पर आउटबाउंड कनेक्शन बनाता है। |
| **SPA auth फ़्लो** | ब्राउज़र auth डायलॉग को रोकने के लिए सर्वर जानबूझकर `WWW-Authenticate` हेडर्स छोड़ देता है। वेब UI अपने लॉगिन फ़ॉर्म के माध्यम से प्रमाणीकरण संभालता है। |

<Aside variant="danger">
  **CyberStrike को कभी सीधे इंटरनेट पर एक्सपोज़ न करें** बिना टनल या VPN के। हमेशा Cloudflare Tunnel, TLS वाला रिवर्स प्रॉक्सी, या प्राइवेट नेटवर्क का उपयोग करें। हमेशा मज़बूत, अद्वितीय पासवर्ड सेट करें।
</Aside>

## कॉन्फ़िग फ़ाइल

सभी वेब विकल्प कमांड-लाइन फ़्लैग्स के बजाय `cyberstrike.json` में सेट किए जा सकते हैं:

```json
{
  "server": {
    "port": 4096,
    "hostname": "0.0.0.0",
    "mdns": true,
    "cors": ["https://example.com"]
  }
}
```

कमांड-लाइन फ़्लैग्स कॉन्फ़िग फ़ाइल सेटिंग्स को ओवरराइड करते हैं।
