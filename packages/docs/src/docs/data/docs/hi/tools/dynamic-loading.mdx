बिल्ट-इन टूल (bash, read, edit, ...) हमेशा उपलब्ध होते हैं। **MCP टूल मांग पर लोड किए जाते हैं** ताकि सैकड़ों टूल वाले सर्वर को कनेक्ट करने से मॉडल का संदर्भ न भरे। चार टूल इसे संचालित करते हैं।

<img src="/docs/images/diagrams/tool-loading.svg" alt="MCP tool loading cycle: a server exposes hundreds of tools; tool_search finds one by capability, load_tools brings it into context, the agent calls it, and unload_tools frees the context" className="my-6" />

## लोडिंग टूल

| टूल | उद्देश्य |
|------|---------|
| `tool_search` | क्षमता के अनुसार MCP टूल खोजें (`query`, वैकल्पिक `limit`) |
| `load_tools` | विशिष्ट टूल को सक्रिय संदर्भ में लोड करें |
| `unload_tools` | संदर्भ मुक्त करने के लिए लोड किए गए टूल हटाएँ |
| `list_loaded_tools` | वर्तमान में कौन से टूल लोड हैं दिखाएँ |

एजेंट इन्हें स्वचालित रूप से उपयोग करता है: यह क्षमता खोजता है, मैचिंग MCP टूल लोड करता है, इसे कॉल करता है, और बाद में इसे अनलोड कर सकता है।

### tool_search

```json
{
  "query": "sql injection testing",
  "limit": 10
}
```

मैचिंग MCP टूल उनके विवरण के साथ लौटाता है। बिल्ट-इन टूल को खोजने की आवश्यकता नहीं — वे हमेशा कॉल करने योग्य हैं।

## लेज़ी बनाम हमेशा-ऑन क्या है

- **हमेशा उपलब्ध** — हर बिल्ट-इन टूल (`bash`, `read`, `edit`, `glob`, `grep`, `write`, `task`, `webfetch`, `websearch`, मेमोरी टूल, ...)।
- **मांग पर लोड** — कनेक्टेड MCP सर्वर ([Bolt](/docs/mcp/bolt) सहित) द्वारा एक्सपोज़ किए गए टूल। ये `tool_search` से खोजे जाते हैं और `load_tools` से लाए जाते हैं।

## टूल अक्षम करना

`tools` कॉन्फ़िग टूल नाम → बूलियन का मैप है। किसी टूल को अक्षम करने के लिए `false` सेट करें:

```json title="cyberstrike.json"
{
  "tools": {
    "websearch": false
  }
}
```
