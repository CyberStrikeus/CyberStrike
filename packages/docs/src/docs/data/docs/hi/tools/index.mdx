## टूल श्रेणियाँ

| श्रेणी | टूल | उद्देश्य |
|----------|-------|---------|
| **फ़ाइल ऑपरेशन** | Read, Write, Edit, Glob, Grep | फ़ाइल पढ़ना, लिखना, संपादन, और खोज |

## फ़ाइल ऑपरेशन

### Read

लाइन नंबर के साथ फ़ाइल सामग्री पढ़ता है। टेक्स्ट फ़ाइलें, छवियाँ, और PDF का समर्थन करता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `filePath` | string | हाँ | फ़ाइल का पथ (पूर्ण या सापेक्ष) |
| `offset` | number | नहीं | शुरू करने के लिए लाइन नंबर (1-इंडेक्स्ड) |
| `limit` | number | नहीं | पढ़ने के लिए लाइनों की संख्या (डिफ़ॉल्ट: 2000) |

#### उदाहरण

```json
{
  "filePath": "/path/to/file.txt",
  "offset": 100,
  "limit": 500
}
```

#### आउटपुट प्रारूप

```
00001| First line of content
00002| Second line of content
00003| Third line of content

(End of file - total 3 lines)
```

#### विशेषताएँ

- स्वचालित बाइनरी फ़ाइल पहचान
- छवि और PDF समर्थन (base64 एन्कोडेड सामग्री लौटाता है)
- 2000 अक्षरों पर लाइन ट्रंकेशन
- प्रति रीड ऑपरेशन अधिकतम 50KB
- फ़ाइल न मिलने पर स्मार्ट फ़ाइल सुझाव

---

### Write

नई सामग्री के साथ फ़ाइल बनाता या ओवरराइट करता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `filePath` | string | हाँ | फ़ाइल का पूर्ण पथ |
| `content` | string | हाँ | लिखने के लिए सामग्री |

#### उदाहरण

```json
{
  "filePath": "/path/to/new-file.txt",
  "content": "File contents here"
}
```

#### विशेषताएँ

- आवश्यकता होने पर पैरेंट डायरेक्टरी बनाता है
- समीक्षा के लिए यूनिफ़ाइड diff जनरेट करता है
- लिखने के बाद LSP डायग्नोस्टिक्स
- कन्फ़्लिक्ट डिटेक्शन के लिए फ़ाइल समय ट्रैकिंग

---

### Edit

स्मार्ट मैचिंग के साथ फ़ाइलों पर खोजें-और-बदलें ऑपरेशन करता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `filePath` | string | हाँ | फ़ाइल का पूर्ण पथ |
| `oldString` | string | हाँ | खोजने और बदलने के लिए टेक्स्ट |
| `newString` | string | हाँ | प्रतिस्थापन टेक्स्ट |
| `replaceAll` | boolean | नहीं | सभी उपस्थितियाँ बदलें (डिफ़ॉल्ट: false) |

#### उदाहरण

```json
{
  "filePath": "/path/to/file.ts",
  "oldString": "function oldName(",
  "newString": "function newName(",
  "replaceAll": false
}
```

#### स्मार्ट मैचिंग

Edit टूल कई मैचिंग रणनीतियों का उपयोग करता है:

1. **साधारण प्रतिस्थापन**: सटीक स्ट्रिंग मैच
2. **लाइन ट्रिम्ड**: प्रति लाइन अग्रणी/अनुगामी व्हाइटस्पेस अनदेखा
3. **ब्लॉक एंकर**: पहली और अंतिम लाइन मैच, मध्य फ़ज़ी
4. **व्हाइटस्पेस नॉर्मलाइज़्ड**: कई स्पेस कोलैप्स
5. **इंडेंटेशन फ़्लेक्सिबल**: इंडेंटेशन अंतर अनदेखा
6. **एस्केप नॉर्मलाइज़्ड**: एस्केप सीक्वेंस हैंडल
7. **संदर्भ-जागरूक**: मैचिंग के लिए आसपास के संदर्भ का उपयोग

#### विशेषताएँ

- यूनिफ़ाइड diff जनरेशन
- संपादन के बाद LSP डायग्नोस्टिक्स
- कई उपस्थिति पहचान
- फ़ाइल समय ट्रैकिंग से कन्फ़्लिक्ट रोकथाम

---

### Glob

ग्लॉब पैटर्न से मेल खाती फ़ाइलें ढूँढता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `pattern` | string | हाँ | ग्लॉब पैटर्न (जैसे, `**/*.ts`) |
| `path` | string | नहीं | खोज डायरेक्टरी (डिफ़ॉल्ट: वर्तमान डायरेक्टरी) |

#### उदाहरण

```json
{
  "pattern": "**/*.{ts,tsx}",
  "path": "/path/to/project"
}
```

#### आउटपुट

संशोधन समय (नवीनतम पहले) के अनुसार क्रमबद्ध फ़ाइल पथ लौटाता है, 100 परिणामों तक सीमित।

#### पैटर्न उदाहरण

| पैटर्न | मेल खाता है |
|---------|---------|
| `*.ts` | वर्तमान डायरेक्टरी में TypeScript फ़ाइलें |
| `**/*.ts` | पुनरावर्ती रूप से TypeScript फ़ाइलें |
| `src/**/*.{ts,tsx}` | src डायरेक्टरी में TS/TSX फ़ाइलें |
| `!**/node_modules/**` | node_modules को बाहर करें |

---

### Grep

regex पैटर्न का उपयोग करके फ़ाइल सामग्री खोजता है। ripgrep पर निर्मित।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `pattern` | string | हाँ | खोज के लिए regex पैटर्न |
| `path` | string | नहीं | खोज डायरेक्टरी (डिफ़ॉल्ट: वर्तमान डायरेक्टरी) |
| `include` | string | नहीं | फ़ाइल पैटर्न फ़िल्टर (जैसे, `*.js`) |

#### उदाहरण

```json
{
  "pattern": "password|secret|api_key",
  "path": "/path/to/project",
  "include": "*.{js,ts,py}"
}
```

#### आउटपुट प्रारूप

```
Found 5 matches

/path/to/file.ts:
  Line 42: const apiKey = process.env.API_KEY
  Line 85: // TODO: remove hardcoded secret

/path/to/config.js:
  Line 12: password: "changeme"
```

#### विशेषताएँ

- Regex समर्थन (ripgrep सिंटैक्स)
- छिपी फ़ाइल खोज
- सिमलिंक फ़ॉलोइंग
- संशोधन समय के अनुसार क्रमबद्ध परिणाम
- अधिकतम 100 परिणाम

## कमांड निष्पादन

### Bash

टाइमआउट और आउटपुट कैप्चर के साथ शेल कमांड निष्पादित करता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `command` | string | हाँ | निष्पादित करने के लिए कमांड |
| `timeout` | number | नहीं | मिलीसेकंड में टाइमआउट (डिफ़ॉल्ट: 120000) |
| `workdir` | string | नहीं | कार्यशील डायरेक्टरी |
| `description` | string | हाँ | कमांड उद्देश्य का संक्षिप्त विवरण |

#### उदाहरण

```json
{
  "command": "nmap -sV -sC target.com",
  "timeout": 300000,
  "workdir": "/path/to/project",
  "description": "Scan target for open ports and services"
}
```

#### विशेषताएँ

- शेल पहचान (bash/zsh/sh)
- टाइमआउट पर प्रोसेस ट्री किलिंग
- अनुमति प्रणाली एकीकरण
- रियल-टाइम आउटपुट स्ट्रीमिंग
- बाहरी डायरेक्टरी एक्सेस कंट्रोल

#### सुरक्षा विचार

कमांड को tree-sitter से पार्स किया जाता है ताकि पता लगा सकें:
- प्रोजेक्ट के बाहर डायरेक्टरी एक्सेस
- खतरनाक कमांड पैटर्न
- फ़ाइल सिस्टम संशोधन

## मेमोरी सिस्टम

Cyberstrike में सत्रों में संदर्भ संग्रहीत करने के लिए एक स्थायी मेमोरी सिस्टम शामिल है।

### Memory Write

स्थायी मेमोरी में जानकारी संग्रहीत करता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `content` | string | हाँ | संग्रहीत करने के लिए सामग्री |
| `type` | string | नहीं | MEMORY.md के लिए `long_term`, दिनांकित नोट्स के लिए `daily` |
| `title` | string | नहीं | प्रविष्टि के लिए वैकल्पिक शीर्षक |

#### उदाहरण

```json
{
  "content": "Target uses PostgreSQL 14.2 on port 5432",
  "type": "long_term",
  "title": "Database Configuration"
}
```

#### मेमोरी प्रकार

| प्रकार | स्टोरेज | उद्देश्य |
|------|---------|---------|
| `long_term` | `.cyberstrike/MEMORY.md` | निर्णय, प्राथमिकताएँ, महत्वपूर्ण तथ्य |
| `daily` | `.cyberstrike/memory/YYYY-MM-DD.md` | सत्र नोट्स, अस्थायी संदर्भ |

---

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `query` | string | हाँ | खोज कीवर्ड या वाक्यांश |

#### उदाहरण

```json
{
  "query": "database credentials"
}
```

### Memory Read

विशिष्ट मेमोरी फ़ाइलें पढ़ता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `file` | string | हाँ | फ़ाइल पहचानकर्ता |

#### फ़ाइल पहचानकर्ता

| पहचानकर्ता | विवरण |
|------------|-------------|
| `long_term` | दीर्घकालिक मेमोरी (MEMORY.md) |
| `today` | आज के दैनिक नोट्स |
| `yesterday` | कल के नोट्स |
| `YYYY-MM-DD` | विशिष्ट तिथि के नोट्स |
| `list` | सभी मेमोरी फ़ाइलें सूचीबद्ध करें |

## डायनामिक टूल लोडिंग

<img src="/docs/images/diagrams/tool-interaction-flow.svg" alt="How a tool becomes available: built-in tools are called directly; MCP tools are found with tool_search, loaded with load_tools, then callable, and freed with unload_tools" className="my-6 mx-auto max-w-sm" />

Cyberstrike MCP (Model Context Protocol) सर्वर के लिए डायनामिक टूल लोडिंग का समर्थन करता है। यह संदर्भ विंडो को ओवरलोड किए बिना सैकड़ों टूल तक एक्सेस सक्षम करता है।

### Tool Search

क्षमता के अनुसार उपलब्ध MCP टूल खोजता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `query` | string | हाँ | क्षमता विवरण |
| `limit` | number | नहीं | अधिकतम परिणाम (डिफ़ॉल्ट: 5) |

#### उदाहरण

```json
{
  "query": "sql injection testing",
  "limit": 10
}
```

#### आउटपुट

```
Found 3 tools:

1. sqlmap_scan
   SQL injection scanner using sqlmap
   Estimated tokens: ~500

2. nuclei_sqli
   Nuclei templates for SQL injection
   Estimated tokens: ~300

3. manual_sqli
   Manual SQL injection payloads
   Estimated tokens: ~200
```

---

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|

#### उदाहरण

```json
{
  "tool_ids": ["sqlmap_scan", "nuclei_sqli"]
}
```

|-----------|------|----------|-------------|
| `tool_ids` | string[] | हाँ | अनलोड करने के लिए टूल ID |

## कार्य प्रबंधन

### Task

एक सबएजेंट को कार्य सौंपता है। इस प्रकार प्राथमिक एजेंट विशेषज्ञ सबएजेंट भेजता है ([एजेंट](/docs/agents) देखें)।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `description` | string | हाँ | एक संक्षिप्त (3-5 शब्द) कार्य विवरण |
| `prompt` | string | हाँ | सबएजेंट के लिए कार्य |
| `subagent_type` | string | हाँ | कौन सा सबएजेंट भेजना है (जैसे `web-application`, `general`) |

---

### TodoWrite

एक टू-डू सूची में कार्य आइटम लिखता है।

#### पैरामीटर

| पैरामीटर | प्रकार | आवश्यक | विवरण |
|-----------|------|----------|-------------|
| `tasks` | array | हाँ | कार्य ऑब्जेक्ट की सरणी |

#### कार्य ऑब्जेक्ट

```json
{
  "id": "1",
  "content": "Scan for open ports",
  "status": "pending",
  "priority": "high"
}
```

## टूल अनुमतियाँ

प्रत्येक टूल को विशिष्ट अनुमतियों की आवश्यकता होती है जो कॉन्फ़िगर की जा सकती हैं:

| अनुमति | टूल | डिफ़ॉल्ट |
|------------|-------|---------|
| `read` | Read | ask |
| `edit` | Write, Edit | ask |
| `glob` | Glob | allow |
| `grep` | Grep | allow |
| `bash` | Bash | ask |
| `websearch` | WebSearch | ask |
| `webfetch` | WebFetch | ask |
| `codesearch` | CodeSearch | ask |
| `task` | Task | ask |
| `external_directory` | प्रोजेक्ट के बाहर एक्सेस | ask |

### कॉन्फ़िगरेशन

```json
{
  "permission": {
    "bash": "ask",
    "edit": "allow",
    "read": "allow",
    "glob": "allow",
    "grep": "allow"
  }
}
```

### अनुमति कार्रवाइयाँ

| कार्रवाई | विवरण |
|--------|-------------|
| `ask` | उपयोगकर्ता से अनुमोदन माँगें |
| `allow` | बिना पूछे ऑटो-अनुमोदित करें |
| `deny` | टूल उपयोग ब्लॉक करें |

पूर्ण मॉडल और ग्लॉब पैटर्न के लिए [अनुमतियाँ](/docs/permissions) देखें।

## कस्टम टूल बनाना

`.cyberstrike/tools/` में फ़ाइलें बनाकर कस्टम टूल जोड़ें:

```typescript title=".cyberstrike/tools/custom-scanner.ts"
import { z } from "zod"

export default {
  description: "Custom vulnerability scanner",
  args: {
    target: z.string().describe("Target URL to scan"),
    depth: z.number().default(3).describe("Scan depth"),
  },
  async execute(args, ctx): Promise<string> {
    const { target, depth } = args
    // Custom scanning logic
    return `Scanned ${target} to depth ${depth}`
  },
}
```

किसी भी `.cyberstrike/` फ़ोल्डर के अंदर `tool/` या `tools/` डायरेक्टरी में फ़ाइलें स्वचालित रूप से लोड होती हैं।

### टूल परिभाषा स्कीमा

| फ़ील्ड | प्रकार | विवरण |
|-------|------|-------------|
| `description` | string | मॉडल को दिखाया जाने वाला टूल विवरण |
| `args` | object | पैरामीटर नाम → Zod स्कीमा का मैप |
| `execute` | function | `async (args, ctx) => string` |

## MCP सर्वर टूल

Cyberstrike MCP सर्वर से टूल लोड कर सकता है। अनुशंसित दृष्टिकोण [Bolt](/docs/mcp/bolt) है, जो प्लगइन सिस्टम के साथ Docker कंटेनर के माध्यम से सुरक्षा टूल प्रदान करता है:

```json title="cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true
    }
  }
}
```

MCP टूल सीधे टूल कॉल के रूप में उपलब्ध हो जाते हैं -- प्रत्येक प्लगइन को सीधे नाम से कॉल किया जाता है (जैसे `nmap`, `nuclei`, `ffuf`)।

<Aside variant="tip">
  अनुशंसित सुरक्षा-टूल सेटअप के लिए [Bolt](/docs/mcp/bolt) देखें — 7 प्लगइन प्लस ~26 एकत्रित MCP सर्वर, सभी सीधे टूल कॉल के रूप में उपलब्ध।
</Aside>
