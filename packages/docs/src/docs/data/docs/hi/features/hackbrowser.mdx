HackBrowser Cyberstrike का स्वायत्त वेब क्रॉलर है। यह एक Chromium ब्राउज़र खोलता है, एक LLM को एक्सेसिबिलिटी ट्री पढ़कर लक्ष्य एप्लिकेशन नेविगेट करने देता है, और प्रत्येक कैप्चर किए गए HTTP अनुरोध को — UI संदर्भ से समृद्ध करके — विश्लेषण पाइपलाइन को अग्रेषित करता है। [proxy-agent](/docs/agents/proxy-agent) फिर प्रत्येक अनुरोध का विश्लेषण और परीक्षण करता है।

## HackBrowser कब उपयोग करें

| उपयोग का मामला | चुनें |
|----------|------|
| कई भूमिकाओं के साथ मैन्युअल अन्वेषण | [Chrome Extension](/docs/tools/chrome-extension) |
| अनअटेंडेड स्वचालित क्रॉल | **HackBrowser** |
| कैप्चर पर UI फ़ॉर्म संदर्भ (`readonly`, `hidden`, `disabled` फ्लैग) चाहिए | **HackBrowser** |
| मौजूदा पूर्व-प्रमाणित ब्राउज़र सत्र | दोनों — Chrome Extension सरल है |

दोनों पथ एक ही `/session/ingest` एंडपॉइंट और एक ही proxy-agent पाइपलाइन को फ़ीड करते हैं। आप एक ही सत्र में दोनों को मिला सकते हैं।

## यह कैसे काम करता है

```
┌────────────────────────────────────────────────────────────────────┐
│  Chromium (Playwright)                                             │
│  ├── Scanner    — DOM → accessibility tree (RawElement[])          │
│  ├── Navigator  — LLM call → page plan (form/click tasks)          │
│  ├── Executor   — Plan → Playwright actions                        │
│  ├── Capture    — HTTP requests + ui_context snapshot              │
│  └── Live panel — Shadow-DOM telemetry overlay (visible mode)      │
└────────────────────────┬───────────────────────────────────────────┘
                         │ POST /session/ingest
                         ▼
┌────────────────────────────────────────────────────────────────────┐
│  Cyberstrike API                                                   │
│  ├── Normalize → deduplicate → Request.add                         │
│  └── IngestQueue → SessionPrompt(agent="proxy-agent")              │
└────────────────────────┬───────────────────────────────────────────┘
                         ▼
                proxy-agent → proxy-analyzer + vulnerability testers
```

LLM पृष्ठ को एक एक्सेसिबिलिटी ट्री के रूप में देखता है और तय करता है कि कौन से फ़ॉर्म भरने हैं और कौन से बटन क्लिक करने हैं। प्रत्येक कैप्चर किए गए अनुरोध में एक `ui_context` स्नैपशॉट शामिल होता है — फ़ॉर्म फ़ील्ड, उनके फ्लैग, और कोई भी छिपे हुए पैरामीटर — जिसका उपयोग proxy-analyzer संदिग्ध अनुरोध आकृतियों की पहचान के लिए करता है।

## क्रॉल शुरू करें

### `/hackbrowser`

लक्ष्य URL, क्रेडेंशियल्स, स्कोप, बहिष्कृत लेबल, स्टेप्स और हेडलेस मोड के फ़ील्ड वाला लॉन्च डायलॉग खोलने के लिए TUI में `/hackbrowser` चलाएं।

| विकल्प | विवरण |
|--------|-------------|
| **Target URL** | क्रॉलिंग शुरू करने के लिए URL |
| **Scope** | कैप्चर को सीमित करने के लिए होस्टनेम पैटर्न (जैसे `*.example.com`) |
| **Exclude** | UI लेबल जिन्हें प्लानर को छोड़ना चाहिए (सिमेंटिक मैच) |
| **Steps** | क्रॉल करने के लिए अधिकतम पृष्ठ (डिफ़ॉल्ट: 50) |
| **Credentials** | क्रॉल करने के लिए क्रेडेंशियल। दृश्यमान ब्राउज़र को बाध्य करता है। |
| **Headless** | दृश्यमान ब्राउज़र विंडो के बिना चलाएं |

### क्रॉल रद्द करें

```
/hackbrowser-stop
```

### एजेंट-आरंभित

एजेंट HackBrowser को स्वायत्त रूप से भी लॉन्च कर सकता है जब वार्तालाप इसकी मांग करता है (जैसे "इस ऐप का परीक्षण करें")। उपकरण तुरंत लौटता है — क्रॉल प्रगति के अनुसार कैप्चर सत्र में स्ट्रीम होते हैं।

## मल्टी-क्रेडेंशियल क्रॉल

अनुक्रमिक प्रति-भूमिका क्रॉल चलाने के लिए `/hackbrowser` लॉन्च डायलॉग में दो या अधिक क्रेडेंशियल चुनें।

प्रत्येक क्रेडेंशियल के लिए, HackBrowser एक दृश्यमान Chromium विंडो खोलता है, आपके लॉगिन करने की प्रतीक्षा करता है, फिर उस क्रेडेंशियल ID से टैग करके पूर्ण क्रॉल चलाता है। WSTG पाइपलाइन फिर तुलना कर सकती है कि प्रत्येक भूमिका क्या एक्सेस कर सकती है।

## UI संदर्भ पेलोड

Chrome Extension से अंतर यह है कि प्रत्येक कैप्चर से `ui_context` ब्लॉक जुड़ा होता है:

```json
{
  "ui_context": {
    "pageUrl": "https://shop.example.com/settings/profile",
    "formName": "Update Profile",
    "fields": [
      { "name": "email", "type": "text", "isReadOnly": true },
      { "name": "role", "type": "hidden", "isHidden": true, "value": "user" }
    ],
    "hiddenParams": ["account_id", "_csrf"]
  }
}
```

proxy-analyzer इन सिग्नलों का उपयोग फ्लैग करने के लिए करता है:

- अनुरोध में भेजा गया `readonly` फ़ील्ड → परीक्षण करें कि सर्वर इसे लागू करता है या नहीं
- `hidden` फ़ील्ड → मास-असाइनमेंट उम्मीदवार
- `hiddenParams` में पैरामीटर (कोई UI तत्व नहीं) → सबसे उच्च-जोखिम छिपा पैरामीटर
- एक भूमिका को ही दिखने वाला तत्व → अन्य क्रेडेंशियल्स से परीक्षण करें

## नेटवर्क स्कोप

डिफ़ॉल्ट रूप से, HackBrowser लक्ष्य URL के `*.{eTLD+1}` से मेल खाने वाले अनुरोधों को कैप्चर करता है। कस्टम होस्टनेम पैटर्न जोड़कर `/hackbrowser` लॉन्च डायलॉग में स्कोप ओवरराइड करें (जैसे `app.example.com`, `api.example.com`)।

## समस्या निवारण

| त्रुटि | समाधान |
|-------|-----|
| Chromium स्थापित नहीं | `bunx playwright install chromium` |
| Playwright स्थापित नहीं | `npm install --prefix ~/.local/share/cyberstrike playwright` |
| Worker नहीं मिला | पुनः स्थापित करें: `npm install -g @cyberstrike-io/cyberstrike` |
| पहले से चल रहा है | पूर्ण होने तक प्रतीक्षा करें या `/hackbrowser-stop` चलाएं |

<Aside variant="danger">
  HackBrowser का उपयोग केवल अधिकृत लक्ष्यों के विरुद्ध करें। अनधिकृत पेनेट्रेशन टेस्टिंग अवैध है।
</Aside>
