गैर-इंटरैक्टिव रन (`cyberstrike run`) में, अनुमति संकेतों का उत्तर देने वाला कोई नहीं होता — इसलिए कोई भी उपकरण जो संकेत *करेगा* वह **ऑटो-अस्वीकृत** हो जाता है। एक पाइपलाइन को वास्तविक काम करने देने के लिए, आवश्यक उपकरणों को पूर्व-स्वीकृत करें।

## उपकरणों को पूर्व-स्वीकृत करना

कोई "ऑटो मोड" फ्लैग नहीं है। दो तरीकों से अनुमतियाँ प्रदान करें:

**1. `CYBERSTRIKE_PERMISSION` env var** — एक JSON अनुमति मैप (कॉन्फ़िग `permission` फ़ील्ड के समान आकार):

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
cyberstrike run "scan this codebase for security issues" --format json > report.json
```

**2. कॉन्फ़िग `permission`** — सुरक्षित डिफ़ॉल्ट कमिट करें, खतरनाक भागों को अस्वीकार करें ([पैटर्न](/docs/permissions/patterns) देखें):

```json title="cyberstrike.json"
{
  "permission": {
    "read": "allow",
    "bash": { "*": "allow", "rm -rf *": "deny", "sudo *": "deny" },
    "edit": { "reports/**": "allow", ".env*": "deny" }
  }
}
```

आउटपुट stdout पर जाता है; मशीन-पठनीय परिणामों के लिए `--format json` का उपयोग करें।

## CI/CD एकीकरण

### GitHub Actions

```yaml title=".github/workflows/security-scan.yml"
name: Security Scan
on:
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @cyberstrike-io/cyberstrike@latest
      - name: Run Security Scan
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
        run: cyberstrike run "scan this codebase for security vulnerabilities" --format json > security-report.json
      - uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: security-report.json
```

### GitLab CI

```yaml title=".gitlab-ci.yml"
security-scan:
  image: node:20
  variables:
    CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'
  script:
    - npm install -g @cyberstrike-io/cyberstrike@latest
    - cyberstrike run "analyze code for vulnerabilities" --format json > report.json
  artifacts:
    paths:
      - report.json
```

## बैच और अनुसूचित रन

लक्ष्यों पर लूप करें, या cron से चलाएं — वही `CYBERSTRIKE_PERMISSION` (या कॉन्फ़िग) नियम लागू होते हैं:

```bash title="scan-targets.sh"
#!/bin/bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow"}'
while read -r target; do
  cyberstrike run "scan $target for open ports and services" --format json > "reports/${target}.json"
done < targets.txt
```

```bash
# रोज़ाना 02:00 पर स्कैन
0 2 * * * CYBERSTRIKE_PERMISSION='{"bash":"allow"}' /usr/local/bin/cyberstrike run "daily security scan" >> /var/log/cyberstrike.log 2>&1
```

## एक्जिट कोड और आउटपुट

`cyberstrike run` परिणामों को stdout पर लिखता है (JSON के लिए `--format json`) और सफलता पर `0`, त्रुटि या रुकावट पर एक गैर-शून्य कोड लौटाता है। निष्कर्षों के लिए JSON पार्स करें:

```bash
cyberstrike run "scan target" --format json | jq '.'
```

## सुरक्षा विचार

- **न्यूनतम विशेषाधिकार** — केवल वही उपकरण `allow` करें जिनकी जॉब को आवश्यकता है; `rm -rf *`, `sudo *`, और सीक्रेट पथों के लिए स्पष्ट `deny` रखें।
- **सीक्रेट्स** — अपने CI सीक्रेट स्टोर से API कुंजियाँ इंजेक्ट करें, कभी कमिट न करें।
- **अलगाव** — जहाँ संभव हो, प्रतिबंधित नेटवर्क वाले कंटेनर में चलाएं।

<Aside variant="caution">
  ऑटोमेशन में `bash` को पूर्व-स्वीकृत करते समय हमेशा विनाशकारी कमांड के लिए deny नियम रखें।
</Aside>
