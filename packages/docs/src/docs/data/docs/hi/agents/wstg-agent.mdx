`wstg-agent` Cyberstrike की वेब सुरक्षा परीक्षण पाइपलाइन का ऑर्केस्ट्रेटर है। यह कैप्चर किए गए HTTP ट्रैफिक को प्राप्त करता है और अनुरोध विशेषताओं और संचित सत्र संदर्भ के आधार पर उचित WSTG विशेषज्ञ एजेंट्स को भेजता है।

## अवलोकन

| गुण | मान |
|----------|-------|
| **Agent ID** | `wstg-agent` |
| **भूमिका** | `orchestrator` |
| **डोमेन** | `@cyberstrike-io/web` |
| **रंग** | नीला |

## यह कैसे काम करता है

`wstg-agent` एक **शुद्ध ऑर्केस्ट्रेटर** है — यह स्वयं कमजोरी परीक्षण नहीं करता। इसका कार्यप्रवाह:

1. एक कैप्चर किया गया HTTP अनुरोध प्राप्त करता है ([HackBrowser](/docs/features/hackbrowser) या [Chrome Extension](/docs/tools/chrome-extension) से)
2. अनुरोध विशेषताओं और संचित सत्र संदर्भ का विश्लेषण करता है
3. सिग्नल-आधारित डिस्पैच के माध्यम से अनुरोध को उचित WSTG विशेषज्ञ(ओं) को रूट करता है
4. परीक्षण कतार और पुनः-परीक्षण ट्रिगर का प्रबंधन करता है

## सिग्नल-आधारित रूटिंग

प्रत्येक कैप्चर किया गया अनुरोध अपनी विशेषताओं के आधार पर सिग्नल उत्पन्न करता है — एंडपॉइंट पथ, पैरामीटर, हेडर, प्रतिक्रिया पैटर्न, और [Vortex](/docs/features/vortex) नियम मिलान। `wstg-agent` इन सिग्नलों को विशेषज्ञ वर्गों में मैप करता है:

| सिग्नल श्रेणी | विशेषज्ञ |
|----------------|------------|
| प्रमाणीकरण पैटर्न | `wstg-authentication` |
| प्राधिकरण संकेतक | `wstg-authorization` |
| इनपुट पैरामीटर | `wstg-input-validation` |
| सत्र टोकन | `wstg-session-mgmt` |
| कॉन्फ़िगरेशन एंडपॉइंट्स | `wstg-config-deploy` |
| API पैटर्न | `wstg-api` |
| क्रिप्टो संकेतक | `wstg-cryptography` |
| त्रुटि प्रतिक्रियाएं | `wstg-error-handling` |
| व्यापार तर्क | `wstg-business-logic` |
| क्लाइंट-साइड संसाधन | `wstg-client-side` |
| LLM एंडपॉइंट्स | `wstg-llm` |

एक ही अनुरोध कई विशेषज्ञों को ट्रिगर कर सकता है जब यह कई श्रेणियों से सिग्नल प्रदर्शित करता है।

## WSTG विशेषज्ञ

प्रत्येक विशेषज्ञ एक WSTG श्रेणी के लिए एक केंद्रित परीक्षण एजेंट है:

| विशेषज्ञ | WSTG अनुभाग | केंद्र |
|-----------|--------------|-------|
| `wstg-info-gathering` | 4.1 | फ़िंगरप्रिंटिंग, एन्यूमरेशन, लीक डिटेक्शन |
| `wstg-config-deploy` | 4.2 | सर्वर कॉन्फ़िग, डिफ़ॉल्ट क्रेडेंशियल्स, फ़ाइल एक्सटेंशन |
| `wstg-identity-mgmt` | 4.3 | यूज़र एन्यूमरेशन, खाता प्रावधान |
| `wstg-authentication` | 4.4 | लॉगिन बाइपास, क्रेडेंशियल परीक्षण, MFA |
| `wstg-authorization` | 4.5 | IDOR, विशेषाधिकार वृद्धि, पथ ट्रैवर्सल |
| `wstg-session-mgmt` | 4.6 | सत्र स्थिरीकरण, कुकी विशेषताएं, टाइमआउट |
| `wstg-input-validation` | 4.7 | SQLi, XSS, SSTI, कमांड इंजेक्शन |
| `wstg-error-handling` | 4.8 | त्रुटि प्रकटीकरण, स्टैक ट्रेस |
| `wstg-cryptography` | 4.9 | कमजोर सिफर, पैडिंग ओरेकल, की एक्सपोज़र |
| `wstg-business-logic` | 4.10 | वर्कफ़्लो बाइपास, रेस कंडीशन |
| `wstg-client-side` | 4.11 | DOM XSS, क्लिकजैकिंग, postMessage |
| `wstg-api` | 4.12 | BOLA, मास असाइनमेंट, रेट लिमिटिंग |
| `wstg-llm` | कस्टम | प्रॉम्प्ट इंजेक्शन, LLM-विशिष्ट हमले |

प्रत्येक विशेषज्ञ WSTG स्किल्स (नियतात्मक परीक्षण स्क्रिप्ट) ले जाता है जिन्हें वह कैप्चर किए गए अनुरोधों के विरुद्ध निष्पादित करता है।

## Escalation Hunter

विशेषज्ञों के परीक्षण पूर्ण होने के बाद, [`escalation-hunter`](/docs/agents/escalation-hunter) श्रृंखलित कमजोरियों की पहचान करने और प्रभाव बढ़ाने के लिए सभी निष्कर्षों में चलता है।

## अनुमतियां

`wstg-agent` ऑर्केस्ट्रेटर के पास प्रतिबंधित अनुमति सेट है:

- कार्य बना सकता है (विशेषज्ञों को भेज सकता है)
- सत्र संदर्भ और कवरेज नोट पढ़ सकता है
- कार्यप्रणाली स्थिति और दायरा जांच सकता है
- सीधे परीक्षण नहीं कर सकता या कमजोरियां रिपोर्ट नहीं कर सकता
