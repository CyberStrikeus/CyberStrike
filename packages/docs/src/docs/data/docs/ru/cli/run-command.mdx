`cyberstrike run` выполняет один промпт неинтерактивно — идеально для автоматизации и скриптов. В этом режиме некому отвечать на запросы разрешений, поэтому любой инструмент, который запросил бы подтверждение, автоматически отклоняется (см. [Автоматизация](/docs/permissions/automation)).

## Базовое использование

```bash
cyberstrike run "your prompt here"
```

Промпт также читается из stdin при передаче через pipe:

```bash
echo "summarize the findings in report.json" | cyberstrike run
```

## Параметры

| Флаг | Псевдоним | Описание |
|------|-----------|----------|
| `--model` | `-m` | Модель в формате `provider/model` |
| `--agent` | | Первичный агент (только `cyberstrike` поставляется встроенным) |
| `--format` | | Формат вывода: `default` или `json` (по умолчанию: `default`) |
| `--file` | `-f` | Файл(ы) для прикрепления к сообщению (повторяемый) |
| `--continue` | `-c` | Продолжить последнюю сессию |
| `--session` | `-s` | ID сессии для продолжения |
| `--fork` | | Ответвить сессию перед продолжением (требует `--continue`/`--session`) |
| `--share` | | Поделиться сессией |
| `--title` | | Заголовок сессии |
| `--variant` | | Вариант модели / уровень рассуждения (например, `high`, `max`, `minimal`) |
| `--thinking` | | Показывать блоки размышлений |
| `--attach` | | Подключиться к работающему серверу (например, `http://localhost:4096`) |
| `--dir` | | Каталог для работы (удалённый путь при подключении) |
| `--port` | | Порт для локального сервера |
| `--command` | | Выполнить именованную команду; сообщение используется как аргументы |

<Aside variant="caution">
  Не существует флагов `--output`, `--permission`, `--timeout`, `--verbose` или `--quiet`. Управление выводом — `--format` (`default` | `json`); отображение рассуждений — `--thinking`.
</Aside>

## Примеры

### JSON-вывод для скриптов

```bash
cyberstrike run "scan example.com for OWASP Top 10 issues" --format json > report.json
```

### Выбор модели и прикрепление файлов

```bash
cyberstrike run "review this code for auth bugs" \
  -m anthropic/claude-sonnet-4-20250514 \
  -f src/auth.ts -f src/session.ts
```

### Продолжение или ответвление сессии

```bash
cyberstrike run "now test the admin endpoints" --continue
cyberstrike run "try a different payload" --session <id> --fork
```

## Разрешения в `run`

Поскольку промпты нельзя отвечать неинтерактивно, предварительно одобрите инструменты, необходимые скрипту, через переменную окружения `CYBERSTRIKE_PERMISSION` или поле конфигурации `permission`:

```bash
CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow"}' \
  cyberstrike run "enumerate services on the host" --format json
```

См. [Автоматизация](/docs/permissions/automation) для паттернов CI.

## Коды выхода

`cyberstrike run` возвращает `0` при успехе и ненулевой код при ошибке (например, недопустимые аргументы) или прерывании.
