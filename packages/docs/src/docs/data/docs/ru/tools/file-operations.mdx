## Инструмент Read

Чтение содержимого файлов с номерами строк.

### Базовое использование

```
> Read the contents of src/auth/login.ts
```

### Частичное чтение файла

```
> Read lines 50-100 of src/auth/login.ts
```

### Несколько файлов

```
> Read both config.json and package.json
```

### Анализ изображений

Инструмент Read может анализировать изображения:

```
> Read the screenshot at ./evidence/vuln-poc.png
```

### Анализ PDF

```
> Read the security report at ./reports/pentest.pdf
```

## Инструмент Write

Создание или перезапись файлов.

### Создание нового файла

```
> Write a Python script to exploit the SQL injection to exploit.py
```

### Перезапись файла

```
> Replace the contents of config.json with the secure configuration
```

<Aside variant="caution">
  Инструмент Write перезаписывает существующие файлы без предупреждения. Для частичных модификаций используйте Edit.
</Aside>

## Инструмент Edit

Точное редактирование существующих файлов.

### Замена строк

```
> Edit src/auth/login.ts to replace "SELECT * FROM users WHERE id = " + userId with parameterized query
```

### Многострочное редактирование

```
> Edit the vulnerable function in auth.ts to add input validation
```

### Замена всех вхождений

```
> Replace all instances of "http://" with "https://" in config files
```

### Лучшие практики

1. Сначала прочитайте файл для понимания контекста
2. Будьте конкретны в том, что нужно изменить
3. Включайте достаточно окружающего контекста для уникального совпадения
4. Проверяйте изменения после редактирования

## Инструмент Glob

Поиск файлов по шаблону.

### Базовые шаблоны

```
> Find all TypeScript files in the project
```

Шаблон: `**/*.ts`

### Несколько расширений

```
> Find all JavaScript and TypeScript files
```

Шаблон: `**/*.{js,ts}`

### Конкретные каталоги

```
> Find all config files in the src directory
```

Шаблон: `src/**/config.*`

### Распространённые шаблоны

| Шаблон | Совпадения |
|--------|-----------|
| `**/*.ts` | Все TypeScript-файлы |
| `src/**/*.test.ts` | Тестовые файлы в src |
| `**/package.json` | Все файлы package.json |
| `**/.env*` | Файлы окружения |
| `**/secret*` | Файлы со словом «secret» в имени |

### Шаблоны для сканирования безопасности

```
> Find files that might contain credentials

Patterns:
- **/*.env*
- **/secrets.*
- **/*credentials*
- **/*password*
- **/config.json
```

## Инструмент Grep

Поиск по содержимому файлов с помощью regex.

### Базовый поиск

```
> Search for "password" in all files
```

### Поиск по regex

```
> Search for API key patterns in the codebase
```

Шаблон: `(api[_-]?key|apikey)\s*[:=]\s*['"][^'"]+['"]`

### Без учёта регистра

```
> Search for "SELECT" case insensitively
```

### Фильтр по типу файла

```
> Search for "eval(" only in JavaScript files
```

### Строки контекста

```
> Search for "TODO" with 2 lines of context before and after
```

### Поиски, ориентированные на безопасность

| Назначение | Шаблон |
|-----------|--------|
| SQL-инъекция | `(SELECT|INSERT|UPDATE|DELETE).*\+.*\$` |
| Инъекция команд | `(exec|spawn|system)\s*\(` |
| Захардкоженные секреты | `(password\|secret\|key)\s*=\s*['"][^'"]&#123;8,&#125;` |
| Небезопасная десериализация | `(pickle|marshal|yaml\.load)` |
| XSS-уязвимости | `(innerHTML|outerHTML|document\.write)` |

## Рабочий процесс анализа файлов

### 1. Обнаружение файлов

```
> Find all files that might handle user input
```

### 2. Поиск по шаблонам

```
> Search these files for SQL query construction
```

### 3. Чтение подозрительных файлов

```
> Read the files that matched the SQL pattern
```

### 4. Документирование результатов

```
> Write a summary of the SQL injection findings to findings.md
```

## Вопросы разрешений

Файловые операции могут требовать разрешений:

| Операция | Ключ разрешения | Поведение по умолчанию |
|----------|----------------|----------------------|
| Read | `read` | Разрешено (только чтение) |
| Glob | `glob` | Разрешено (только чтение) |
| Grep | `grep` | Разрешено (только чтение) |
| Write | `edit` | Требует разрешения |
| Edit | `edit` | Требует разрешения |

Инструменты Write и Edit управляются единым ключом разрешения `edit`.

### Автоматическое одобрение записи

Для автоматизации сопоставляйте glob-шаблоны путей файлов с действиями в `edit`:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "permission": {
    "edit": {
      "reports/**": "allow",
      "findings/**": "allow"
    }
  }
}
```

В качестве подстановочных знаков поддерживаются только `*` и `?`. Полную модель разрешений см. в [Разрешения](/docs/permissions).

## Работа с большими файлами

### Постраничное чтение

Для больших файлов:

```
> Read the first 100 lines of large-log.txt
> Read lines 100-200 of large-log.txt
```

### Бинарные файлы

Инструмент Read обрабатывает бинарные файлы:

```
> Read the binary at ./malware.exe and analyze its strings
```

## Интеграция с тестированием безопасности

### Ревью кода

```
> Analyze all authentication-related files for security issues

1. Find auth files: Glob **/*auth*.{ts,js}
2. Search for vulnerabilities: Grep patterns
3. Read and analyze matches
4. Document findings
```

### Аудит конфигурации

```
> Review all configuration files for security misconfigurations

1. Find configs: Glob **/{config,settings}*.{json,yaml,yml}
2. Read each file
3. Check for sensitive data exposure
4. Verify secure defaults
```

### Обнаружение секретов

```
> Scan the codebase for hardcoded secrets

1. Glob all source files
2. Grep for secret patterns
3. Read matches for verification
4. Report findings
```

<Aside variant="tip">
  Комбинируйте Glob и Grep для эффективного сканирования кодовой базы. Начинайте широко, затем сужайте.
</Aside>
