`wstg-agent` — это оркестратор конвейера тестирования веб-безопасности Cyberstrike. Он получает захваченный HTTP-трафик и направляет соответствующих специалистов WSTG на основе характеристик запросов и накопленного контекста сессии.

## Обзор

| Свойство | Значение |
|----------|----------|
| **ID агента** | `wstg-agent` |
| **Роль** | `orchestrator` |
| **Домен** | `@cyberstrike-io/web` |
| **Цвет** | Синий |

## Как это работает

`wstg-agent` — это **чистый оркестратор** — он не выполняет тестирование уязвимостей сам. Его рабочий процесс:

1. Получает захваченный HTTP-запрос (из [HackBrowser](/docs/features/hackbrowser) или [расширения Chrome](/docs/tools/chrome-extension))
2. Анализирует характеристики запроса и накопленный контекст сессии
3. Маршрутизирует запрос соответствующему специалисту(-ам) WSTG через сигнальную диспетчеризацию
4. Управляет очередью тестирования и триггерами повторного тестирования

## Маршрутизация на основе сигналов

Каждый захваченный запрос генерирует сигналы на основе своих свойств — пути конечной точки, параметров, заголовков, паттернов ответов и совпадений правил [Vortex](/docs/features/vortex). `wstg-agent` сопоставляет эти сигналы с классами специалистов:

| Категория сигнала | Специалист |
|-------------------|------------|
| Паттерны аутентификации | `wstg-authentication` |
| Индикаторы авторизации | `wstg-authorization` |
| Входные параметры | `wstg-input-validation` |
| Токены сессий | `wstg-session-mgmt` |
| Конечные точки конфигурации | `wstg-config-deploy` |
| Паттерны API | `wstg-api` |
| Криптографические индикаторы | `wstg-cryptography` |
| Ответы с ошибками | `wstg-error-handling` |
| Бизнес-логика | `wstg-business-logic` |
| Клиентские ресурсы | `wstg-client-side` |
| Конечные точки LLM | `wstg-llm` |

Один запрос может активировать нескольких специалистов, если он демонстрирует сигналы из нескольких категорий.

## Специалисты WSTG

Каждый специалист — это сфокусированный агент тестирования для одной категории WSTG:

| Специалист | Раздел WSTG | Фокус |
|-----------|-------------|-------|
| `wstg-info-gathering` | 4.1 | Определение версий, перечисление, обнаружение утечек |
| `wstg-config-deploy` | 4.2 | Конфигурация сервера, учётные данные по умолчанию, расширения файлов |
| `wstg-identity-mgmt` | 4.3 | Перечисление пользователей, создание учётных записей |
| `wstg-authentication` | 4.4 | Обход входа, тестирование учётных данных, MFA |
| `wstg-authorization` | 4.5 | IDOR, повышение привилегий, обход пути |
| `wstg-session-mgmt` | 4.6 | Фиксация сессии, атрибуты cookie, тайм-аут |
| `wstg-input-validation` | 4.7 | SQLi, XSS, SSTI, инъекция команд |
| `wstg-error-handling` | 4.8 | Раскрытие ошибок, стектрейсы |
| `wstg-cryptography` | 4.9 | Слабые шифры, padding oracle, раскрытие ключей |
| `wstg-business-logic` | 4.10 | Обход рабочего процесса, состояния гонки |
| `wstg-client-side` | 4.11 | DOM XSS, clickjacking, postMessage |
| `wstg-api` | 4.12 | BOLA, массовое присваивание, ограничение частоты |
| `wstg-llm` | Пользовательский | Prompt injection, атаки на LLM |

Каждый специалист несёт навыки WSTG (детерминированные тестовые скрипты), которые он выполняет против захваченных запросов.

## Escalation Hunter

После завершения тестирования специалистами [`escalation-hunter`](/docs/agents/escalation-hunter) анализирует все находки для выявления цепочечных уязвимостей и эскалации воздействия.

## Разрешения

Оркестратор `wstg-agent` имеет ограниченный набор разрешений:

- Может создавать задачи (направлять специалистов)
- Может читать контекст сессии и заметки о покрытии
- Может проверять статус методологии и scope
- Не может выполнять прямое тестирование или сообщать об уязвимостях
