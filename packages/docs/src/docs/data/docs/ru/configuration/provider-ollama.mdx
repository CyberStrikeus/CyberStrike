## Обзор

Преимущества Ollama:

- Полная конфиденциальность данных
- Отсутствие затрат на API
- Офлайн-работа
- Отсутствие лимитов частоты запросов
- Полный контроль над моделями

## Установка

### macOS

```bash
brew install ollama
```

### Linux

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### Windows

Скачайте с [ollama.com/download](https://ollama.com/download)

## Запуск Ollama

### Запуск сервера

```bash
ollama serve
```

Сервер по умолчанию работает на `http://localhost:11434`.

### Проверка установки

```bash
ollama --version
```

## Доступные модели

### Рекомендуемые модели

| Модель | Размер | Лучше всего для |
|--------|--------|----------------|
| llama3.3:70b | 40GB | Лучшее качество, требует мощную GPU |
| llama3.3 | 4.7GB | Хороший баланс качества и скорости |
| codellama:34b | 19GB | Анализ кода |
| mistral | 4.1GB | Быстрое универсальное использование |
| mixtral:8x7b | 26GB | Высокое качество, эффективная |
| deepseek-coder:33b | 19GB | Обзор безопасности кода |
| qwen2.5:72b | 41GB | Отличные рассуждения |

### Загрузка моделей

```bash
# Рекомендуется для тестирования безопасности
ollama pull llama3.3

# Для обзора кода
ollama pull codellama:34b

# Лёгкий вариант
ollama pull mistral
```

### Список установленных моделей

```bash
ollama list
```

## Конфигурация

Ollama — **не** встроенный провайдер; вы определяете его как пользовательский OpenAI-совместимый провайдер. Ключевым является поле верхнего уровня `api` (базовый URL с суффиксом `/v1`); указание в `provider` с URL в `api` — это то, что заставляет Cyberstrike загрузить его (аутентификация не требуется). Определите загруженные модели в `models`:

### Базовая настройка

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "provider": {
    "ollama": {
      "name": "Ollama",
      "api": "http://localhost:11434/v1",
      "models": {
        "llama3.3": { "name": "Llama 3.3" }
      }
    }
  },
  "model": "ollama/llama3.3"
}
```

`npm` по умолчанию использует `@ai-sdk/openai-compatible`, поэтому устанавливать его не нужно.

### Пользовательский хост

Для удалённого сервера Ollama измените URL в `api`:

```json
{
  "provider": {
    "ollama": {
      "name": "Ollama",
      "api": "http://192.168.1.100:11434/v1",
      "models": { "llama3.3": { "name": "Llama 3.3" } }
    }
  }
}
```

## Использование

Используйте `/models` в TUI для выбора модели Ollama или установите её по умолчанию в конфигурации.

## Конфигурация модели

### Длина контекста

Увеличение контекстного окна:

```bash
ollama run llama3.3 --num-ctx 8192
```

Или в Modelfile:

```
FROM llama3.3
PARAMETER num_ctx 8192
```

### Слои GPU

Управление использованием GPU:

```bash
OLLAMA_NUM_GPU=999 ollama serve  # Использовать все слои GPU
OLLAMA_NUM_GPU=0 ollama serve    # Только CPU
```

### Управление памятью

```bash
# Ограничение использования VRAM
OLLAMA_MAX_VRAM=8G ollama serve
```

## Пользовательские модели

### Создание Modelfile

```dockerfile title="Modelfile"
FROM llama3.3

SYSTEM """
You are a security testing assistant specialized in:
- Web application vulnerabilities
- Code security review
- Network penetration testing

Always follow OWASP guidelines and report findings with:
- Vulnerability name
- Severity (Critical/High/Medium/Low)
- Evidence
- Remediation steps
"""

PARAMETER temperature 0.7
PARAMETER num_ctx 8192
```

### Сборка пользовательской модели

```bash
ollama create security-assistant -f Modelfile
```

### Использование пользовательской модели

Добавьте пользовательскую модель в конфигурацию и выберите через `/models`:

```json
{
  "provider": {
    "ollama": {
      "models": {
        "security-assistant": { "name": "Security Assistant" }
      }
    }
  }
}
```

## Оптимизация производительности

### Требования к оборудованию

| Размер модели | Мин. RAM | Рекомендуемая GPU |
|---------------|---------|-------------------|
| 7B | 8GB | 8GB VRAM |
| 13B | 16GB | 12GB VRAM |
| 34B | 32GB | 24GB VRAM |
| 70B | 64GB | 48GB VRAM |

### Квантизация

Используйте квантизированные модели для меньшего расхода памяти:

```bash
ollama pull llama3.3:q4_0  # 4-битная квантизация
ollama pull llama3.3:q8_0  # 8-битная квантизация
```

### Параллельные запросы

Включение одновременных запросов:

```bash
OLLAMA_NUM_PARALLEL=4 ollama serve
```

## Офлайн-использование

### Предварительная загрузка моделей

```bash
ollama pull llama3.3
ollama pull codellama
```

### Изолированные системы

1. Загрузите модели на подключённой системе
2. Скопируйте `~/.ollama/models/` на изолированную систему
3. Запустите Ollama без интернета

## Развёртывание в Docker

### Запуск в контейнере

```bash
docker run -d \
  --gpus all \
  -v ollama:/root/.ollama \
  -p 11434:11434 \
  --name ollama \
  ollama/ollama
```

### Загрузка моделей в контейнере

```bash
docker exec -it ollama ollama pull llama3.3
```

## Совместимость API

Ollama предоставляет OpenAI-совместимый API по адресу `http://localhost:11434/v1` — именно поэтому приведённая выше конфигурация пользовательского провайдера работает (`npm` по умолчанию использует `@ai-sdk/openai-compatible`). Укажите этот URL в поле `api`, и Cyberstrike будет общаться с Ollama по протоколу OpenAI.

## Устранение неполадок

### Connection Refused

```
Error: Connection refused
```

Убедитесь, что Ollama запущен:

```bash
ollama serve
```

### Нехватка памяти

```
Error: CUDA out of memory
```

Решения:
- Используйте модель меньшего размера
- Используйте квантизированную версию
- Уменьшите длину контекста
- Установите `OLLAMA_NUM_GPU=0` для CPU

### Низкая производительность

- Включите ускорение GPU
- Используйте квантизированные модели
- Увеличьте `num_parallel`
- Проверьте термальный троттлинг

<Aside variant="tip">
  Для лучших результатов используйте llama3.3:70b с мощной GPU. Для систем с ограниченными ресурсами mistral обеспечивает хорошее качество при меньших требованиях.
</Aside>
