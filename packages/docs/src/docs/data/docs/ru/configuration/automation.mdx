В неинтерактивных запусках (`cyberstrike run`) некому отвечать на запросы разрешений — поэтому любой инструмент, который *запросил бы* разрешение, **автоматически отклоняется**. Чтобы позволить пайплайну выполнять реальную работу, предварительно одобрите необходимые инструменты.

## Предварительное одобрение инструментов

Режима "auto" нет. Предоставляйте разрешения двумя способами:

**1. Переменная окружения `CYBERSTRIKE_PERMISSION`** — JSON-карта разрешений (такая же структура, как поле конфигурации `permission`):

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
cyberstrike run "scan this codebase for security issues" --format json > report.json
```

**2. Конфигурация `permission`** — закоммитьте безопасные значения по умолчанию, запретите опасные действия (см. [Шаблоны](/docs/configuration/permission-patterns)):

```json title="cyberstrike.json"
{
  "permission": {
    "read": "allow",
    "bash": { "*": "allow", "rm -rf *": "deny", "sudo *": "deny" },
    "edit": { "reports/**": "allow", ".env*": "deny" }
  }
}
```

Вывод направляется в stdout; используйте `--format json` для машинно-читаемых результатов.

## Интеграция CI/CD

### GitHub Actions

```yaml title=".github/workflows/security-scan.yml"
name: Security Scan
on:
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @cyberstrike-io/cyberstrike@latest
      - name: Run Security Scan
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
        run: cyberstrike run "scan this codebase for security vulnerabilities" --format json > security-report.json
      - uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: security-report.json
```

### GitLab CI

```yaml title=".gitlab-ci.yml"
security-scan:
  image: node:20
  variables:
    CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'
  script:
    - npm install -g @cyberstrike-io/cyberstrike@latest
    - cyberstrike run "analyze code for vulnerabilities" --format json > report.json
  artifacts:
    paths:
      - report.json
```

## Пакетные и запланированные запуски

Перебирайте цели или запускайте по расписанию — действуют те же правила `CYBERSTRIKE_PERMISSION` (или конфигурации):

```bash title="scan-targets.sh"
#!/bin/bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow"}'
while read -r target; do
  cyberstrike run "scan $target for open ports and services" --format json > "reports/${target}.json"
done < targets.txt
```

```bash
# Ежедневное сканирование в 02:00
0 2 * * * CYBERSTRIKE_PERMISSION='{"bash":"allow"}' /usr/local/bin/cyberstrike run "daily security scan" >> /var/log/cyberstrike.log 2>&1
```

## Коды завершения и вывод

`cyberstrike run` записывает результаты в stdout (`--format json` для JSON) и возвращает `0` при успехе, ненулевой код при ошибке или прерывании. Парсите JSON для получения находок:

```bash
cyberstrike run "scan target" --format json | jq '.'
```

## Соображения безопасности

- **Минимальные привилегии** — ставьте `allow` только для инструментов, необходимых задаче; сохраняйте явный `deny` для `rm -rf *`, `sudo *` и путей к секретам.
- **Секреты** — инжектируйте API-ключи из хранилища секретов CI, никогда не коммитьте их.
- **Изоляция** — по возможности запускайте в контейнере с ограниченной сетью.

<Aside variant="caution">
  Всегда сохраняйте правила deny для деструктивных команд при предварительном одобрении `bash` в автоматизации.
</Aside>
