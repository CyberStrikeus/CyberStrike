Переменные окружения настраивают учётные данные провайдеров и переключают поведение во время выполнения — полезно для CI/CD и контейнерных сред.

<Aside variant="info">
  Cyberstrike **не** читает настройки, такие как модель, агент или тема, из переменных окружения. Они хранятся в файле конфигурации (см. [Справочник по конфигурации](/docs/configuration)). Переменные `CYBERSTRIKE_*` ниже ограничены учётными данными, путями конфигурации и переключателями поведения.
</Aside>

## API-ключи провайдеров

Ключи провайдеров используют стандартные имена переменных SDK. Полный список см. в [ИИ-провайдеры](/docs/configuration/providers).

### Anthropic

```bash
export ANTHROPIC_API_KEY="sk-ant-api03-..."
```

### OpenAI

```bash
export OPENAI_API_KEY="sk-proj-..."
```

### Google (Gemini)

```bash
export GOOGLE_GENERATIVE_AI_API_KEY="AI..."
# GEMINI_API_KEY также принимается
```

### OpenRouter

```bash
export OPENROUTER_API_KEY="sk-or-..."
```

### Groq

```bash
export GROQ_API_KEY="gsk_..."
```

### Azure OpenAI

```bash
export AZURE_RESOURCE_NAME="your-resource"
export AZURE_API_KEY="..."
```

### AWS Bedrock

```bash
export AWS_ACCESS_KEY_ID="AKIA..."
export AWS_SECRET_ACCESS_KEY="..."
export AWS_REGION="us-east-1"
# или bearer-токен:
export AWS_BEARER_TOKEN_BEDROCK="..."
```

## Переменные пути конфигурации

| Переменная | Описание |
|------------|----------|
| `CYBERSTRIKE_CONFIG` | Полный путь к пользовательскому файлу конфигурации |
| `CYBERSTRIKE_CONFIG_DIR` | Дополнительный каталог `.cyberstrike` для сканирования |
| `CYBERSTRIKE_CONFIG_CONTENT` | Встроенная JSON-конфигурация (переопределяет файловые источники) |
| `CYBERSTRIKE_DISABLE_PROJECT_CONFIG` | Установите truthy для пропуска загрузки конфигурации проекта |
| `CYBERSTRIKE_PERMISSION` | Переопределение разрешений как JSON-строка |

## Флаги поведения

Эти переменные переключают поведение во время выполнения. Булевы флаги включаются при установке truthy значения (`1`, `true`).

| Переменная | Описание |
|------------|----------|
| `CYBERSTRIKE_AUTO_SHARE` | Автоматический общий доступ к новым сессиям |
| `CYBERSTRIKE_DISABLE_AUTOUPDATE` | Отключить автоматические обновления |
| `CYBERSTRIKE_DISABLE_AUTOCOMPACT` | Отключить автоматическую компактификацию контекста |
| `CYBERSTRIKE_DISABLE_PRUNE` | Отключить очистку старых выводов инструментов |
| `CYBERSTRIKE_DISABLE_TERMINAL_TITLE` | Не обновлять заголовок терминала |
| `CYBERSTRIKE_DISABLE_DEFAULT_PLUGINS` | Пропустить загрузку встроенных плагинов |
| `CYBERSTRIKE_DISABLE_LSP_DOWNLOAD` | Не скачивать LSP-серверы |
| `CYBERSTRIKE_DISABLE_MODELS_FETCH` | Не загружать удалённый каталог моделей |
| `CYBERSTRIKE_DISABLE_EXTERNAL_SKILLS` | Пропустить загрузку внешних навыков |
| `CYBERSTRIKE_ENABLE_EXA` | Включить веб-поиск на базе Exa |
| `CYBERSTRIKE_MODELS_URL` | Переопределить URL каталога моделей |
| `CYBERSTRIKE_MODELS_PATH` | Загрузить каталог моделей из локального пути |

### Учётные данные сервера

Используются `cyberstrike serve` и `cyberstrike web`:

```bash
export CYBERSTRIKE_SERVER_PASSWORD="..."   # обязательно для запуска сервера
export CYBERSTRIKE_SERVER_USERNAME="admin" # необязательно, есть значения по умолчанию
```

## Ссылки на переменные в конфигурации

Файлы конфигурации поддерживают две подстановки — и только эти две:

### Переменные окружения — `{env:VAR}`

```jsonc title="~/.config/cyberstrike/cyberstrike.jsonc"
{
  "provider": {
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

`{env:VAR}` заменяется значением `VAR` или пустой строкой, если не установлена. Shell-синтаксис `${VAR}`, `$VAR` и синтаксис значений по умолчанию (`{env:VAR:-default}`) **не** поддерживаются.

### Содержимое файлов — `{file:path}`

```json
{
  "instructions": ["{file:./SECURITY.md}"]
}
```

Пути могут быть относительными к файлу конфигурации, абсолютными или начинаться с `~/` для домашнего каталога.

## Переопределение разрешений для автоматизации

`cyberstrike run` (неинтерактивный) автоматически отклоняет любой вызов инструмента, который потребовал бы запроса. Для предварительного одобрения инструментов в CI передайте JSON-карту разрешений через `CYBERSTRIKE_PERMISSION`:

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","edit":"allow","read":"allow"}'
```

Значение имеет ту же форму, что и поле конфигурации `permission`. См. [Разрешения](/docs/configuration/permissions).

## Настройка оболочки

### Bash / Zsh

```bash title="~/.bashrc / ~/.zshrc"
export ANTHROPIC_API_KEY="sk-ant-..."
export CYBERSTRIKE_AUTO_SHARE=1
```

### Fish

```fish title="~/.config/fish/config.fish"
set -gx ANTHROPIC_API_KEY "sk-ant-..."
set -gx CYBERSTRIKE_AUTO_SHARE 1
```

## Файлы .env

```bash title=".env"
ANTHROPIC_API_KEY=sk-ant-...
CYBERSTRIKE_PERMISSION={"bash":"allow"}
```

```bash
# Загрузить перед запуском
source .env && cyberstrike
```

<Aside variant="caution">
  Никогда не коммитьте файлы `.env` в систему контроля версий. Добавьте `.env` в `.gitignore`.
</Aside>

## Интеграция CI/CD

### GitHub Actions

```yaml
env:
  ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
  CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":"allow"}'

steps:
  - name: Security Scan
    run: cyberstrike run "scan for vulnerabilities"
```

### GitLab CI

```yaml
variables:
  CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'

security_scan:
  script:
    - cyberstrike run "analyze code for security issues"
```

## Docker

### Docker Run

```bash
docker run -it \
  -e ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  -e CYBERSTRIKE_PERMISSION='{"bash":"allow"}' \
  cyberstrike/cyberstrike
```

### Docker Compose

```yaml title="docker-compose.yml"
services:
  cyberstrike:
    image: cyberstrike/cyberstrike
    environment:
      - ANTHROPIC_API_KEY
      - CYBERSTRIKE_AUTO_SHARE=1
    env_file:
      - .env
```

## Порядок приоритетов

Источники конфигурации объединяются в этом порядке (наивысший побеждает):

```
1. Аргументы командной строки
2. Управляемая корпоративная конфигурация
3. CYBERSTRIKE_CONFIG_CONTENT (встроенный JSON)
4. Конфигурация каталога .cyberstrike/
5. Конфигурация проекта (cyberstrike.json / .jsonc)
6. CYBERSTRIKE_CONFIG (пользовательский файл)
7. Глобальная конфигурация (~/.config/cyberstrike/)
8. Удалённая .well-known/cyberstrike
9. Значения по умолчанию
```

Подробности см. в [Справочнике по конфигурации](/docs/configuration#configuration-hierarchy).

## Проверка переменных

```bash
# Список активных переменных Cyberstrike
env | grep CYBERSTRIKE

# Проверка установки ключа провайдера (без полного вывода)
echo "${ANTHROPIC_API_KEY:0:12}..."
```

## Безопасность

1. Никогда не выводите полные API-ключи
2. Используйте управление секретами в CI/CD
3. Регулярно ротируйте ключи
4. Ограничьте права `.env`: `chmod 600 .env`

<Aside variant="tip">
  Используйте менеджер секретов, такой как HashiCorp Vault, AWS Secrets Manager или 1Password CLI для продакшен-сред.
</Aside>
