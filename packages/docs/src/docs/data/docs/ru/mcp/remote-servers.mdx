Удалённые MCP-серверы подключаются через HTTP/HTTPS, обеспечивая доступ к размещённым сервисам и общей инфраструктуре. Транспорт — StreamableHTTP (с откатом на SSE).

<Aside variant="tip">
  **Ищете инструменты безопасности?** См. [Bolt](/docs/mcp/bolt) для предустановленных инструментов безопасности. Обратите внимание, что Bolt настраивается под собственным ключом верхнего уровня `bolt`, а не под `mcp`.
</Aside>

## Схема конфигурации

Удалённый сервер — это одна запись в плоской карте `mcp`, с ключом по имени сервера:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "Bearer {env:MY_TOKEN}" },
      "enabled": true,
      "timeout": 5000
    }
  }
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `type` | `"remote"` | Обязательно. Выбирает HTTP-сервер. |
| `url` | string | Обязательно. Конечная точка сервера. |
| `headers` | object | Необязательно. Заголовки, отправляемые с каждым запросом (напр. API-ключ). |
| `oauth` | object \| `false` | Необязательно. Конфигурация OAuth; установите `false` для отключения автообнаружения OAuth. См. [OAuth](/docs/mcp/oauth). |
| `enabled` | boolean | Необязательно. Подключение при запуске (по умолчанию: true). |
| `timeout` | number | Необязательно. Таймаут запроса в мс (по умолчанию: 5000). |

<Aside variant="caution">
  Объект `mcp` — это **плоская карта** с ключами по имени сервера — обёртки `servers` нет. Транспорт только StreamableHTTP/SSE (WebSocket-транспорта нет), а схема строгая: полей `retry`, `keepalive`, `proxy`, TLS/`ca`/`cert` и балансировки нагрузки **не** существует.
</Aside>

## Добавление через TUI

Введите `/mcps` для открытия менеджера MCP, нажмите `a` для добавления и выберите **Remote**. Введите **URL** сервера; **имя** сервера определяется автоматически из имени хоста (точки становятся дефисами). Cyberstrike проверяет подключение перед сохранением. Записывается именно та схема, что показана выше.

## Аутентификация

### API-ключ через заголовок

Отправляйте статический токен или API-ключ в заголовке запроса. Используйте `{env:VAR}`, чтобы секрет не хранился в файле конфигурации:

```json
{
  "mcp": {
    "github-remote": {
      "type": "remote",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer {env:GITHUB_TOKEN}" }
    }
  }
}
```

### OAuth

Для серверов, использующих OAuth, добавьте блок `oauth` (или позвольте Cyberstrike обнаружить его автоматически). Когда `clientId` не указан, выполняется динамическая регистрация клиента (RFC 7591):

```json
{
  "mcp": {
    "oauth-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": { "scope": "read write" }
    }
  }
}
```

Авторизуйтесь с помощью `cyberstrike mcp auth <name>`. Полный процесс см. в [OAuth](/docs/mcp/oauth). Установите `"oauth": false` для отключения автообнаружения OAuth.

## Включение, отключение и таймауты

Установите `enabled: false`, чтобы сохранить сервер настроенным, но отключённым (или переключайте в `/mcps`). Увеличьте `timeout` (мс) для медленных конечных точек:

```json
{
  "mcp": {
    "slow-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "enabled": false,
      "timeout": 30000
    }
  }
}
```

## Устранение неполадок

- **Ошибки аутентификации** — проверьте заголовок или выполните `cyberstrike mcp auth <name>` для OAuth-серверов; проверьте с помощью `cyberstrike mcp debug <name>`.
- **Таймауты** — увеличьте `timeout` или подтвердите доступность конечной точки.
- **Конфигурация отклонена** — схема строгая; используйте плоскую карту с `type: "remote"` + `url` и только полями, перечисленными выше.
