Bolt — контейнеризированный MCP-сервер, предоставляющий инструменты безопасности. Он запускается в Docker-контейнере (Ubuntu 24.04) и предоставляет каждый инструмент напрямую — без мета-инструментов, без динамической загрузки, просто вызывайте нужный инструмент.

## Зачем Bolt?

Bolt решает проблему запуска инструментов безопасности, которым нужна среда Linux. Вместо установки инструментов локально, Bolt запускает их в изолированном контейнере.

| Возможность | Без Bolt | С Bolt |
|-------------|----------|--------|
| Установка инструментов | Вручную для каждого | Предустановлены |
| Поддержка платформ | Только Linux для большинства | Любая платформа с Docker |
| Изоляция | Инструменты запускаются на вашей системе | Изолированы в контейнере |
| Обновления | Вручную | `docker pull` |

## Что внутри

Bolt (`bolt.config.json`, порт `3001`) предоставляет инструменты двумя способами:

- **7 нативных плагинов** — `subfinder`, `nmap`, `nuclei`, `httpx`, `ffuf`, `run-command`, `wordlist`
- **~26 агрегированных stdio MCP-серверов** — напр. `dnsx`, `amass`, `katana`, `sqlmap`, `wpscan`, `gobuster`, `masscan`, `hydra`, `hashcat`, `john`, `impacket` и другие

Каждый — это напрямую вызываемый инструмент — агент вызывает его за один ход, без шага поиска/загрузки.

## Быстрый старт

### 1. Запустите контейнер Bolt

```bash
docker run -d \
  --name bolt \
  --restart unless-stopped \
  -p 3001:3001 \
  -v bolt-data:/data \
  -e MCP_ADMIN_TOKEN=$(openssl rand -hex 32) \
  --cap-add NET_RAW \
  --cap-add NET_ADMIN \
  ghcr.io/cyberstrikeus/bolt:latest

# Просмотр admin-токена (используется один раз, для сопряжения)
docker logs bolt | grep -i token
```

### 2. Сопряжение с Cyberstrike

Откройте диалог `/bolt` в TUI, нажмите **a** для добавления, введите URL `http://localhost:3001` и предоставьте admin-токен. Cyberstrike сопрягается с сервером (см. [Аутентификация](#аутентификация)) и сохраняет учётные данные — сам токен **не** записывается в конфигурацию.

### 3. Используйте инструменты

```
> Run nmap against 192.168.1.1 with service detection
> Use subfinder to enumerate subdomains of example.com
```

## Конфигурация

Серверы Bolt настраиваются под **собственным ключом верхнего уровня `bolt`** — не под `mcp`. Каждая запись требует только `url` (Cyberstrike добавляет путь `/mcp` самостоятельно):

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true,
      "timeout": 30000
    }
  }
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `url` | string | Обязательно. Базовый URL сервера Bolt (напр. `http://localhost:3001`). |
| `enabled` | boolean | Необязательно. Подключение при запуске (по умолчанию: true). |
| `timeout` | number | Необязательно. Таймаут запроса в мс (по умолчанию: 30000). |

<Aside variant="caution">
  Bolt — это **не** запись `mcp`. Нет `type: "remote"`, нет флага `bolt: true` и нет заголовка `Authorization` в конфигурации — аутентификация обрабатывается Ed25519-сопряжением, а admin-токен существует только на этапе сопряжения.
</Aside>

## Аутентификация

Bolt использует **подписание запросов Ed25519**, инициализируемое однократным сопряжением с admin-токеном:

1. `POST /pair` с admin-токеном -> код сопряжения
2. Cyberstrike генерирует пару ключей Ed25519
3. `POST /pair/exchange` с кодом + публичным ключом клиента -> публичный ключ сервера + ID клиента
4. Далее каждый запрос **подписывается** закрытым ключом клиента

Admin-токен используется только на шаге 1 — это не постоянный bearer-токен, и он никогда не хранится в `cyberstrike.json`.

## Управление через TUI

Два отдельных диалога:

- **`/bolt`** — управление серверами Bolt (добавление/сопряжение, переключение, удаление).
- **`/mcps`** — управление обычными локальными/удалёнными MCP-серверами.

В диалоге `/bolt`: **a** для добавления, **space** для переключения сервера, **esc** для закрытия.

## Примеры использования

```
> Use bolt to scan 192.168.1.0/24 for open ports and services   # nmap
> Find all subdomains of example.com                            # subfinder
> Scan https://target.com with nuclei                           # nuclei
> Fuzz directories on https://target.com                        # ffuf
> Run "dig +short example.com"                                  # run-command escape hatch
```

Каждый маппится на прямой вызов инструмента — без шага загрузки.

## Конфигурация контейнера

### Переменные окружения

| Переменная | По умолчанию | Описание |
|------------|-------------|----------|
| `PORT` | 3001 | Порт HTTP-сервера |
| `HOST` | 0.0.0.0 | Адрес привязки |
| `MCP_ADMIN_TOKEN` | — | Admin-токен для сопряжения |
| `DATA_DIR` | /data | Каталог постоянных данных |

### Capabilities Docker

| Capability | Назначение |
|------------|-----------|
| `NET_RAW` | Raw-сокеты для SYN-сканирования nmap |
| `NET_ADMIN` | Сетевая конфигурация для инструментов, требующих повышенного доступа |

## Справочник API

| Эндпоинт | Назначение |
|----------|-----------|
| `GET /health` | Проверка работоспособности — возвращает `{ "status": "ok" }` (аутентифицированные admin-запросы получают детальную информацию, включая количество инструментов) |
| `POST /mcp` | MCP JSON-RPC эндпоинт (подписанные запросы) |
| `POST /pair` | Начало Ed25519-сопряжения с admin-токеном |
| `POST /pair/exchange` | Обмен кодом сопряжения + публичными ключами |

```bash
curl http://localhost:3001/health
```

## Устранение неполадок

- **Connection refused** — проверьте, что контейнер запущен (`docker ps`), порт проброшен (`docker port bolt`) и `curl http://localhost:3001/health` отвечает.
- **Требуется повторное сопряжение** — если URL Bolt изменился, Cyberstrike сбрасывает сохранённые учётные данные и вам нужно повторно сопрячь через `/bolt`.
- **Инструменты недоступны** — убедитесь, что сервер подключён в `/bolt`, и используйте модель с прямым API (напр. `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`).
