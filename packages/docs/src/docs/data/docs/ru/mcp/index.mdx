Cyberstrike использует Model Context Protocol (MCP) для интеграции внешних инструментов. **Bolt** — наш контейнеризированный сервер инструментов, поставляющий большой набор инструментов безопасности; вы также можете подключить любой локальный или удалённый MCP-сервер.

## Два способа добавления инструментов

| Подход | Транспорт | Плюсы | Минусы |
|--------|-----------|-------|--------|
| **Bolt** (рекомендуется) | StreamableHTTP | Предустановленные инструменты, изоляция контейнера, простая настройка | Требуется Docker, сетевая задержка |
| **Локальный / удалённый MCP** | stdio / StreamableHTTP | Любой MCP-сервер; нулевая задержка для локальных | Вы устанавливаете и запускаете сервер |

Cyberstrike также поставляет три MCP-сервера, включённых по умолчанию: `github-security`, `cve` и `osint`. Ваша конфигурация объединяется поверх них.

## Bolt

Bolt запускает инструменты безопасности внутри Docker-контейнера (Ubuntu 24.04, порт 3001). Он предоставляет **7 нативных плагинов** (`subfinder`, `nmap`, `nuclei`, `httpx`, `ffuf`, `run-command`, `wordlist`) плюс **~26 агрегированных stdio MCP-серверов** (`dnsx`, `amass`, `katana`, `sqlmap`, `wpscan`, `hydra`, `hashcat` и другие). Каждый инструмент вызывается напрямую — агент вызывает его за один ход.

Bolt настраивается под **собственным ключом верхнего уровня `bolt`** (не `mcp`) и аутентифицируется через Ed25519-сопряжение:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": { "url": "http://localhost:3001" }
  }
}
```

Настройку и сопряжение см. на странице [Bolt](/docs/mcp/bolt).

## Локальный / удалённый MCP

Любой другой MCP-сервер добавляется в плоскую карту `mcp` по имени:

```json title="cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["your-mcp-server"]
    }
  }
}
```

- [Локальные серверы](/docs/mcp/local-servers) — дочерние процессы stdio
- [Удалённые серверы](/docs/mcp/remote-servers) — StreamableHTTP/SSE, с опциональным [OAuth](/docs/mcp/oauth)

## Управление через TUI

Два отдельных диалога:

- **`/bolt`** — управление серверами Bolt (добавление и сопряжение, переключение, удаление).
- **`/mcps`** — управление локальными/удалёнными MCP-серверами.

В обоих: **a** для добавления, **space** для переключения сервера, **esc** для закрытия.

## Совместимость моделей

<Aside variant="caution">
  Модели на основе подпроцессов не могут получить доступ к инструментам MCP. Используйте модель с прямым API для полной интеграции Bolt/MCP.
</Aside>

Модели с прямым API (напр. `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`) работают внутри Cyberstrike и имеют полный доступ к MCP. Модели, которые вызывают отдельный CLI-процесс, — нет.

## Приоритет конфигурации

Записи MCP и Bolt следуют стандартной [иерархии конфигурации](/docs/configuration#configuration-hierarchy): каталог `.cyberstrike/` проекта переопределяет проектный `cyberstrike.json`, который переопределяет глобальный `~/.config/cyberstrike/`, который переопределяет встроенные серверы.
