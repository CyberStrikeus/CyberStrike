Создавайте пользовательские MCP-серверы для расширения Cyberstrike специализированными инструментами и интеграциями. Это полезно, когда вам нужны возможности, выходящие за пределы [Bolt](/docs/mcp/bolt).

<img src="/docs/images/diagrams/mcp-server-architecture.svg" alt="Архитектура MCP-сервера: MCP-клиент Cyberstrike подключается через stdio или StreamableHTTP/SSE к транспорту, который маршрутизирует запросы к обработчикам (tools/list, tools/call, resources) и вашим функциям инструментов" className="my-6" />

## Обзор

MCP-серверы:

- Предоставляют инструменты Cyberstrike
- Обрабатывают выполнение инструментов
- Управляют ресурсами
- Поддерживают несколько транспортов
- Обеспечивают пользовательские интеграции

## Быстрый старт

### TypeScript-сервер

```typescript title="src/index.ts"
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new Server({
  name: "my-security-tools",
  version: "1.0.0"
}, {
  capabilities: {
    tools: {}
  }
});

// Определение инструментов
server.setRequestHandler("tools/list", async () => ({
  tools: [{
    name: "port-scan",
    description: "Scan ports on a target host",
    inputSchema: {
      type: "object",
      properties: {
        host: { type: "string", description: "Target hostname or IP" },
        ports: { type: "string", description: "Port range (e.g., 1-1000)" }
      },
      required: ["host"]
    }
  }]
}));

// Обработка вызовов инструментов
server.setRequestHandler("tools/call", async (request) => {
  const { name, arguments: args } = request.params;

  if (name === "port-scan") {
    const result = await scanPorts(args.host, args.ports);
    return { content: [{ type: "text", text: result }] };
  }

  throw new Error(`Unknown tool: ${name}`);
});

// Запуск сервера
const transport = new StdioServerTransport();
await server.connect(transport);
```

### Python-сервер

```python title="server.py"
import asyncio
from mcp.server import Server
from mcp.server.stdio import stdio_server

server = Server("my-security-tools")

@server.list_tools()
async def list_tools():
    return [{
        "name": "port-scan",
        "description": "Scan ports on a target host",
        "inputSchema": {
            "type": "object",
            "properties": {
                "host": {"type": "string", "description": "Target hostname"},
                "ports": {"type": "string", "description": "Port range"}
            },
            "required": ["host"]
        }
    }]

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "port-scan":
        result = await scan_ports(arguments["host"], arguments.get("ports"))
        return [{"type": "text", "text": result}]
    raise ValueError(f"Unknown tool: {name}")

async def main():
    async with stdio_server() as streams:
        await server.run(streams[0], streams[1])

asyncio.run(main())
```

```typescript
  parameter: string;
```

## Варианты транспорта

### Stdio (по умолчанию)

```typescript
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const transport = new StdioServerTransport();
await server.connect(transport);
```

### HTTP/SSE

```typescript
import { SSEServerTransport } from "@modelcontextprotocol/sdk/server/sse.js";
import express from "express";

const app = express();
const transport = new SSEServerTransport("/sse", app);

app.listen(3000);
await server.connect(transport);
```

<Aside variant="info">
  Cyberstrike подключается к **stdio**-серверам (локальным) и **StreamableHTTP/SSE**-серверам (удалённым). WebSocket-клиентного транспорта нет — не создавайте сервер только с WebSocket.
</Aside>

## Регистрация в Cyberstrike

Когда ваш сервер запущен, добавьте его в `cyberstrike.json`. Stdio-сервер — это запись `local`, где `command` — полный argv:

```json title="cyberstrike.json"
{
  "mcp": {
    "my-security-tools": {
      "type": "local",
      "command": ["node", "dist/index.js"]
    }
  }
}
```

HTTP/SSE-сервер — это запись `remote`:

```json
{
  "mcp": {
    "my-security-tools": {
      "type": "remote",
      "url": "https://localhost:3000/sse"
    }
  }
}
```

Или добавьте интерактивно через `/mcps` в TUI. Полную схему см. в [Локальные серверы](/docs/mcp/local-servers) и [Удалённые серверы](/docs/mcp/remote-servers).

## Обработка ошибок

### Ошибки инструментов

```typescript
server.setRequestHandler("tools/call", async (request) => {
  try {
    const result = await executeTool(request.params);
    return { content: [{ type: "text", text: result }] };
  } catch (error) {
    return {
      content: [{
        type: "text",
        text: `Error: ${error.message}`

      isError: true
    };
  }
});
```

## Соображения безопасности

### Валидация входных данных

```typescript
function sanitizeHost(host: string): string {
  // Валидация формата хоста
  if (!/^[\w.-]+$/.test(host)) {
    throw new Error("Invalid host format");
  }
  return host;
}
```

### Предотвращение инъекций команд

```typescript
import { execFile } from "child_process";

// Безопасно: используется execFile с массивом аргументов
async function safeScan(host: string): Promise<string> {
  return new Promise((resolve, reject) => {
    execFile("nmap", ["-sV", host], (error, stdout) => {
      if (error) reject(error);
      else resolve(stdout);
    });
  });
}

// Небезопасно: не делайте так
// exec(`nmap -sV ${host}`) // Уязвимость инъекции команд!
```

## Лучшие практики

1. **Понятные описания** — документируйте инструменты тщательно
2. **Валидация входных данных** — валидируйте все входные данные
3. **Обработка ошибок** — возвращайте осмысленные ошибки
4. **Логирование** — логируйте операции для отладки
5. **Тестирование** — тестируйте все инструменты тщательно
6. **Безопасность** — предотвращайте атаки инъекций

<Aside variant="tip">
  Начните с stdio-транспорта для простоты, затем добавьте HTTP/SSE для удалённого доступа.
</Aside>
