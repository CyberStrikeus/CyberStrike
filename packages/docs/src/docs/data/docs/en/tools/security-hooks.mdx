Hooks are domain-specific pentest program suites. Each hook is a single tool that bundles dozens of programs for a target domain — Linux, Windows, macOS, LLM, containers, Kubernetes, infrastructure-as-code, and web applications.

All hooks share the same interface:

```json
{
  "tool": "linux_hook",
  "input": {
    "program": "shadow_dump",
    "args": ""
  }
}
```

The agent selects the right hook and program based on the target environment. You can also call them directly from the TUI or via tool calls.

## Web Testing Tools

<Badge text="6 tools" variant="note" />

Unlike the hooks above, web testing tools are separate tools — each focused on a specific web attack class. They operate on captured HTTP traffic from [Hacker Browser](/docs/tools/hacker-browser) or the [Chrome Extension](/docs/tools/chrome-extension).

| Tool | Description |
|------|-------------|
| `authn_test` | Authentication testing — JWT tampering, session fixation, credential oracles, login bypass |
| `business_test` | Business logic — race conditions, boundary testing, workflow state abuse |
| `misconfig_test` | Server misconfiguration — debug endpoints, verbose errors, default credentials, security headers |
| `recon_test` | Web reconnaissance — directory enumeration, technology fingerprinting, hidden parameter discovery |
| `ssrf_test` | SSRF — cloud metadata endpoints, internal service access, protocol smuggling |
| `login_probe` | Login form detection — auto-detect login pages, test credential pairs, enumerate users |

### Example

```json
{
  "tool": "authn_test",
  "input": {
    "request_id": "req_abc123",
    "mode": "jwt"
  }
}
```

<Aside variant="tip">
  Web testing tools work with captured requests. Use [Hacker Browser](/docs/tools/hacker-browser) or the [Chrome Extension](/docs/tools/chrome-extension) to capture traffic first, then test with these tools.
</Aside>
