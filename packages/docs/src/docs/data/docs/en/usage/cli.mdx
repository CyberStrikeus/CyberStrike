CyberStrike CLI defaults to launching the [TUI](/docs/usage/tui) when run without arguments. It also accepts commands for non-interactive and programmatic use.

```bash
cyberstrike [global-options] <command> [command-options] [arguments]
```

## Global Flags

| Flag | Alias | Description |
|------|-------|-------------|
| `--help` | `-h` | Display help information |
| `--version` | `-v` | Print version |
| `--print-logs` | | Output logs to stderr |
| `--log-level` | | Set level: `DEBUG`, `INFO`, `WARN`, `ERROR` |

## Commands

| Command | Description |
|---------|-------------|
| `run` | Non-interactive mode with a direct prompt |
| `serve` | Headless HTTP server for API access |
| `web` | Headless server with [web interface](/docs/usage/web) |
| `attach` | Connect TUI to a running server |
| `auth` | Manage credentials and provider login |
| `agent` | Manage security agents |
| `mcp` | Manage MCP servers |
| `models` | List available models from providers |
| `session` | Manage sessions |
| `stats` | Display token usage and cost statistics |
| `export` | Export session data as JSON |
| `import` | Import from JSON file or share URL |
| `github` | GitHub App integration |
| `pr` | Review a pull request by number |
| `upgrade` | Update to latest or specific version |
| `uninstall` | Remove CyberStrike and related files |
| `completion` | Generate shell completion scripts |

## Interactive Mode

```bash
# Launch TUI
cyberstrike

# Start with specific model
cyberstrike --model anthropic/claude-sonnet-4-20250514

# Continue previous session
cyberstrike --continue
```

| Option | Alias | Description |
|--------|-------|-------------|
| `--model <model>` | `-m` | Model in format `provider/model` |
| `--agent <name>` | | Security agent to use |
| `--continue` | `-c` | Continue last session |
| `--session <id>` | `-s` | Resume specific session |

## run

Execute a single prompt without entering interactive mode. In this mode there is nobody to answer permission prompts, so any tool that would prompt is auto-rejected (see [Automation](/docs/configuration/automation)).

```bash
cyberstrike run [message..] [options]
```

### Options

| Option | Alias | Description |
|--------|-------|-------------|
| `--model <model>` | `-m` | Model in format `provider/model` |
| `--agent <name>` | | Security agent to use |
| `--continue` | `-c` | Continue last session |
| `--session <id>` | `-s` | Resume specific session |
| `--fork` | | Fork the session before continuing (needs `--continue`/`--session`) |
| `--file <path>` | `-f` | Attach file(s) to message (repeatable) |
| `--format <type>` | | Output format: `default` or `json` |
| `--share` | | Share the session |
| `--title <text>` | | Set session title |
| `--variant <type>` | | Model variant (`high`, `max`, `minimal`) |
| `--thinking` | | Show thinking blocks |
| `--attach <url>` | | Attach to a running server |
| `--dir <path>` | | Directory to run in (remote path when attaching) |
| `--port <number>` | | Port for the local server |
| `--command <name>` | | Run a named command; use the message for its arguments |

<Aside variant="caution">
  There is no `--output`, `--permission`, `--timeout`, `--verbose`, or `--quiet` flag. Output control is `--format` (`default` | `json`); reasoning display is `--thinking`.
</Aside>

### Examples

```bash
# Run a security scan
cyberstrike run "scan example.com for XSS vulnerabilities"

# Attach files for review
cyberstrike run "analyze this config for misconfigurations" -f nginx.conf

# JSON output for scripting
cyberstrike run "list all open ports" --format json > report.json

# Continue or fork a session
cyberstrike run "now check for SQLi" --continue
cyberstrike run "try a different payload" --session <id> --fork
```

### Piping Input

```bash
echo "analyze this code for vulnerabilities" | cyberstrike run
nmap -sV target.local | cyberstrike run "analyze these scan results"
```

### Permissions in `run`

Pre-approve tools for non-interactive use with the `CYBERSTRIKE_PERMISSION` env var:

```bash
CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow"}' \
  cyberstrike run "enumerate services on the host" --format json
```

See [Automation](/docs/configuration/automation) for CI patterns.

## serve

Start a headless HTTP API server without a UI.

```bash
cyberstrike serve [options]
```

| Option | Description |
|--------|-------------|
| `--port <number>` | Server port (default: 4096) |
| `--hostname <address>` | Bind address (default: `127.0.0.1`) |
| `--cors <origin>` | Allowed CORS origin |
| `--mdns` | Advertise the server over mDNS |

<Aside variant="caution">
  **Authentication:** Set `CYBERSTRIKE_SERVER_PASSWORD` when exposing the server on a network. Without it, the server is unsecured.
</Aside>

```bash
CYBERSTRIKE_SERVER_PASSWORD=secret cyberstrike serve --port 4096
```

## attach

Connect a TUI to an already-running CyberStrike server.

```bash
cyberstrike attach <url>
```

```bash
# Start server in one terminal
cyberstrike web --port 4096

# Attach from another terminal
cyberstrike attach http://localhost:4096
```

## auth

Manage authentication credentials for AI providers. Three subcommands — `login`, `logout`, `list` — all interactive (no flags).

### auth login

```bash
cyberstrike auth login [url]
```

Shows a provider list and prompts for an API key or OAuth flow. The optional `url` pre-selects a well-known provider URL. Credentials are stored in `~/.local/share/cyberstrike/auth.json`.

### auth list

```bash
cyberstrike auth list   # alias: ls
```

### auth logout

```bash
cyberstrike auth logout
```

Interactively select a stored credential to remove.

<Aside variant="caution">
  There is no `auth status`, `auth verify`, `auth refresh`, or `auth switch` command. Login is always the interactive `auth login` flow. You can also set provider keys via environment variables — see [AI Providers](/docs/configuration/providers).
</Aside>

## mcp

Manage Model Context Protocol servers. Five subcommands: `list`, `add`, `auth`, `logout`, `debug`.

<Aside variant="caution">
  Server config lives in `cyberstrike.json` (see [MCP](/docs/features/mcp)), and servers are managed interactively in the `/mcps` TUI dialog. There are no `mcp status`, `health`, `start`/`stop`/`restart`, `remove`, `config`, or `tools` commands.
</Aside>

### mcp list

```bash
cyberstrike mcp list   # alias: ls
```

### mcp add

```bash
cyberstrike mcp add
```

Fully interactive — prompts for local vs remote, command or URL, and name. Tests the connection before saving. No positional args or flags; to script server setup, write the entry into `cyberstrike.json` directly.

### mcp auth

```bash
cyberstrike mcp auth [name]        # authorize an OAuth server
cyberstrike mcp auth list          # list OAuth-authorized servers
```

Authorizes a remote server that uses OAuth. See [OAuth](/docs/features/mcp#oauth).

### mcp logout

```bash
cyberstrike mcp logout [name]
```

### mcp debug

```bash
cyberstrike mcp debug <name>
```

Inspects a server's connection — useful when a server fails to load or tools don't appear.

## upgrade

```bash
cyberstrike upgrade [version]
```

Update to the latest stable version or a specific target. Supported methods: `curl`, `npm`, `pnpm`, `bun`, `brew`, `choco`, `scoop`.

## Environment Variables

| Variable | Description |
|----------|-------------|
| `CYBERSTRIKE_PROVIDER` | Default AI provider |
| `CYBERSTRIKE_MODEL` | Default model |
| `CYBERSTRIKE_AGENT` | Default security agent |
| `CYBERSTRIKE_SERVER_PASSWORD` | Server authentication password |
| `CYBERSTRIKE_SERVER_USERNAME` | Server username (default: `cyberstrike`) |
| `CYBERSTRIKE_PERMISSION` | JSON permission override for non-interactive use |
| `CYBERSTRIKE_CONFIG` | Path to a custom config file |
| `CYBERSTRIKE_AUTO_SHARE` | Auto-share sessions |
| `CYBERSTRIKE_DISABLE_AUTOUPDATE` | Disable automatic update checks |
| `ANTHROPIC_API_KEY` | Anthropic API key |
| `OPENAI_API_KEY` | OpenAI API key |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Google AI (Gemini) API key |
| `OPENROUTER_API_KEY` | OpenRouter API key |

## Exit Codes

| Code | Meaning |
|------|---------|
| `0` | Success |
| `1` | Error — invalid/unknown arguments, or a fatal error |
| `130` | Interrupted (Ctrl+C) |
