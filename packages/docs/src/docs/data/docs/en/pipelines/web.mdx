The web pipeline runs a full OWASP WSTG assessment against a web application. You give it a URL, and it crawls the target, captures traffic, dispatches specialist agents per WSTG category, tests for vulnerabilities, chains findings together, and delivers verified results — all from a single prompt.

## Starting a Web Assessment

Launch the web pipeline from any CyberStrike interface:

- **TUI / Web UI / Desktop**: type `/hackbrowser` — a dialog opens where you enter the target URL and options
- **CLI**: run `cyberstrike hackbrowser https://app.example.com` directly from your terminal

This starts the crawler and kicks off the entire pipeline. Everything that follows is automatic.

## What Happens

### 1. Crawl & Discovery

[HackBrowser](/docs/features/hackbrowser) opens a browser and navigates through the target. You can let the AI drive autonomously, take over manually while the AI observes, or just let it passively monitor traffic.

While the browser navigates, a discovery engine runs in the background to find endpoints the browser might miss: sitemaps, JavaScript route bundles, HTML links, API schemas (OpenAPI, GraphQL). This is deterministic — it doesn't depend on the AI.

The scope engine keeps the crawler focused on your target. Third-party services (auth providers, analytics, CDNs) are blocked automatically. If your app makes cross-domain API calls (e.g., `api.example.com`), the scope expands to include them.

### 2. Traffic Analysis

Every HTTP request and response captured during the crawl flows through [Vortex](/docs/features/vortex), which runs independently of the AI:

- **Rules** match against traffic patterns — security headers, information leaks, interesting parameters, technology fingerprints
- **Canary tokens** are injected into requests to detect where input values get reflected in responses — and in what context (HTML body, script block, attribute)
- **Injection points** are identified automatically: parameters, headers, and body fields suitable for testing
- **Signals** generated by these matches get routed to the correct specialist agent

This layer catches things even if the AI doesn't notice them.

### 3. Specialist Testing

Based on the signals from Vortex, specialist agents are dispatched — each focused on one area of the OWASP Web Security Testing Guide:

| Specialist | What It Tests |
|-----------|--------------|
| Information Gathering | Technology fingerprinting, enumeration, information leaks |
| Configuration | Server misconfigurations, default credentials, file extensions |
| Identity Management | User enumeration, account provisioning flaws |
| Authentication | Login bypass, credential attacks, MFA weaknesses |
| Authorization | IDOR, privilege escalation, missing access controls |
| Session Management | Session fixation, cookie security, JWT vulnerabilities |
| Input Validation | XSS, SQL injection, SSTI, command injection, file upload, and 7 more injection types |
| Error Handling | Information disclosure through error messages and stack traces |
| Cryptography | Weak ciphers, TLS issues, cryptographic misconfigurations |
| Business Logic | Workflow bypass, race conditions, logic flaws |
| Client-side | DOM-based XSS, clickjacking, postMessage issues |
| API Testing | BOLA, mass assignment, rate limiting, API-specific flaws |
| LLM Security | Prompt injection, jailbreak, data exfiltration on AI-powered endpoints |

**109 checks** across 12 WSTG categories. A single request can trigger multiple specialists when it shows signals from different categories.

You don't need to invoke any of these agents directly — they're dispatched automatically based on what Vortex detects in the traffic.

### 4. Chain Detection & Escalation

After specialists finish testing, the **escalation hunter** looks across all findings to detect when separate vulnerabilities combine into something worse:

| Chain | What It Means |
|-------|-------------|
| Leaked credential + admin endpoint | Account Takeover |
| Internal URL in error message + SSRF endpoint | Internal Network Access |
| Open redirect + OAuth flow | Token Theft |
| Enumerable ID + PII endpoint | Mass Data Leak |
| Stored XSS + state-changing endpoint | CSRF Bypass |
| Template injection chain | Remote Code Execution |

Each chain gets a confidence score. Low-severity findings that chain into critical impact get escalated automatically.

## What the Agents Use

The specialists don't just ask the AI to "test for XSS." They carry purpose-built security tools designed for each testing area.

### Probe Tools

Each probe contains domain-specific attack logic — not generic payloads:

| Probe | What It Does |
|-------|-------------|
| **Session probe** | JWT algorithm attacks (alg:none bypass, RS256→HS256 key confusion, kid traversal), expired token replay, claim forgery, cookie security analysis |
| **Injection probe** | 13 specialized modes: XSS, SSTI, OS command, LFI, CRLF, time-blind, mass assignment, file upload, host header, verb tampering, HTTP parameter pollution, error signatures |
| **Crypto probe** | TLS handshake analysis, cipher enumeration, weak cryptographic pattern detection |
| **Error probe** | Request mutation to trigger errors, stack trace matching, framework/version fingerprinting |
| **Identity probe** | IDOR pattern detection, user enumeration via timing and response differentials |
| **Access probe** | Authorization bypass, privilege escalation, missing function-level access control |
| **Login probe** | Credential testing, brute force detection, lockout policy analysis |
| **Business test** | Workflow bypass, race conditions, logic flaw detection |
| **Recon test** | Technology fingerprinting, information leakage |

For example, the injection probe doesn't send the same XSS payload everywhere — it analyzes the reflection context and generates payloads that match the specific output location (HTML body, attribute, script block, JSON response).

### Traffic Query Tools

Every specialist can query the traffic corpus captured by Vortex:

- Search for high-signal findings the rule engine flagged
- Deep-inspect any transaction
- Query traffic with a DSL (filter by method, path, status, headers, body)
- View discovered API objects and functions
- Compare responses across user roles (for IDOR/BFLA detection)
- Find where a specific value appears across all traffic
- List endpoints that haven't been tested yet

The input validation specialist additionally gets tools to discover injection points from traffic and actively probe them through Vortex's send engine.

### Out-of-Band Detection

Agents can generate unique out-of-band tokens and inject them into payloads (SSRF, XXE, blind injection). If the token gets hit by the target server, the agent detects it — confirming vulnerabilities that produce no visible response.

## Reviewing Results

During the assessment, findings appear in real time. Use these commands to review them:

| Command | What It Shows |
|---------|--------------|
| `/vulnerabilities` | All findings with severity, evidence, and status |
| `/web` | Captured endpoints, roles, credentials, API objects |
| `/methodology` | WSTG coverage status — what's been tested, what's pending |
| `/report` | Generate a structured assessment report |

The `triage` agent independently verifies each finding by replaying HTTP evidence before marking it as confirmed.

## Authenticated Testing

When launching `/hackbrowser`, the dialog lets you define user roles for the target application — for example, an admin account and a regular user account. If you define multiple roles, HackBrowser opens a separate browser instance for each one simultaneously, crawling and capturing traffic under each identity in parallel.

This matters because authorization testing requires seeing how the same endpoint responds to different privilege levels. The specialist agents automatically compare responses across roles to detect IDOR, broken access control, and privilege escalation — they don't just test one account in isolation.

CyberStrike captures the full authentication state (cookies, tokens, headers) during each role's login and propagates it to all specialist agents throughout the assessment.

## What You Control

| Setting | How |
|---------|-----|
| Target scope | Describe the target — scope is auto-detected, or set explicitly in `cyberstrike.json` |
| AI provider | The AI reasoning runs on your configured provider — switch with `/models` |
| Manual takeover | Switch HackBrowser to human mode anytime to guide the crawler |
| Pause/resume | `/qpause` and `/qresume` control the testing queue |
