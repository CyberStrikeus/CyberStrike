Vortex는 Cyberstrike의 HTTP 트래픽 엔진입니다. [HackBrowser](/docs/features/hackbrowser), [Chrome 확장 기능](/docs/tools/chrome-extension), 또는 API를 통해 주입된 HTTP 요청을 가로채고, 저장하고, 분석합니다.

## Vortex가 하는 일

| 기능 | 설명 |
|------|------|
| **트래픽 캡처** | 전체 헤더와 본문이 포함된 모든 HTTP 요청/응답 쌍 저장 |
| **DSL 엔진** | 전용 표현식 언어로 트래픽 필터링 및 쿼리 |
| **규칙 매칭** | 캡처된 트래픽에 대해 규칙-데이터(탐지, 카나리, 변환) 적용 |
| **재생** | 테스트를 위해 캡처된 요청을 수정하여 재전송 |
| **신호 상관관계** | 체인된 취약점을 탐지하기 위해 요청 간 발견 사항 교차 참조 |

## DSL 쿼리

Vortex에는 HTTP 트래픽 필터링을 위한 표현식 엔진이 포함되어 있습니다. 메서드, 경로, 상태, 헤더, 본문 내용 등으로 쿼리합니다:

```
method == "POST" && path contains "/api/" && status >= 400
```

```
header["content-type"] contains "json" && body contains "token"
```

DSL은 불리언 논리, 문자열 매칭, 숫자 비교, 중첩 필드 접근을 지원합니다.

## 규칙

Vortex 규칙은 선언적 데이터이며 코드가 아닙니다. 세 가지 규칙 형태로 일반적인 패턴을 다룹니다:

| 형태 | 목적 | 예시 |
|------|------|------|
| **Detect** | 패턴에 매칭되는 트래픽 표시 | 응답 본문의 민감한 데이터 |
| **Canary** | 마커를 주입하고 반영 여부 감시 | SSRF, 오픈 리다이렉트, 헤더 인젝션 |
| **Transform** | 재생 전 요청 수정 | 인증 헤더 제거, 매개변수 값 교환 |

규칙은 내장 팩에서 로드하거나 프로젝트별로 정의할 수 있습니다.

## HackBrowser와의 통합

HackBrowser가 트래픽을 캡처하면 Vortex가 자동으로 처리합니다:

1. `POST /session/ingest`를 통해 요청이 도착
2. Vortex가 요청을 저장하고 활성 규칙을 적용
3. 매칭된 규칙이 신호를 생성
4. 신호가 proxy-agent의 분석 파이프라인에 전달

## 사용법

Vortex는 Cyberstrike 백엔드의 일부로 실행되며 별도 설정이 필요하지 않습니다. HackBrowser, Chrome 확장 기능, 또는 WSTG 파이프라인을 사용할 때마다 트래픽이 Vortex를 통해 흐릅니다.

TUI에서 `/web`을 사용하여 누적된 Vortex 데이터를 검사합니다: 캡처된 요청, 매칭된 규칙, 생성된 신호. 관련 명령:

| 명령 | 표시 내용 |
|------|-----------|
| `/web` | 캡처된 엔드포인트, 역할, 자격 증명 |
| `/vulnerabilities` | Vortex 신호 + WSTG 테스트의 발견 사항 |
| `/methodology` | 커버리지 및 방법론 상태 |

<Aside variant="tip">
  Vortex는 무료 티어에 포함되어 있습니다. AI 분석 레이어(proxy-agent 추론, 신호 상관관계)가 강력한 핵심이며, 이는 구성된 AI 제공자에서 실행됩니다.
</Aside>
