Cyberstrike는 Model Context Protocol(MCP)을 사용하여 외부 도구를 통합합니다. 로컬 또는 원격의 모든 MCP 호환 서버를 연결할 수 있어, 평가 중 AI 에이전트가 해당 도구에 접근할 수 있습니다.

## 내장 서버

Cyberstrike는 기본적으로 활성화된 세 개의 MCP 서버를 제공합니다:

| 서버 | 목적 |
|------|------|
| `github-security` | GitHub 리포지토리 보안 분석 |
| `cve` | CVE/NVD/EPSS/KEV 취약점 조회 |
| `osint` | 오픈 소스 인텔리전스 수집 |

사용자의 구성이 이 위에 병합됩니다.

## 서버 추가

MCP 서버는 구성의 평면 `mcp` 맵 아래에 이름으로 키를 지정하여 추가합니다:

```json title="cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["your-mcp-server"]
    }
  }
}
```

### 로컬 서버 (stdio)

로컬 서버는 자식 프로세스로 실행됩니다:

```json
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"]
    }
  }
}
```

### 원격 서버 (HTTP)

원격 서버는 StreamableHTTP 또는 SSE를 통해 연결됩니다:

```json
{
  "mcp": {
    "remote-tools": {
      "type": "remote",
      "url": "https://mcp.example.com/sse"
    }
  }
}
```

원격 서버는 보호된 엔드포인트를 위한 [OAuth 인증](/docs/mcp/oauth)을 지원합니다.

## 관리

| 명령 | 관리 대상 |
|------|-----------|
| `/mcps` | 로컬 및 원격 MCP 서버 (추가, 토글, 제거) |
| `/bolt` | Bolt 서버 전용 (추가, 페어링, 토글, 제거) |

두 대화상자 모두: **a**로 추가, **space**로 토글, **esc**로 닫기.

## 모델 호환성

<Aside variant="caution">
  서브프로세스 기반 모델은 MCP 도구에 접근할 수 없습니다. 완전한 MCP 통합을 위해 직접 API 모델(예: `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`)을 사용하세요.
</Aside>

## 구성 우선순위

MCP 항목은 표준 [구성 계층](/docs/configuration#configuration-hierarchy)을 따릅니다: 프로젝트 `.cyberstrike/`가 프로젝트 `cyberstrike.json`을 재정의하고, 이것이 글로벌 `~/.config/cyberstrike/`를 재정의하며, 이것이 내장 서버를 재정의합니다.
