비대화형 실행(`cyberstrike run`)에서는 권한 프롬프트에 응답할 사람이 없으므로 프롬프트를 표시할 모든 도구는 **자동 거부**됩니다. 파이프라인이 실제 작업을 수행하려면 필요한 도구를 사전 승인합니다.

<img src="/docs/images/diagrams/cicd-workflow.svg" alt="헤드리스 실행 권한 흐름: CYBERSTRIKE_PERMISSION 또는 구성으로 사전 승인된 도구는 실행됨; 프롬프트가 필요한 도구는 자동 거부됨; 결과는 JSON으로 stdout에 출력" className="my-6 mx-auto max-w-sm" />

## 도구 사전 승인

"자동 모드" 플래그는 없습니다. 두 가지 방법으로 권한을 부여합니다:

**1. `CYBERSTRIKE_PERMISSION` 환경 변수** — JSON 권한 맵 (구성 `permission` 필드와 동일한 형태):

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
cyberstrike run "scan this codebase for security issues" --format json > report.json
```

**2. 구성 `permission`** — 안전한 기본값을 커밋하고 위험한 부분을 거부합니다 ([패턴](/docs/permissions/patterns) 참조):

```json title="cyberstrike.json"
{
  "permission": {
    "read": "allow",
    "bash": { "*": "allow", "rm -rf *": "deny", "sudo *": "deny" },
    "edit": { "reports/**": "allow", ".env*": "deny" }
  }
}
```

출력은 stdout으로 전달됩니다; 기계 판독 가능한 결과를 위해 `--format json`을 사용합니다.

## CI/CD 통합

### GitHub Actions

```yaml title=".github/workflows/security-scan.yml"
name: Security Scan
on:
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @cyberstrike-io/cyberstrike@latest
      - name: Run Security Scan
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
        run: cyberstrike run "scan this codebase for security vulnerabilities" --format json > security-report.json
      - uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: security-report.json
```

### GitLab CI

```yaml title=".gitlab-ci.yml"
security-scan:
  image: node:20
  variables:
    CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'
  script:
    - npm install -g @cyberstrike-io/cyberstrike@latest
    - cyberstrike run "analyze code for vulnerabilities" --format json > report.json
  artifacts:
    paths:
      - report.json
```

## 배치 및 예약 실행

대상을 반복하거나 cron으로 구동합니다 — 동일한 `CYBERSTRIKE_PERMISSION` (또는 구성) 규칙이 적용됩니다:

```bash title="scan-targets.sh"
#!/bin/bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow"}'
while read -r target; do
  cyberstrike run "scan $target for open ports and services" --format json > "reports/${target}.json"
done < targets.txt
```

```bash
# 매일 02:00에 스캔
0 2 * * * CYBERSTRIKE_PERMISSION='{"bash":"allow"}' /usr/local/bin/cyberstrike run "daily security scan" >> /var/log/cyberstrike.log 2>&1
```

## 종료 코드 및 출력

`cyberstrike run`은 결과를 stdout에 출력하고(JSON을 위해 `--format json`) 성공 시 `0`, 오류 또는 중단 시 0이 아닌 코드를 반환합니다. 발견 사항을 위해 JSON을 파싱합니다:

```bash
cyberstrike run "scan target" --format json | jq '.'
```

## 보안 고려 사항

- **최소 권한** — 작업에 필요한 도구만 `allow`하세요; `rm -rf *`, `sudo *`, 시크릿 경로에 대한 명시적 `deny`를 유지하세요.
- **시크릿** — CI 시크릿 저장소에서 API 키를 주입하고, 절대 커밋하지 마세요.
- **격리** — 가능한 경우 제한된 네트워크가 있는 컨테이너에서 실행하세요.

<Aside variant="caution">
  자동화에서 `bash`를 사전 승인할 때 파괴적 명령에 대한 deny 규칙을 항상 유지하세요.
</Aside>
