Cyberstrike가 작동하려면 하나 이상의 AI 제공자와 인증이 필요합니다. 이 가이드에서는 지원되는 제공자의 자격 증명 설정을 다룹니다.

## 제공자 연결

인증하는 가장 간단한 방법입니다 — TUI에서 실행하세요:

```
/connect
```

대화형 메뉴에서 제공자를 선택합니다:

```
? Select provider
❯ cyberstrike (recommended)
  anthropic (Claude Max or API key)
  github-copilot
  openai (ChatGPT Plus/Pro or API key)
  google
  openrouter
  …
```

목록은 모델 카탈로그에서 동적으로 생성되며 우선순위에 따라 정렬되므로, 정확한 항목은 다를 수 있습니다. 고정 메뉴가 아닌 자동완성 프롬프트입니다.

## 제공자별 설정

### Anthropic

1. [console.anthropic.com](https://console.anthropic.com)에서 API 키를 발급받습니다
2. `/connect`를 실행하고, **Anthropic**을 선택하고, API 키를 입력합니다

### OpenAI

1. [platform.openai.com](https://platform.openai.com)에서 API 키를 발급받습니다
2. `/connect`를 실행하고, **OpenAI**를 선택하고, API 키를 입력합니다

### GitHub Copilot

1. 활성 GitHub Copilot 구독이 필요합니다
2. `/connect`를 실행하고, **Login with GitHub Copilot**을 선택합니다
3. 브라우저 OAuth 흐름을 통해 인증합니다 — API 키가 필요하지 않습니다

자세한 내용은 [GitHub Copilot](/docs/configuration/providers#github-copilot)을 참조하세요.

### OpenRouter

OpenRouter는 무료 티어로 여러 모델에 대한 접근을 제공합니다:

1. [openrouter.ai/keys](https://openrouter.ai/keys)에서 API 키를 발급받습니다
2. `/connect`를 실행하고, **OpenRouter**를 선택하고, API 키를 입력합니다

### Google Gemini

1. [ai.google.dev](https://ai.google.dev)에서 API 키를 발급받습니다
2. `/connect`를 실행하고, **Google**을 선택하고, API 키를 입력합니다

### Ollama (로컬)

Ollama는 API 키가 필요하지 않지만 로컬에서 실행 중이어야 합니다:

```bash
# Ollama 시작
ollama serve

# 모델 다운로드
ollama pull llama3.3
```

그런 다음 `/models`를 사용하여 Ollama 모델을 선택합니다.

## 환경 변수

CI/CD 또는 자동화를 위해 환경 변수로 자격 증명을 설정합니다:

```bash
# Anthropic
export ANTHROPIC_API_KEY="sk-ant-..."

# OpenAI
export OPENAI_API_KEY="sk-..."

# Google
export GOOGLE_GENERATIVE_AI_API_KEY="AI..."

# OpenRouter
export OPENROUTER_API_KEY="sk-or-..."

# Groq
export GROQ_API_KEY="gsk_..."
```

영구 적용을 위해 쉘 프로필에 추가합니다:

```bash
# ~/.bashrc or ~/.zshrc
export ANTHROPIC_API_KEY="sk-ant-..."
```

## 구성 파일

구성 파일에 자격 증명을 저장합니다:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "provider": {
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

<Aside variant="tip">
  구성 파일에서 환경 변수를 참조하려면 `{env:VAR_NAME}` 구문을 사용하세요.
</Aside>

## 자격 증명 관리

### 상태 확인

TUI에서 `/status`를 사용하여 연결된 제공자와 활성 자격 증명을 확인합니다.

### 모델 변경

`/models`를 사용하여 연결된 제공자의 모델 간에 전환합니다. 또는 구성에서 기본값을 설정합니다:

```json
{
  "model": "anthropic/claude-sonnet-4-20250514"
}
```

## 엔터프라이즈 인증

### AWS Bedrock

```bash
# AWS 자격 증명 구성
aws configure

# 또는 환경 변수를 통해
export AWS_ACCESS_KEY_ID="..."
export AWS_SECRET_ACCESS_KEY="..."
export AWS_REGION="us-east-1"
```

그런 다음 `/connect`를 실행하고 **Amazon Bedrock**을 선택합니다.

### Azure OpenAI

```bash
export AZURE_API_KEY="..."
export AZURE_RESOURCE_NAME="your-resource"
```

### Google Vertex AI

```bash
gcloud auth application-default login
```

## 보안 모범 사례

1. **API 키를 절대 버전 관리에 커밋하지 마세요**
2. 민감한 값에 **환경 변수를 사용하세요**
3. 보안을 위해 **정기적으로 키를 교체하세요**
4. 가능한 경우 **범위가 제한된 키를 사용하세요**
5. 제공자 대시보드에서 **사용량을 모니터링하세요**

## 문제 해결

### 잘못된 API 키

```
Error: Invalid API key
```

1. 키가 정확한지 확인합니다 (여분의 공백 없음)
2. 키가 만료되지 않았는지 확인합니다
3. 제공자에서 결제가 활성화되어 있는지 확인합니다

### 속도 제한

```
Error: Rate limit exceeded
```

1. 기다렸다가 재시도합니다
2. 제공자 대시보드에서 제한을 확인합니다
3. 플랜 업그레이드를 고려합니다

### 네트워크 문제

```
Error: Connection refused
```

1. 인터넷 연결을 확인합니다
2. 프록시/방화벽 차단이 없는지 확인합니다
3. 다른 네트워크를 시도합니다
