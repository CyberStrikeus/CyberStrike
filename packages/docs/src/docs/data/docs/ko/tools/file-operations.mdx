## Read 도구

줄 번호와 함께 파일 내용을 읽습니다.

### 기본 사용법

```
> Read the contents of src/auth/login.ts
```

### 부분 파일 읽기

```
> Read lines 50-100 of src/auth/login.ts
```

### 여러 파일

```
> Read both config.json and package.json
```

### 이미지 분석

Read 도구는 이미지를 분석할 수 있습니다:

```
> Read the screenshot at ./evidence/vuln-poc.png
```

### PDF 분석

```
> Read the security report at ./reports/pentest.pdf
```

## Write 도구

파일을 생성하거나 덮어씁니다.

### 새 파일 만들기

```
> Write a Python script to exploit the SQL injection to exploit.py
```

### 파일 덮어쓰기

```
> Replace the contents of config.json with the secure configuration
```

<Aside variant="caution">
  Write 도구는 경고 없이 기존 파일을 덮어씁니다. 부분 수정에는 Edit를 사용하세요.
</Aside>

## Edit 도구

기존 파일에 정밀한 편집을 수행합니다.

### 문자열 교체

```
> Edit src/auth/login.ts to replace "SELECT * FROM users WHERE id = " + userId with parameterized query
```

### 여러 줄 편집

```
> Edit the vulnerable function in auth.ts to add input validation
```

### 모두 바꾸기

```
> Replace all instances of "http://" with "https://" in config files
```

### 모범 사례

1. 컨텍스트를 이해하기 위해 먼저 파일 읽기
2. 변경 사항을 구체적으로 지정
3. 고유 일치를 위한 충분한 주변 컨텍스트 포함
4. 편집 후 변경 사항 확인

## Glob 도구

패턴 매칭으로 파일을 찾습니다.

### 기본 패턴

```
> Find all TypeScript files in the project
```

패턴: `**/*.ts`

### 여러 확장자

```
> Find all JavaScript and TypeScript files
```

패턴: `**/*.{js,ts}`

### 특정 디렉토리

```
> Find all config files in the src directory
```

패턴: `src/**/config.*`

### 일반적인 패턴

| 패턴 | 일치 대상 |
|------|-----------|
| `**/*.ts` | 모든 TypeScript 파일 |
| `src/**/*.test.ts` | src의 테스트 파일 |
| `**/package.json` | 모든 package.json 파일 |
| `**/.env*` | 환경 파일 |
| `**/secret*` | 이름에 "secret"이 포함된 파일 |

### 보안 스캔 패턴

```
> Find files that might contain credentials

패턴:
- **/*.env*
- **/secrets.*
- **/*credentials*
- **/*password*
- **/config.json
```

## Grep 도구

정규식으로 파일 내용을 검색합니다.

### 기본 검색

```
> Search for "password" in all files
```

### 정규식 검색

```
> Search for API key patterns in the codebase
```

패턴: `(api[_-]?key|apikey)\s*[:=]\s*['"][^'"]+['"]`

### 대소문자 무시

```
> Search for "SELECT" case insensitively
```

### 파일 타입 필터

```
> Search for "eval(" only in JavaScript files
```

### 컨텍스트 줄

```
> Search for "TODO" with 2 lines of context before and after
```

### 보안 중심 검색

| 용도 | 패턴 |
|------|------|
| SQL 인젝션 | `(SELECT|INSERT|UPDATE|DELETE).*\+.*\$` |
| 명령 인젝션 | `(exec|spawn|system)\s*\(` |
| 하드코딩된 시크릿 | `(password\|secret\|key)\s*=\s*['"][^'"]&#123;8,&#125;` |
| 안전하지 않은 역직렬화 | `(pickle|marshal|yaml\.load)` |
| XSS 싱크 | `(innerHTML|outerHTML|document\.write)` |

## 파일 분석 워크플로

### 1. 파일 발견

```
> Find all files that might handle user input
```

### 2. 패턴 검색

```
> Search these files for SQL query construction
```

### 3. 의심스러운 파일 읽기

```
> Read the files that matched the SQL pattern
```

### 4. 발견 사항 문서화

```
> Write a summary of the SQL injection findings to findings.md
```

## 권한 고려사항

파일 작업은 권한이 필요할 수 있습니다:

| 작업 | 권한 키 | 기본 동작 |
|------|---------|-----------|
| Read | `read` | 허용 (읽기 전용) |
| Glob | `glob` | 허용 (읽기 전용) |
| Grep | `grep` | 허용 (읽기 전용) |
| Write | `edit` | 권한 필요 |
| Edit | `edit` | 권한 필요 |

Write와 Edit 도구 모두 단일 `edit` 권한 키로 제어됩니다.

### 쓰기 자동 승인

자동화를 위해 `edit` 아래에 파일 경로 glob을 동작에 매핑합니다:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "permission": {
    "edit": {
      "reports/**": "allow",
      "findings/**": "allow"
    }
  }
}
```

와일드카드로 `*`와 `?`만 지원됩니다. 전체 모델은 [권한](/docs/configuration/permissions)을 참조하세요.


## 보안 테스트와의 통합

### 코드 리뷰

```
> Analyze all authentication-related files for security issues

1. 인증 파일 찾기: Glob **/*auth*.{ts,js}
2. 취약점 검색: Grep 패턴
3. 매칭 결과 읽기 및 분석
4. 발견 사항 문서화
```

### 구성 감사

```
> Review all configuration files for security misconfigurations

1. 구성 찾기: Glob **/{config,settings}*.{json,yaml,yml}
2. 각 파일 읽기
3. 민감한 데이터 노출 확인
4. 안전한 기본값 검증
```

### 시크릿 감지

```
> Scan the codebase for hardcoded secrets

1. 모든 소스 파일 Glob
2. 시크릿 패턴 Grep
3. 검증을 위해 매칭 결과 읽기
4. 발견 사항 보고
```

<Aside variant="tip">
  효율적인 코드베이스 스캔을 위해 Glob과 Grep을 결합하세요. 넓게 시작한 후 범위를 좁히세요.
</Aside>
