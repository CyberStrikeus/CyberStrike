권한 패턴은 도구의 인수(명령 문자열, 파일 경로)를 글로브에 매칭하고 동작에 매핑하여 세분화된 제어를 제공합니다.

## 형식

권한 항목은 단일 동작이거나 **글로브 → 동작** 맵입니다. `Tool(pattern)` 구문이나 allow/deny 배열은 없습니다 — 도구 키가 패턴을 그룹화합니다:

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "ls *": "allow",
      "git status": "allow",
      "rm -rf *": "deny"
    },
    "edit": {
      "reports/**": "allow",
      ".env*": "deny"
    }
  }
}
```

글로브는 도구의 인수에 매칭됩니다: `bash`의 경우 명령 문자열, `edit`/`read`의 경우 파일 경로입니다.

## 와일드카드

두 가지 와일드카드만 지원됩니다:

| 토큰 | 매칭 |
|------|------|
| `*` | `/`를 포함한 모든 문자 시퀀스 |
| `?` | 모든 단일 문자 |

<Aside variant="caution">
  `*`과 `?`가 **유일한** 와일드카드입니다. `[`, `]`, `{`, `}`, `(`, `)`, `|` 같은 문자는 **리터럴**로 매칭됩니다. `**`는 없습니다(`*`와 동일하게 동작), 부정(`!pattern`)은 지원되지 않습니다.
</Aside>

공백 + `*`로 끝나는 패턴은 인수가 없는 기본 명령도 매칭합니다 — `"ls *"`는 `ls`와 `ls -la` 모두에 매칭됩니다.

## 우선순위

여러 패턴이 매칭되면 **더 구체적인(긴) 패턴이 우선**합니다. 패턴은 가장 짧은 것부터 평가되며, 마지막 매칭이 적용됩니다 — 넓은 `"*": "ask"`는 더 긴 `"git status": "allow"`로 재정의할 수 있습니다:

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "npm *": "allow",
      "npm publish*": "deny"
    }
  }
}
```

여기서 `npm test`는 허용되지만 `npm publish`는 거부됩니다.

## 예시

### 도구 체인 허용, 위험한 부분 차단

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git push*": "ask",
      "rm -rf *": "deny"
    }
  }
}
```

### 편집을 디렉토리로 제한

```json
{
  "permission": {
    "edit": {
      "*": "deny",
      "src/**": "allow",
      "src/secrets/**": "deny"
    }
  }
}
```
