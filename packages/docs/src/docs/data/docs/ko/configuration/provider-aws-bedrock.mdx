AWS Bedrock을 사용하면 자체 AWS 계정을 통해 CyberStrike를 실행할 수 있습니다. 데이터가 인프라에 유지되고, IAM 기반 접근 제어를 받으며, 프라이빗 네트워크 접근을 위해 VPC 엔드포인트를 사용할 수 있습니다.

CyberStrike는 표준 AWS 자격 증명 제공자 체인(`@aws-sdk/credential-providers`)을 사용하므로, 이미 AWS CLI나 SDK를 사용하고 있다면 기존 자격 증명이 작동합니다.

## 사전 요구 사항

시작하기 전에 AWS 계정에서 Bedrock 모델에 대한 접근 권한이 있는지 확인합니다:

<Steps>
1. **AWS 콘솔**을 열고 **Amazon Bedrock**으로 이동합니다
2. 왼쪽 사이드바에서 **Model access**를 클릭합니다
3. 사용하려는 Claude 모델에 대한 접근을 요청합니다
4. 승인을 기다립니다 (대부분의 모델은 즉시 승인)
</Steps>

## 빠른 시작

가장 빠르게 시작하는 방법은 설정에 따라 다릅니다:

```bash
# 이미 AWS CLI가 구성되어 있는 경우
cyberstrike

# 이름이 지정된 프로필이 있는 경우
AWS_PROFILE=my-profile cyberstrike

# 접근 키가 있는 경우
AWS_ACCESS_KEY_ID=AKIA... AWS_SECRET_ACCESS_KEY=... cyberstrike

# IAM 역할이 연결된 EC2에서 — 바로 실행
cyberstrike
```

CyberStrike가 AWS 자격 증명을 자동 감지합니다. Bedrock 자격 증명이 발견되면 모델 선택기에 제공자가 자동으로 나타납니다.

## 인증 방법

CyberStrike는 AWS Bedrock으로 인증하는 9가지 방법을 지원합니다. 가장 간단한 것부터 가장 고급까지 나열합니다.

---

### 1. AWS 접근 키

가장 간단한 방법입니다. 접근 키와 시크릿을 환경 변수로 설정합니다:

```bash
export AWS_ACCESS_KEY_ID="AKIAIOSFODNN7EXAMPLE"
export AWS_SECRET_ACCESS_KEY="wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
export AWS_REGION="us-east-1"

cyberstrike
```

단일 세션을 위해 인라인으로 전달할 수도 있습니다:

```bash
AWS_ACCESS_KEY_ID=AKIA... AWS_SECRET_ACCESS_KEY=... AWS_REGION=us-east-1 cyberstrike
```

<Aside variant="caution">
  접근 키는 장기 자격 증명입니다. 프로덕션 사용에는 IAM 역할, SSO, 또는 임시 자격 증명을 선호하세요.
</Aside>

---

### 2. AWS 프로필

`~/.aws/credentials`와 `~/.aws/config`에 프로필이 구성되어 있으면 선택할 수 있습니다:

```bash
# 이름이 지정된 프로필 사용
AWS_PROFILE=my-profile cyberstrike
```

또는 프로젝트의 `cyberstrike.json`에서 프로필을 설정합니다:

```json title="cyberstrike.json"
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "profile": "my-profile",
        "region": "us-east-1"
      }
    }
  }
}
```

<Aside variant="tip">
  `cyberstrike.json`과 `AWS_PROFILE` 환경 변수가 모두 설정된 경우, 구성 파일이 우선합니다.
</Aside>

---

### 3. SSO / IAM Identity Center

조직에서 AWS IAM Identity Center(이전 AWS SSO)를 사용하는 경우, `~/.aws/config`에 SSO 프로필을 구성합니다:

```ini title="~/.aws/config"
[profile my-sso]
sso_session = my-org
sso_account_id = 123456789012
sso_role_name = BedrockAccess
region = us-east-1

[sso-session my-org]
sso_start_url = https://my-org.awsapps.com/start
sso_region = us-east-1
```

그런 다음 로그인하고 CyberStrike를 실행합니다:

```bash
aws sso login --profile my-sso
AWS_PROFILE=my-sso cyberstrike
```

---

### 4. STS AssumeRole (역할 체이닝)

다른 AWS 계정의 역할(또는 같은 계정의 더 높은 권한 역할)을 가정해야 하는 경우, `~/.aws/config`에 역할 체이닝을 구성합니다:

```ini title="~/.aws/config"
[profile base-account]
aws_access_key_id = AKIA...
aws_secret_access_key = ...

[profile bedrock-role]
role_arn = arn:aws:iam::987654321098:role/BedrockAccessRole
source_profile = base-account
region = us-east-1
```

그런 다음 역할 프로필을 사용합니다:

```bash
AWS_PROFILE=bedrock-role cyberstrike
```

AWS 자격 증명 제공자 체인에 의해 자동으로 처리됩니다 — CyberStrike에 특별한 구성은 필요하지 않습니다.

---

### 5. Web Identity Token (OIDC)

**EKS (Kubernetes)**, **GitHub Actions**, 또는 기타 OIDC 연합 환경에서 실행되는 워크로드의 경우, 토큰 파일 경로를 설정합니다:

```bash
export AWS_WEB_IDENTITY_TOKEN_FILE="/var/run/secrets/eks.amazonaws.com/serviceaccount/token"
export AWS_ROLE_ARN="arn:aws:iam::123456789012:role/my-eks-role"

cyberstrike
```

IRSA(IAM Roles for Service Accounts)가 있는 EKS에서는 이 환경 변수가 Kubernetes에 의해 자동으로 설정됩니다.

---

### 6. 컨테이너 자격 증명 (ECS / Fargate)

**ECS** 또는 **Fargate** 태스크 내에서 실행하는 경우, AWS가 메타데이터 엔드포인트를 통해 자동으로 자격 증명을 주입합니다. CyberStrike는 이 환경 변수를 감지합니다:

- `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`
- `AWS_CONTAINER_CREDENTIALS_FULL_URI`

구성이 필요하지 않습니다 — 태스크의 IAM 역할에 Bedrock 권한이 있는지 확인하고 실행합니다:

```bash
cyberstrike
```

---

### 7. EC2 인스턴스 메타데이터 (IMDS)

IAM 역할이 연결된 **EC2 인스턴스**에서는 인스턴스 메타데이터 서비스에서 자동으로 자격 증명을 가져옵니다. 환경 변수나 구성 파일이 필요하지 않습니다:

```bash
# IAM 역할이 있는 EC2 인스턴스에서 — 바로 실행
cyberstrike
```

인스턴스의 IAM 역할에 아래 [IAM 권한](#iam-permissions) 섹션에 설명된 Bedrock 권한이 포함되어 있는지 확인합니다.

<Aside variant="info">
  표준 자격 증명 체인이 실패하면 CyberStrike는 최후의 수단으로 자동으로 IMDS에 폴백합니다.
</Aside>

---

### 8. 베어러 토큰

베어러 토큰으로 인증할 수 있습니다. 환경 변수를 통해 설정합니다:

```bash
export AWS_BEARER_TOKEN_BEDROCK="your-bearer-token"
cyberstrike
```

또는 TUI를 통해 저장합니다 — `/connect`를 실행하고, **Amazon Bedrock**을 선택하고, 프롬프트가 표시되면 베어러 토큰을 붙여넣습니다. 매번 설정할 필요가 없도록 토큰이 저장됩니다.

<Aside variant="tip">
  베어러 토큰은 **최우선순위**를 가집니다 — 설정되면 전체 AWS 자격 증명 체인(프로필, 접근 키, IAM 역할 등)을 우회합니다.
</Aside>

---

### 9. 커스텀 자격 증명 프로세스

임시 AWS 자격 증명을 생성하는 커스텀 도구(회사 자격 증명 벤딩 머신 등)가 있는 경우, `~/.aws/config`에 구성합니다:

```ini title="~/.aws/config"
[profile custom-creds]
credential_process = /usr/local/bin/my-credential-tool --format json
region = us-east-1
```

프로그램은 다음 형식의 JSON을 반환해야 합니다:

```json
{
  "Version": 1,
  "AccessKeyId": "AKIA...",
  "SecretAccessKey": "...",
  "SessionToken": "...",
  "Expiration": "2025-12-31T23:59:59Z"
}
```

그런 다음 프로필을 사용합니다:

```bash
AWS_PROFILE=custom-creds cyberstrike
```

## 인증 우선순위

여러 자격 증명이 사용 가능한 경우, CyberStrike는 다음 우선순위를 사용합니다:

| 우선순위 | 방법 | 소스 |
|----------|------|------|
| 1 (최고) | 베어러 토큰 | `AWS_BEARER_TOKEN_BEDROCK` 환경 변수 또는 TUI의 `/connect` |
| 2 | AWS 자격 증명 체인 | `fromNodeProviderChain`이 표준 AWS SDK 순서로 해석: 환경 변수 → 프로필 → SSO → 웹 ID → ECS 컨테이너 → EC2 IMDS |

## IAM 권한

어떤 인증 방법을 사용하든 IAM ID에는 다음 권한이 필요합니다:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": "arn:aws:bedrock:*::foundation-model/anthropic.*"
    }
  ]
}
```

<Aside variant="tip">
  특정 모델에 대한 접근만 제한하려면 `anthropic.*`을 특정 모델 ARN으로 교체합니다.
</Aside>

## 리전 구성

CyberStrike는 다음 순서로 AWS 리전을 해석합니다:

| 우선순위 | 소스 | 예시 |
|----------|------|------|
| 1 (최고) | `cyberstrike.json` 구성 | `provider.amazon-bedrock.options.region` |
| 2 | 환경 변수 | `AWS_REGION=eu-west-1` |
| 3 (기본값) | 하드코딩된 폴백 | `us-east-1` |

구성 파일에서 리전을 설정합니다:

```json title="cyberstrike.json"
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "eu-west-1"
      }
    }
  }
}
```

또는 환경 변수를 통해:

```bash
export AWS_REGION="eu-west-1"
```

## 교차 리전 추론

CyberStrike는 교차 리전 추론 프로필 접두사를 자동으로 처리합니다. 구성된 리전에 따라 모델 ID에 올바른 접두사가 추가됩니다:

| 리전 | 접두사 | 예시 |
|------|--------|------|
| US 리전 (us-east-1, us-west-2, ...) | `us.` | `us.anthropic.claude-sonnet-4-20250514-v1:0` |
| EU 리전 (eu-west-1, eu-central-1, ...) | `eu.` | `eu.anthropic.claude-sonnet-4-20250514-v1:0` |
| 도쿄 (ap-northeast-1) | `jp.` | `jp.anthropic.claude-sonnet-4-20250514-v1:0` |
| 오스트레일리아 (ap-southeast-2, ap-southeast-4) | `au.` | `au.anthropic.claude-sonnet-4-20250514-v1:0` |
| 기타 APAC 리전 | `apac.` | `apac.anthropic.claude-sonnet-4-20250514-v1:0` |
| 글로벌 | `global.` | `global.anthropic.claude-sonnet-4-20250514-v1:0` |

자동으로 처리됩니다 — 접두사를 직접 추가할 필요가 없습니다. 모델 ID에 이미 접두사가 있으면(예: 모델 선택기에서) 이중 접두사가 추가되지 않습니다.

## VPC 엔드포인트

프라이빗 네트워크 접근(인터넷 트래픽 없음)을 위해 VPC 엔드포인트를 구성합니다:

```json title="cyberstrike.json"
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1",
        "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
      }
    }
  }
}
```

## 사용법

인증이 구성되면 TUI에서 `/models`를 통해 Bedrock 모델을 선택하거나 구성에서 기본값을 설정합니다:

```json title="cyberstrike.json"
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1"
      }
    }
  },
  "model": "amazon-bedrock/anthropic.claude-sonnet-4-20250514-v1:0"
}
```

세션 중 모델을 변경하려면 `/model` 슬래시 명령을 사용합니다.

## 문제 해결

### "Access Denied" 오류

- AWS Bedrock 콘솔에서 모델 접근이 활성화되어 있는지 확인
- IAM 정책에 `bedrock:InvokeModel`과 `bedrock:InvokeModelWithResponseStream`이 포함되어 있는지 확인
- 올바른 리전을 사용하고 있는지 확인

### "Model not found" 오류

- 모델 ID가 정확한지 확인
- 해당 리전에서 모델이 사용 가능한지 확인
- 다른 리전을 시도하거나 교차 리전 추론을 활성화

### "ThrottlingException" 오류

- AWS 콘솔을 통해 서비스 제한 증가를 요청
- 교차 리전 추론으로 리전 간 부하를 분산
- 일관된 처리량을 위해 AWS Bedrock 프로비저닝된 용량을 고려

### Bedrock 제공자가 나타나지 않음

CyberStrike는 유효한 자격 증명을 감지한 경우에만 Bedrock 제공자를 표시합니다. 나타나지 않는 경우:

1. AWS CLI로 자격 증명이 작동하는지 확인: `aws bedrock list-foundation-models --region us-east-1`
2. 하나 이상의 인증 방법이 구성되어 있는지 확인 (환경 변수, 프로필, 구성 등)
3. `cyberstrike.json`의 `disabled_providers`에 해당 제공자가 나열되어 있지 않은지 확인
