OAuth를 사용하면 Cyberstrike가 장기 자격 증명을 저장하지 않고 원격 MCP 서버와 인증할 수 있습니다. Cyberstrike는 서버의 OAuth 엔드포인트를 자동으로 검색합니다 — 서버가 요구하는 경우에만 클라이언트 세부 정보를 제공합니다.

## 구성 스키마

OAuth는 **원격** MCP 서버의 선택적 블록입니다. 전체 스키마는 세 개의 선택적 필드뿐입니다:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "clientId": "{env:OAUTH_CLIENT_ID}",
        "clientSecret": "{env:OAUTH_CLIENT_SECRET}",
        "scope": "read write"
      }
    }
  }
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `clientId` | string | 선택. 생략 시 **동적 클라이언트 등록(RFC 7591)**이 시도됩니다. |
| `clientSecret` | string | 선택. 인증 서버가 기밀 클라이언트를 요구하는 경우에만. |
| `scope` | string | 선택. 인증 중 요청할 범위. |

<Aside variant="caution">
  인증 및 토큰 URL은 여기서 구성되지 **않습니다** — Cyberstrike가 서버의 OAuth 메타데이터에서 검색합니다. `authorizationUrl`, `tokenUrl`, `pkce`, `deviceAuthorizationUrl`, `grantType`, `callbackPort`/`callbackPath` 같은 필드는 스키마에 **존재하지 않습니다** (`clientId`, `clientSecret`, `scope`만).
</Aside>

## 작동 방식

1. Cyberstrike가 원격 서버의 OAuth 필요 여부를 감지합니다 (메타데이터에서).
2. `clientId`가 설정되지 않은 경우 동적으로 클라이언트를 등록합니다 (RFC 7591).
3. 브라우저에서 인증 URL을 열고; 로그인하고 접근 권한을 부여합니다.
4. 내부적으로 처리되는 로컬 콜백에서 인증 코드를 토큰으로 교환합니다.
5. 토큰은 Cyberstrike에 의해 저장되며 만료 시 자동으로 갱신됩니다.

OAuth 자동 감지를 완전히 비활성화하려면 서버에 `"oauth": false`를 설정합니다.

## 서버 인증

CLI에서 인증을 트리거합니다:

```bash
cyberstrike mcp auth <name>       # 서버 인증
cyberstrike mcp auth list         # OAuth 인증된 서버 목록
cyberstrike mcp logout <name>     # 저장된 OAuth 자격 증명 제거
```

Cyberstrike는 세션에서 OAuth 보호 서버를 처음 사용할 때 자동으로 인증을 요청합니다. 토큰 갱신은 자동입니다 — 수동 갱신 명령은 없습니다.

## 예시: 범위가 지정된 서버

```json
{
  "mcp": {
    "example-mcp": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "scope": "openid profile email"
      }
    }
  }
}
```

`clientId`가 없으면 Cyberstrike가 동적으로 클라이언트를 등록한 다음 요청된 범위로 인증합니다.

## 보안 참고 사항

- `{env:VAR}`로 비밀을 참조하세요 — `clientSecret`을 절대 버전 관리에 커밋하지 마세요.
- 서버가 필요로 하는 최소 범위를 요청하세요.
- 더 이상 필요하지 않은 자격 증명은 `cyberstrike mcp logout <name>`으로 제거하세요.

## 문제 해결

- **인증 실패** — 서버 URL에 접근 가능한지, (서버가 기밀 클라이언트를 필요로 하는 경우) `clientId`/`clientSecret`이 정확한지 확인합니다.
- **반복적인 인증 프롬프트** — 저장된 토큰이 서버 측에서 취소되었을 수 있습니다; `cyberstrike mcp auth <name>`을 다시 실행합니다.
- **콜백 타임아웃** — 브라우저에서 로그인이 완료되었는지, 로컬 방화벽이 루프백 콜백을 차단하지 않는지 확인합니다.
- `cyberstrike mcp debug <name>`으로 서버 연결을 검사합니다.
