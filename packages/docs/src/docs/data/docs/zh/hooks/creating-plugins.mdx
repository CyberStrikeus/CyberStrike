## 编写插件

插件是 `(input: PluginInput) => Promise<Hooks>`。从 `@cyberstrike-io/plugin` 导入类型：

```typescript title=".cyberstrike/plugin/guard.ts"
import type { Plugin } from "@cyberstrike-io/plugin"

export const GuardPlugin: Plugin = async ({ project, directory, $ }) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash" && /rm\s+-rf/.test(output.args.command)) {
        throw new Error("blocked: rm -rf")
      }
    },
    "permission.ask": async (input, output) => {
      if (input.type === "read") output.status = "allow"
    },
  }
}
```

函数的 `input` 提供上下文——`client`、`project`、`directory`、`worktree`、`serverUrl` 和 `$`（Bun shell）。返回一个以钩子名称为键的对象；参阅[钩子参考](/docs/hooks/plugin-hooks)了解每个钩子及其签名。

## 注册插件

有两种方式加载插件。

### 1. 本地文件（无需发布）

将 `.ts`/`.js` 文件放入任何 `.cyberstrike/` 文件夹（项目或 `~/.cyberstrike/`）中的 `plugin/`（或 `plugins/`）目录：

```
.cyberstrike/
└── plugin/
    └── guard.ts
```

Cyberstrike 会自动发现它，并为您安装 `@cyberstrike-io/plugin`，以便本地插件可以导入类型。

### 2. `plugin` 配置数组

在 `plugin` 数组中引用 npm 包或路径（值在配置源之间取并集合并）：

```json title="cyberstrike.json"
{
  "plugin": [
    "@myorg/cyberstrike-guard",
    "./local/guard.ts"
  ]
}
```

## 测试与调试

使用调试日志运行 Cyberstrike 以查看插件加载和钩子触发：

```bash
cyberstrike --log-level DEBUG --print-logs
```

（或在配置中设置 `"logLevel": "DEBUG"`。）

由于钩子修改 `output`（或抛出异常），您可以通过使用模拟的 `input`/`output` 调用钩子并断言修改后的 `output` 来进行单元测试。

## 发布

像任何 npm 模块一样打包并发布您的插件，然后让用户将其添加到 `plugin` 数组：

```json title="package.json"
{
  "name": "@myorg/cyberstrike-guard",
  "type": "module",
  "main": "./index.ts",
  "peerDependencies": { "@cyberstrike-io/plugin": "*" }
}
```

```bash
npm publish --access public
```

<Aside variant="caution">
  插件对您的机器和 Cyberstrike 内部拥有完全访问权限。只安装您信任的插件，并保持钩子快速——它们与工具调用和 LLM 请求内联运行。
</Aside>
