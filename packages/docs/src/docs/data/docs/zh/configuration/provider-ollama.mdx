## 概述

Ollama 的优势：

- 完全的数据隐私
- 无 API 费用
- 离线运行
- 无速率限制
- 对模型的完全控制

## 安装

### macOS

```bash
brew install ollama
```

### Linux

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### Windows

从 [ollama.com/download](https://ollama.com/download) 下载

## 启动 Ollama

### 启动服务器

```bash
ollama serve
```

服务器默认运行在 `http://localhost:11434`。

### 验证安装

```bash
ollama --version
```

## 可用模型

### 推荐模型

| 模型 | 大小 | 最适合 |
|------|------|--------|
| llama3.3:70b | 40GB | 最佳质量，需要高端 GPU |
| llama3.3 | 4.7GB | 质量和速度的良好平衡 |
| codellama:34b | 19GB | 代码分析 |
| mistral | 4.1GB | 快速通用 |
| mixtral:8x7b | 26GB | 高质量、高效 |
| deepseek-coder:33b | 19GB | 代码安全审查 |
| qwen2.5:72b | 41GB | 优秀的推理能力 |

### 拉取模型

```bash
# 推荐用于安全测试
ollama pull llama3.3

# 用于代码审查
ollama pull codellama:34b

# 轻量级选项
ollama pull mistral
```

### 列出已安装的模型

```bash
ollama list
```

## 配置

Ollama **不是**内置提供商——您需要将它定义为自定义 OpenAI 兼容提供商。关键是顶级 `api` 字段（基础 URL，带 `/v1` 后缀）；在 `provider` 下列出并带有 `api` URL 是让 Cyberstrike 加载它的方式（不需要认证）。在 `models` 下定义您已拉取的模型：

### 基本设置

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "provider": {
    "ollama": {
      "name": "Ollama",
      "api": "http://localhost:11434/v1",
      "models": {
        "llama3.3": { "name": "Llama 3.3" }
      }
    }
  },
  "model": "ollama/llama3.3"
}
```

`npm` 默认为 `@ai-sdk/openai-compatible`，因此不需要设置。

### 自定义主机

对于远程 Ollama 服务器，更改 `api` URL：

```json
{
  "provider": {
    "ollama": {
      "name": "Ollama",
      "api": "http://192.168.1.100:11434/v1",
      "models": { "llama3.3": { "name": "Llama 3.3" } }
    }
  }
}
```

## 使用

在 TUI 中使用 `/models` 选择 Ollama 模型，或在配置中设置为默认值。

## 模型配置

### 上下文长度

增加上下文窗口：

```bash
ollama run llama3.3 --num-ctx 8192
```

或在 Modelfile 中：

```
FROM llama3.3
PARAMETER num_ctx 8192
```

### GPU 层

控制 GPU 使用：

```bash
OLLAMA_NUM_GPU=999 ollama serve  # 使用所有 GPU 层
OLLAMA_NUM_GPU=0 ollama serve    # 仅 CPU
```

### 内存管理

```bash
# 限制 VRAM 使用
OLLAMA_MAX_VRAM=8G ollama serve
```

## 自定义模型

### 创建 Modelfile

```dockerfile title="Modelfile"
FROM llama3.3

SYSTEM """
You are a security testing assistant specialized in:
- Web application vulnerabilities
- Code security review
- Network penetration testing

Always follow OWASP guidelines and report findings with:
- Vulnerability name
- Severity (Critical/High/Medium/Low)
- Evidence
- Remediation steps
"""

PARAMETER temperature 0.7
PARAMETER num_ctx 8192
```

### 构建自定义模型

```bash
ollama create security-assistant -f Modelfile
```

### 使用自定义模型

将自定义模型添加到配置中并通过 `/models` 选择：

```json
{
  "provider": {
    "ollama": {
      "models": {
        "security-assistant": { "name": "Security Assistant" }
      }
    }
  }
}
```

## 性能优化

### 硬件要求

| 模型大小 | 最低 RAM | 推荐 GPU |
|----------|----------|----------|
| 7B | 8GB | 8GB VRAM |
| 13B | 16GB | 12GB VRAM |
| 34B | 32GB | 24GB VRAM |
| 70B | 64GB | 48GB VRAM |

### 量化

使用量化模型降低内存需求：

```bash
ollama pull llama3.3:q4_0  # 4 位量化
ollama pull llama3.3:q8_0  # 8 位量化
```

### 并行请求

启用并发请求：

```bash
OLLAMA_NUM_PARALLEL=4 ollama serve
```

## 离线使用

### 预下载模型

```bash
ollama pull llama3.3
ollama pull codellama
```

### 气隙系统

1. 在有网络的系统上下载模型
2. 将 `~/.ollama/models/` 复制到气隙系统
3. 在没有互联网的情况下运行 Ollama

## Docker 部署

### 在容器中运行

```bash
docker run -d \
  --gpus all \
  -v ollama:/root/.ollama \
  -p 11434:11434 \
  --name ollama \
  ollama/ollama
```

### 在容器中拉取模型

```bash
docker exec -it ollama ollama pull llama3.3
```

## API 兼容性

Ollama 在 `http://localhost:11434/v1` 暴露 OpenAI 兼容 API——这正是上面的自定义提供商配置可以工作的原因（`npm` 默认为 `@ai-sdk/openai-compatible`）。将 `api` 字段指向该 URL，Cyberstrike 就可以通过 OpenAI 协议与 Ollama 通信。

## 故障排除

### 连接被拒绝

```
Error: Connection refused
```

确保 Ollama 正在运行：

```bash
ollama serve
```

### 内存不足

```
Error: CUDA out of memory
```

解决方案：
- 使用更小的模型
- 使用量化版本
- 减少上下文长度
- 设置 `OLLAMA_NUM_GPU=0` 使用 CPU

### 性能慢

- 启用 GPU 加速
- 使用量化模型
- 增加 `num_parallel`
- 检查热节流

<Aside variant="tip">
  为获得最佳效果，使用 llama3.3:70b 配合高端 GPU。对于资源有限的系统，mistral 以较低的要求提供良好的质量。
</Aside>
