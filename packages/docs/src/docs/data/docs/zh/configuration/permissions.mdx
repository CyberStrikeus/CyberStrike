## 权限模型

```mermaid
flowchart TD
    ToolCall([工具调用]) --> CheckConfig{检查\n配置}
    CheckConfig -->|allow| Execute[执行工具]
    CheckConfig -->|deny| Block[拦截工具]
    CheckConfig -->|ask| CheckApproved{之前\n已批准?}
    CheckApproved -->|是| Execute
    CheckApproved -->|否| AskUser[提示用户]
    AskUser -->|一次| Execute
    AskUser -->|始终| Remember[记住 + 执行]
    AskUser -->|拒绝| Block
    Remember --> Execute
```

---

## 权限模式

| 模式 | 行为 | 用途 |
|------|------|------|
| `ask` | 提示审批 | 敏感工具的默认值 |
| `allow` | 自动批准 | 可信工具、自动化 |
| `deny` | 拦截执行 | 受限操作 |

---

## 配置权限

### 全局配置

在 `~/.config/cyberstrike/cyberstrike.json` 中设置权限：

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "permission": {
    "read": "allow",
    "glob": "allow",
    "grep": "allow",
    "edit": "ask",
    "bash": "ask",
    "websearch": "ask"
  }
}
```

### 项目配置

在 `cyberstrike.json` 中按项目覆盖权限：

```json title="cyberstrike.json"
{
  "permission": {
    "bash": "allow",
    "edit": "allow",
    "external_directory": "deny"
  }
}
```

项目设置覆盖全局设置。

## 权限类型

### 文件操作

| 权限 | 工具 | 默认值 | 描述 |
|------|------|--------|------|
| `read` | Read | `ask` | 读取文件内容 |
| `edit` | Write, Edit | `ask` | 修改文件 |
| `glob` | Glob | `allow` | 按模式查找文件 |
| `grep` | Grep | `allow` | 搜索文件内容 |

### 命令执行

| 权限 | 工具 | 默认值 | 描述 |
|------|------|--------|------|
| `bash` | Bash | `ask` | 执行 Shell 命令 |
| `task` | Task | `ask` | 创建子代理 |

### Web 操作

| 权限 | 工具 | 默认值 | 描述 |
|------|------|--------|------|
| `websearch` | WebSearch | `ask` | 搜索网络 |
| `webfetch` | WebFetch | `ask` | 获取网页内容 |
| `codesearch` | CodeSearch | `ask` | 搜索代码仓库 |

### 特殊权限

| 权限 | 描述 |
|------|------|
| `external_directory` | 访问项目外的文件 |
| `lsp` | 语言服务器操作 |
| `doom_loop` | 检测并中断无限循环 |

## 基于模式的权限

使用模式授予细粒度权限。

### 目录模式

允许特定目录：

```json
{
  "permission": {
    "read": {
      "src/**": "allow",
      "test/**": "allow",
      "node_modules/**": "deny"
    },
    "edit": {
      "src/**": "allow",
      "*.config.js": "deny"
    }
  }
}
```

### 命令模式

允许特定命令：

```json
{
  "permission": {
    "bash": {
      "git *": "allow",
      "npm test": "allow",
      "npm run *": "allow",
      "rm *": "deny"
    }
  }
}
```

### 通配符匹配

| 模式 | 匹配 |
|------|------|
| `*` | 任何单个路径段 |
| `**` | 任何路径深度 |
| `*.ts` | 以 .ts 结尾的文件 |
| `src/**/*.ts` | src 中的 TypeScript 文件 |

## 交互式审批

当工具需要权限时，Cyberstrike 会提示审批。

### 响应选项

| 选项 | 行为 |
|------|------|
| **一次** | 批准此次特定调用 |
| **始终** | 批准会话中所有类似调用 |
| **拒绝** | 拦截此次调用 |

### 审批对话框

```
┌─────────────────────────────────────────┐
│  需要权限                                │
├─────────────────────────────────────────┤
│  工具: Bash                              │
│  命令: git push origin main              │
│                                          │
│  [一次]  [始终]  [拒绝]                  │
└─────────────────────────────────────────┘
```

### 快捷键

| 按键 | 操作 |
|------|------|
| `y` | 批准一次 |
| `a` | 始终批准 |
| `n` | 拒绝 |
| `Esc` | 拒绝 |

---

## 会话审批记忆

当您选择"始终"时，Cyberstrike 会在会话中记住审批模式。

### 记忆工作原理

1. 用户通过"始终"批准 `git push`
2. 模式 `git *` 存储在会话中
3. 后续的 `git pull`、`git commit` 等自动批准
4. 会话结束时记忆重置

### 查看已批准的模式

已批准的模式在会话重启前持续有效。

## 自动化模式

用于 CI/CD 和自动化，配置完全信任：

```json title="cyberstrike.json"
{
  "permission": "allow"
}
```

这将所有权限设置为允许，无需提示。

<Aside variant="caution">
  使用 `"permission": "allow"` 会绕过所有安全检查。仅在受控环境中使用。
</Aside>

## 权限钩子

使用插件钩子进行编程权限控制。

### permission.ask 钩子

```typescript
const hooks: Hooks = {
  "permission.ask": async (input, output) => {
    // 自动批准 src 中的读取操作
    if (input.type === "read" && input.path?.startsWith("src/")) {
      output.status = "allow"
      return
    }

    // 阻止访问密钥
    if (input.path?.includes("secret") || input.path?.includes(".env")) {
      output.status = "deny"
      return
    }

    // 默认：提示用户
    output.status = "ask"
  },
}
```

### 钩子输入

| 字段 | 类型 | 描述 |
|------|------|------|
| `id` | string | 权限请求 ID |
| `type` | string | 权限类型 |
| `pattern` | string | 匹配模式 |
| `sessionID` | string | 会话标识符 |
| `messageID` | string | 消息标识符 |
| `callID` | string | 工具调用 ID |
| `message` | string | 描述 |
| `metadata` | object | 附加上下文 |

### 钩子输出

| 字段 | 值 | 描述 |
|------|-----|------|
| `status` | `"ask"` | 提示用户 |
| `status` | `"allow"` | 自动批准 |
| `status` | `"deny"` | 拦截 |

## 权限优先级

权限按以下顺序评估：

1. **代理特定**权限（最高优先级）
2. **项目** `cyberstrike.json`
3. **全局** `~/.config/cyberstrike/cyberstrike.json`
4. **默认**内置值（最低优先级）

更具体的模式优先：

```json
{
  "permission": {
    "bash": "deny",
    "bash": {
      "git *": "allow"
    }
  }
}
```

在此情况下，`git push` 被允许但 `rm -rf` 被拒绝。

## 故障排除

### 权限始终提示

检查配置是否有效：

```bash
cyberstrike config validate
```

验证权限设置是否正确：

```bash
cat ~/.config/cyberstrike/cyberstrike.json | jq .permission
```

### 权限未生效

1. 检查项目与全局配置优先级
2. 验证模式语法与路径匹配
3. 重启 Cyberstrike 以重新加载配置

### 操作被拦截

如果工具意外被拦截：

1. 检查配置中的 `deny` 规则
2. 检查模式不匹配
3. 检查可能拦截的插件钩子
