权限模式通过将工具的参数（命令字符串、文件路径）与通配符匹配并映射到操作来提供细粒度控制。

## 格式

权限条目可以是单个操作，也可以是**通配符 → 操作**的映射。没有 `Tool(pattern)` 语法，没有 allow/deny 数组——工具键组织其模式：

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "ls *": "allow",
      "git status": "allow",
      "rm -rf *": "deny"
    },
    "edit": {
      "reports/**": "allow",
      ".env*": "deny"
    }
  }
}
```

通配符匹配工具的参数：对于 `bash` 是命令字符串，对于 `edit`/`read` 是文件路径。

## 通配符

仅支持两个通配符：

| 标记 | 匹配 |
|------|------|
| `*` | 任何字符序列（包括 `/`） |
| `?` | 任何单个字符 |

<Aside variant="caution">
  `*` 和 `?` 是**唯一的**通配符。`[`、`]`、`{`、`}`、`(`、`)` 和 `|` 等字符被**按字面匹配**。没有 `**`（行为与 `*` 相同），也不支持否定（`!pattern`）。
</Aside>

以空格 + `*` 结尾的模式也匹配没有参数的裸命令——因此 `"ls *"` 同时匹配 `ls` 和 `ls -la`。

## 优先级

当多个模式匹配时，**更具体（更长）的模式获胜**。模式从最短到最长评估，最后一个匹配生效——因此广泛的 `"*": "ask"` 可以被更长的 `"git status": "allow"` 覆盖：

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "npm *": "allow",
      "npm publish*": "deny"
    }
  }
}
```

这里 `npm test` 被允许，但 `npm publish` 被拒绝。

## 示例

### 允许工具链，拦截危险部分

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git push*": "ask",
      "rm -rf *": "deny"
    }
  }
}
```

### 将编辑限制在特定目录

```json
{
  "permission": {
    "edit": {
      "*": "deny",
      "src/**": "allow",
      "src/secrets/**": "deny"
    }
  }
}
```
