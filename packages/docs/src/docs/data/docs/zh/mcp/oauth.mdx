OAuth 允许 Cyberstrike 对远程 MCP 服务器进行认证，而无需存储长期凭据。Cyberstrike 会自动发现服务器的 OAuth 端点——您只需在服务器要求时提供客户端详情。

## 配置模式

OAuth 是**远程** MCP 服务器上的可选块。完整模式只有三个可选字段：

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "clientId": "{env:OAUTH_CLIENT_ID}",
        "clientSecret": "{env:OAUTH_CLIENT_SECRET}",
        "scope": "read write"
      }
    }
  }
}
```

| 字段 | 类型 | 描述 |
|------|------|------|
| `clientId` | string | 可选。如果省略，将尝试**动态客户端注册 (RFC 7591)**。 |
| `clientSecret` | string | 可选。仅当授权服务器需要机密客户端时使用。 |
| `scope` | string | 可选。授权期间请求的作用域。 |

<Aside variant="caution">
  授权和令牌 URL **不在**此处配置——Cyberstrike 从服务器的 OAuth 元数据中发现它们。`authorizationUrl`、`tokenUrl`、`pkce`、`deviceAuthorizationUrl`、`grantType` 和 `callbackPort`/`callbackPath` 等字段在模式中**不存在**（仅有 `clientId`、`clientSecret`、`scope`）。
</Aside>

## 工作原理

1. Cyberstrike 检测到远程服务器需要 OAuth（从其元数据中）。
2. 如果未设置 `clientId`，则动态注册客户端 (RFC 7591)。
3. 在浏览器中打开授权 URL；您登录并授予访问权限。
4. 授权码在内部处理的本地回调上交换为令牌。
5. Cyberstrike 存储令牌并在过期时自动刷新。

在服务器上设置 `"oauth": false` 可完全禁用 OAuth 自动检测。

## 授权服务器

从 CLI 触发授权：

```bash
cyberstrike mcp auth <name>       # 授权服务器
cyberstrike mcp auth list         # 列出已 OAuth 授权的服务器
cyberstrike mcp logout <name>     # 移除存储的 OAuth 凭据
```

Cyberstrike 在会话中首次使用受 OAuth 保护的服务器时也会自动提示授权。令牌刷新是自动的——没有手动刷新命令。

## 示例：带作用域的服务器

```json
{
  "mcp": {
    "example-mcp": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "scope": "openid profile email"
      }
    }
  }
}
```

没有 `clientId` 时，Cyberstrike 动态注册客户端，然后使用请求的作用域进行授权。

## 安全注意事项

- 使用 `{env:VAR}` 引用密钥——切勿将 `clientSecret` 提交到版本控制。
- 请求服务器需要的最小作用域。
- 不再需要时使用 `cyberstrike mcp logout <name>` 移除凭据。

## 故障排除

- **授权失败** — 确认服务器 URL 可达，如果服务器需要机密客户端，确认 `clientId`/`clientSecret` 正确。
- **重复授权提示** — 存储的令牌可能已在服务器端被撤销；再次运行 `cyberstrike mcp auth <name>`。
- **回调超时** — 确保浏览器完成了登录，且本地防火墙没有阻止回环回调。
- 使用 `cyberstrike mcp debug <name>` 检查服务器的连接。
