Cyberstrike 使用 Model Context Protocol (MCP) 来集成外部工具。**Bolt** 是我们的容器化工具服务器，内置了大量安全工具；您也可以连接任何本地或远程 MCP 服务器。

## 两种添加工具的方式

| 方式 | 传输协议 | 优点 | 缺点 |
|------|----------|------|------|
| **Bolt**（推荐） | StreamableHTTP | 预装工具、容器隔离、设置简单 | 需要 Docker、网络延迟 |
| **本地 / 远程 MCP** | stdio / StreamableHTTP | 任何 MCP 服务器；本地零延迟 | 需要自行安装和运行服务器 |

Cyberstrike 还默认启用了三个 MCP 服务器：`github-security`、`cve` 和 `osint`。您的自定义配置会合并到这些之上。

## Bolt

Bolt 在 Docker 容器（Ubuntu 24.04，端口 3001）中运行安全工具。它提供 **7 个原生插件**（`subfinder`、`nmap`、`nuclei`、`httpx`、`ffuf`、`run-command`、`wordlist`）以及**约 26 个聚合的 MCP 服务器**（`dnsx`、`amass`、`katana`、`sqlmap`、`wpscan`、`hydra`、`hashcat` 等）。每个工具都可直接调用——代理在一个回合内即可调用。

Bolt 配置在其**独立的顶级 `bolt` 键**下（不是 `mcp`），通过 Ed25519 配对进行认证：

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": { "url": "http://localhost:3001" }
  }
}
```

设置和配对详情请参阅 [Bolt](/docs/mcp/bolt) 页面。

## 本地 / 远程 MCP

其他 MCP 服务器放在扁平的 `mcp` 映射下，按名称键控：

```json title="cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["your-mcp-server"]
    }
  }
}
```

- [本地服务器](/docs/mcp/local-servers) — stdio 子进程
- [远程服务器](/docs/mcp/remote-servers) — StreamableHTTP/SSE，支持可选的 [OAuth](/docs/mcp/oauth)

## TUI 管理

两个独立的对话框：

- **`/bolt`** — 管理 Bolt 服务器（添加和配对、切换、移除）。
- **`/mcps`** — 管理本地/远程 MCP 服务器。

两个对话框中：**a** 添加，**space** 切换服务器，**esc** 关闭。

## 模型兼容性

<Aside variant="caution">
  基于子进程的模型无法访问 MCP 工具。请使用直连 API 模型以获得完整的 Bolt/MCP 集成。
</Aside>

直连 API 模型（例如 `anthropic/claude-sonnet-4-20250514`、`openai/gpt-4o`）在 Cyberstrike 内部运行，拥有完整的 MCP 访问权限。通过外部 CLI 进程运行的模型则没有。

## 配置优先级

MCP 和 Bolt 条目遵循标准的[配置层级](/docs/configuration#configuration-hierarchy)：项目的 `.cyberstrike/` 目录覆盖项目 `cyberstrike.json`，覆盖全局 `~/.config/cyberstrike/` 配置，覆盖内置服务器。
