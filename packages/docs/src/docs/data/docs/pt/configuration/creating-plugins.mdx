## Escreva um Plugin

Um plugin e `(input: PluginInput) => Promise<Hooks>`. Importe os tipos de `@cyberstrike-io/plugin`:

```typescript title=".cyberstrike/plugin/guard.ts"
import type { Plugin } from "@cyberstrike-io/plugin"

export const GuardPlugin: Plugin = async ({ project, directory, $ }) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash" && /rm\s+-rf/.test(output.args.command)) {
        throw new Error("blocked: rm -rf")
      }
    },
    "permission.ask": async (input, output) => {
      if (input.type === "read") output.status = "allow"
    },
  }
}
```

O `input` da funcao fornece contexto — `client`, `project`, `directory`, `worktree`, `serverUrl` e `$` (um shell Bun). Retorne um objeto cujas chaves sao nomes de hooks; consulte a [referencia de hooks](/docs/configuration/plugin-hooks) para cada hook e sua assinatura.

## Registre um Plugin

Existem duas formas de carregar um plugin.

### 1. Arquivo local (sem publicacao)

Coloque um arquivo `.ts`/`.js` em um diretorio `plugin/` (ou `plugins/`) dentro de qualquer pasta `.cyberstrike/` — projeto ou `~/.cyberstrike/`:

```
.cyberstrike/
└── plugin/
    └── guard.ts
```

O Cyberstrike o descobre automaticamente e instala `@cyberstrike-io/plugin` para que plugins locais possam importar os tipos.

### 2. O array `plugin` na configuracao

Referencie um pacote npm ou um caminho no array `plugin` (valores sao mesclados por uniao entre fontes de configuracao):

```json title="cyberstrike.json"
{
  "plugin": [
    "@myorg/cyberstrike-guard",
    "./local/guard.ts"
  ]
}
```

## Testar e Depurar

Execute o Cyberstrike com logs de depuracao para ver plugins carregando e hooks disparando:

```bash
cyberstrike --log-level DEBUG --print-logs
```

(Ou defina `"logLevel": "DEBUG"` na sua configuracao.)

Como hooks mutam `output` (ou lancam excecao), voce pode testa-los unitariamente chamando o hook com um `input`/`output` falso e verificando o `output` mutado.

## Publicar

Empacote seu plugin como qualquer modulo npm e publique-o, entao faca os usuarios adicionarem ao array `plugin`:

```json title="package.json"
{
  "name": "@myorg/cyberstrike-guard",
  "type": "module",
  "main": "./index.ts",
  "peerDependencies": { "@cyberstrike-io/plugin": "*" }
}
```

```bash
npm publish --access public
```

<Aside variant="caution">
  Plugins executam com acesso total a sua maquina e aos internos do Cyberstrike. Instale apenas plugins em que voce confia, e mantenha hooks rapidos — eles executam inline com chamadas de ferramentas e requisicoes LLM.
</Aside>
