## Categorias de Ferramentas

| Categoria | Ferramentas | Finalidade |
|-----------|-------------|------------|
| **Operacoes de Arquivo** | Read, Write, Edit, Glob, Grep | Leitura, escrita, edicao e busca de arquivos |
| **Execucao de Comandos** | Bash | Execucao de comandos shell |
| **Testes Web** | [Hacker Browser](/docs/tools/hacker-browser).
| **Memoria** | Memory Search, Memory Write, Memory Read, Memory Context | Armazenamento persistente entre sessoes |
| **Descoberta de Ferramentas** | ToolSearch, LoadTools, UnloadTools | Carregamento dinamico de ferramentas MCP |
| **Tarefas** | Task, TodoWrite | Delegacao e rastreamento de tarefas |
| **Web** | WebFetch, WebSearch, CodeSearch | Busca e pesquisa de conteudo web |

## Operacoes de Arquivo

### Read

Le o conteudo de arquivos com numeros de linha. Suporta arquivos de texto, imagens e PDFs.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `filePath` | string | Sim | Caminho do arquivo (absoluto ou relativo) |
| `offset` | number | Nao | Numero da linha inicial (indice a partir de 1) |
| `limit` | number | Nao | Numero de linhas para ler (padrao: 2000) |

#### Exemplo

```json
{
  "filePath": "/path/to/file.txt",
  "offset": 100,
  "limit": 500
}
```

#### Formato de Saida

```
00001| Primeira linha do conteudo
00002| Segunda linha do conteudo
00003| Terceira linha do conteudo

(End of file - total 3 lines)
```

#### Recursos

- Deteccao automatica de arquivo binario
- Suporte a imagens e PDF (retorna conteudo codificado em base64)
- Truncamento de linha em 2000 caracteres
- Maximo de 50KB por operacao de leitura
- Sugestoes inteligentes de arquivo em caso de erro de arquivo nao encontrado

---

### Write

Cria ou sobrescreve um arquivo com novo conteudo.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `filePath` | string | Sim | Caminho absoluto do arquivo |
| `content` | string | Sim | Conteudo a ser escrito |

#### Exemplo

```json
{
  "filePath": "/path/to/new-file.txt",
  "content": "Conteudo do arquivo aqui"
}
```

#### Recursos

- Cria diretorios pais se necessario
- Gera diff unificado para revisao
- Diagnosticos LSP apos escrita
- Rastreamento de tempo de arquivo para deteccao de conflitos

---

### Edit

Realiza operacoes de busca e substituicao em arquivos com correspondencia inteligente.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `filePath` | string | Sim | Caminho absoluto do arquivo |
| `oldString` | string | Sim | Texto a encontrar e substituir |
| `newString` | string | Sim | Texto de substituicao |
| `replaceAll` | boolean | Nao | Substituir todas as ocorrencias (padrao: false) |

#### Exemplo

```json
{
  "filePath": "/path/to/file.ts",
  "oldString": "function oldName(",
  "newString": "function newName(",
  "replaceAll": false
}
```

#### Correspondencia Inteligente

A ferramenta Edit usa multiplas estrategias de correspondencia:

1. **Substituicao Simples**: Correspondencia exata de string
2. **Linha Aparada**: Ignora espacos no inicio/fim por linha
3. **Ancoragem de Bloco**: Corresponde primeira e ultima linhas, meio flexivel
4. **Espaco Normalizado**: Colapsa multiplos espacos
5. **Indentacao Flexivel**: Ignora diferencas de indentacao
6. **Escape Normalizado**: Lida com sequencias de escape
7. **Sensivel ao Contexto**: Usa contexto ao redor para correspondencia

#### Recursos

- Geracao de diff unificado
- Diagnosticos LSP apos edicao
- Deteccao de multiplas ocorrencias
- Prevencao de conflitos via rastreamento de tempo de arquivo

---

### Glob

Encontra arquivos correspondentes a um padrao glob.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `pattern` | string | Sim | Padrao glob (ex: `**/*.ts`) |
| `path` | string | Nao | Diretorio de busca (padrao: diretorio atual) |

#### Exemplo

```json
{
  "pattern": "**/*.{ts,tsx}",
  "path": "/path/to/project"
}
```

#### Saida

Retorna caminhos de arquivo ordenados por data de modificacao (mais recentes primeiro), limitado a 100 resultados.

#### Exemplos de Padroes

| Padrao | Corresponde |
|--------|-------------|
| `*.ts` | Arquivos TypeScript no diretorio atual |
| `**/*.ts` | Arquivos TypeScript recursivamente |
| `src/**/*.{ts,tsx}` | Arquivos TS/TSX no diretorio src |
| `!**/node_modules/**` | Excluir node_modules |

---

### Grep

Pesquisa conteudo de arquivos usando padroes regex. Construido sobre ripgrep.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `pattern` | string | Sim | Padrao regex para pesquisa |
| `path` | string | Nao | Diretorio de busca (padrao: diretorio atual) |
| `include` | string | Nao | Filtro de padrao de arquivo (ex: `*.js`) |

#### Exemplo

```json
{
  "pattern": "password|secret|api_key",
  "path": "/path/to/project",
  "include": "*.{js,ts,py}"
}
```

#### Formato de Saida

```
Found 5 matches

/path/to/file.ts:
  Line 42: const apiKey = process.env.API_KEY
  Line 85: // TODO: remove hardcoded secret

/path/to/config.js:
  Line 12: password: "changeme"
```

#### Recursos

- Suporte a regex (sintaxe ripgrep)
- Busca em arquivos ocultos
- Segue links simbolicos
- Resultados ordenados por data de modificacao
- Maximo de 100 resultados

## Execucao de Comandos

### Bash

Executa comandos shell com timeout e captura de saida.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `command` | string | Sim | Comando a executar |
| `timeout` | number | Nao | Timeout em milissegundos (padrao: 120000) |
| `workdir` | string | Nao | Diretorio de trabalho |
| `description` | string | Sim | Descricao breve do proposito do comando |

#### Exemplo

```json
{
  "command": "nmap -sV -sC target.com",
  "timeout": 300000,
  "workdir": "/path/to/project",
  "description": "Varrer alvo por portas abertas e servicos"
}
```

#### Recursos

- Deteccao de shell (bash/zsh/sh)
- Encerramento de arvore de processos em timeout
- Integracao com sistema de permissoes
- Streaming de saida em tempo real
- Controle de acesso a diretorios externos

#### Consideracoes de Seguranca

Comandos sao analisados com tree-sitter para detectar:
- Acesso a diretorios fora do projeto
- Padroes de comandos perigosos
- Modificacoes no sistema de arquivos

## Sistema de Memoria

O Cyberstrike inclui um sistema de memoria persistente para armazenar contexto entre sessoes.

### Memory Write

Armazena informacao na memoria persistente.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `content` | string | Sim | Conteudo a armazenar |
| `type` | string | Nao | `long_term` para MEMORY.md, `daily` para notas datadas |
| `title` | string | Nao | Cabecalho opcional para a entrada |

#### Exemplo

```json
{
  "content": "Alvo usa PostgreSQL 14.2 na porta 5432",
  "type": "long_term",
  "title": "Configuracao do Banco de Dados"
}
```

#### Tipos de Memoria

| Tipo | Armazenamento | Finalidade |
|------|---------------|------------|
| `long_term` | `.cyberstrike/MEMORY.md` | Decisoes, preferencias, fatos importantes |
| `daily` | `.cyberstrike/memory/YYYY-MM-DD.md` | Notas de sessao, contexto temporario |

---

### Memory Search

Pesquisa na memoria armazenada.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `query` | string | Sim | Palavras-chave ou frases de pesquisa |

#### Exemplo

```json
{
  "query": "credenciais do banco de dados"
}
```

---

### Memory Read

Le arquivos de memoria especificos.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `file` | string | Sim | Identificador do arquivo |

#### Identificadores de Arquivo

| Identificador | Descricao |
|---------------|-----------|
| `long_term` | Memoria de longo prazo (MEMORY.md) |
| `today` | Notas diarias de hoje |
| `yesterday` | Notas de ontem |
| `YYYY-MM-DD` | Notas de uma data especifica |
| `list` | Listar todos os arquivos de memoria |

---

### Memory Context

Recupera o contexto completo de memoria para a sessao.

#### Parametros

Nenhum obrigatorio.

#### Exemplo

```json
{}
```

Retorna a memoria de longo prazo combinada com notas diarias recentes.

## Carregamento Dinamico de Ferramentas

<img src="/docs/images/diagrams/tool-interaction-flow.svg" alt="Como uma ferramenta se torna disponivel: ferramentas integradas sao chamadas diretamente; ferramentas MCP sao encontradas com tool_search, carregadas com load_tools, entao chamadas, e liberadas com unload_tools" className="my-6 mx-auto max-w-sm" />

O Cyberstrike suporta carregamento dinamico de ferramentas para servidores MCP (Model Context Protocol). Isso permite acesso a centenas de ferramentas sem sobrecarregar a janela de contexto.

### Tool Search

Pesquisa ferramentas MCP disponiveis por capacidade.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `query` | string | Sim | Descricao da capacidade |
| `limit` | number | Nao | Maximo de resultados (padrao: 5) |

#### Exemplo

```json
{
  "query": "teste de injecao sql",
  "limit": 10
}
```

#### Saida

```
Found 3 tools:

1. sqlmap_scan
   Scanner de injecao SQL usando sqlmap
   Estimated tokens: ~500

2. nuclei_sqli
   Templates Nuclei para injecao SQL
   Estimated tokens: ~300

3. manual_sqli
   Payloads manuais de injecao SQL
   Estimated tokens: ~200
```

---

### Load Tools

Carrega ferramentas no contexto para uso.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `tool_ids` | string[] | Sim | IDs de ferramentas dos resultados de busca |

#### Exemplo

```json
{
  "tool_ids": ["sqlmap_scan", "nuclei_sqli"]
}
```

---

### Unload Tools

Remove ferramentas do contexto para liberar orcamento.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `tool_ids` | string[] | Sim | IDs de ferramentas para descarregar |

---

### List Loaded Tools

Mostra ferramentas carregadas atualmente e uso de tokens.

#### Parametros

Nenhum obrigatorio.

## Gerenciamento de Tarefas

### Task

Delega trabalho a um subagente. E assim que o agente principal despacha subagentes especializados (veja [Agentes](/docs/agents)).

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `description` | string | Sim | Descricao curta (3-5 palavras) da tarefa |
| `prompt` | string | Sim | A tarefa para o subagente realizar |
| `subagent_type` | string | Sim | Qual subagente despachar (ex: `web-application`, `general`) |

---

### TodoWrite

Escreve itens de tarefa em uma lista de afazeres.

#### Parametros

| Parametro | Tipo | Obrigatorio | Descricao |
|-----------|------|-------------|-----------|
| `tasks` | array | Sim | Array de objetos de tarefa |

#### Objeto de Tarefa

```json
{
  "id": "1",
  "content": "Varrer portas abertas",
  "status": "pending",
  "priority": "high"
}
```

## Permissoes de Ferramentas

Cada ferramenta requer permissoes especificas que podem ser configuradas:

| Permissao | Ferramentas | Padrao |
|-----------|-------------|--------|
| `read` | Read | ask |
| `edit` | Write, Edit | ask |
| `glob` | Glob | allow |
| `grep` | Grep | allow |
| `bash` | Bash | ask |
| `websearch` | WebSearch | ask |
| `webfetch` | WebFetch | ask |
| `codesearch` | CodeSearch | ask |
| `task` | Task | ask |
| `external_directory` | Acesso fora do projeto | ask |

### Configuracao

```json
{
  "permission": {
    "bash": "ask",
    "edit": "allow",
    "read": "allow",
    "glob": "allow",
    "grep": "allow"
  }
}
```

### Acoes de Permissao

| Acao | Descricao |
|------|-----------|
| `ask` | Solicitar aprovacao do usuario |
| `allow` | Aprovar automaticamente sem perguntar |
| `deny` | Bloquear uso da ferramenta |

Veja [Permissoes](/docs/permissions) para o modelo completo e padroes glob.

## Criando Ferramentas Personalizadas

Adicione ferramentas personalizadas criando arquivos em `.cyberstrike/tools/`:

```typescript title=".cyberstrike/tools/custom-scanner.ts"
import { z } from "zod"

export default {
  description: "Scanner de vulnerabilidades personalizado",
  args: {
    target: z.string().describe("URL alvo para varrer"),
    depth: z.number().default(3).describe("Profundidade da varredura"),
  },
  async execute(args, ctx): Promise<string> {
    const { target, depth } = args
    // Logica de varredura personalizada
    return `Varreu ${target} ate profundidade ${depth}`
  },
}
```

Arquivos em um diretorio `tool/` ou `tools/` dentro de qualquer pasta `.cyberstrike/` sao carregados automaticamente.

### Schema de Definicao de Ferramenta

| Campo | Tipo | Descricao |
|-------|------|-----------|
| `description` | string | Descricao da ferramenta mostrada ao modelo |
| `args` | object | Mapa de nome do parametro para schema Zod |
| `execute` | function | `async (args, ctx) => string` |

## Ferramentas de Servidor MCP

O Cyberstrike pode carregar ferramentas de servidores MCP. A abordagem recomendada e o [Bolt](/docs/mcp/bolt), que fornece ferramentas de seguranca por meio de um container Docker com sistema de plugins:

```json title="cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true
    }
  }
}
```

Ferramentas MCP ficam disponiveis como chamadas de ferramenta diretas -- cada plugin e chamado diretamente pelo nome (ex: `nmap`, `nuclei`, `ffuf`).

<Aside variant="tip">
  Veja [Bolt](/docs/mcp/bolt) para a configuracao recomendada de ferramentas de seguranca -- 7 plugins mais ~26 servidores MCP agregados, todos disponiveis como chamadas de ferramenta diretas.
</Aside>
