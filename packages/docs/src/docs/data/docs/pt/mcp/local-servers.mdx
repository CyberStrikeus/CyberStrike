Servidores MCP locais executam na sua maquina como processos filhos, comunicando-se via stdio. Esta e uma alternativa ao [Bolt](/docs/mcp/bolt) para usuarios que preferem executar ferramentas diretamente no seu sistema.

<Aside variant="tip">
  **Prefira o Bolt para ferramentas de seguranca.** MCP local requer instalar cada ferramenta voce mesmo. Consulte [Bolt](/docs/mcp/bolt) para a abordagem recomendada com plugins de ferramentas de seguranca pre-instalados.
</Aside>

## Quando Usar MCP Local

- **Ambientes offline** — sem acesso a rede necessario
- **Baixa latencia** — comunicacao direta via stdio entre processos
- **Ferramentas personalizadas** — seus proprios servidores MCP
- **Privacidade** — dados nunca saem da sua maquina

O Cyberstrike tambem vem com alguns servidores MCP locais habilitados por padrao: `github-security`, `cve` e `osint`. Sua configuracao e mesclada sobre estes.

## Schema de Configuracao

Um servidor local e uma entrada no mapa plano `mcp`, indexado por nome do servidor:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["npx", "-y", "my-mcp-server"],
      "environment": { "API_KEY": "{env:MY_API_KEY}" },
      "enabled": true,
      "timeout": 5000
    }
  }
}
```

| Campo | Tipo | Descricao |
|-------|------|-----------|
| `type` | `"local"` | Obrigatorio. Seleciona um servidor de processo filho stdio. |
| `command` | `string[]` | Obrigatorio. O comando **e seus argumentos** como um unico array. |
| `environment` | object | Opcional. Variaveis de ambiente extras para o processo. |
| `enabled` | boolean | Opcional. Iniciar o servidor no lancamento (padrao: true). |
| `timeout` | number | Opcional. Timeout de requisicao em ms (padrao: 5000). |

<Aside variant="caution">
  O objeto `mcp` e um **mapa plano** indexado por nome do servidor — nao ha wrapper `servers`. `command` e um unico array (comando + args juntos); nao ha campos separados `args`, `cwd`, `autoStart` ou `restart`. Chaves desconhecidas sao rejeitadas.
</Aside>

## Adicionando via TUI

A maneira mais facil de adicionar um servidor local e pela TUI com o comando `/mcps`.

Digite `/mcps` para abrir o gerenciador MCP. Ele lista servidores configurados com seu status (`✓` habilitado / `○` desabilitado). Pressione `espaco` para alternar um servidor, `a` para adicionar um, `Enter` para agir na selecao.

Para adicionar um servidor local: pressione `a` → escolha **Local** → insira o **comando** (ex: `npx my-mcp-server`) → opcionalmente adicione **variaveis de ambiente** (`KEY=VALUE, KEY2=VALUE2`) → confirme o **nome** derivado automaticamente. O Cyberstrike testa a conexao antes de salvar; se falhar, o servidor nao e adicionado.

A TUI escreve exatamente o schema mostrado acima.

## Exemplos

### Servidor Node.js

```json
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/path/to/allow"]
    }
  }
}
```

### Servidor Python

```json
{
  "mcp": {
    "python-tools": {
      "type": "local",
      "command": ["python", "-m", "mcp_server"]
    }
  }
}
```

### Binario ou Docker

Como `command` e o argv completo, voce pode executar um binario diretamente ou envolver em Docker — sem campos especiais necessarios:

```json
{
  "mcp": {
    "docker-tools": {
      "type": "local",
      "command": ["docker", "run", "-i", "--rm", "--network=none", "mcp-tools:latest"]
    }
  }
}
```

## Variaveis de Ambiente

Passe variaveis para o processo do servidor com `environment`. Use `{env:VAR}` para referenciar uma variavel do seu shell em vez de codificar segredos:

```json
{
  "mcp": {
    "api-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "environment": {
        "API_KEY": "{env:MY_API_KEY}",
        "DEBUG": "mcp:*"
      }
    }
  }
}
```

## Habilitando e Desabilitando

Defina `enabled: false` para manter um servidor configurado mas inativo (ou alterne no dialogo `/mcps`):

```json
{
  "mcp": {
    "heavy-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "enabled": false
    }
  }
}
```

## Servidores de Inicializacao Lenta

Aumente o `timeout` (milissegundos) para servidores que demoram mais que os 5 segundos padrao para responder:

```json
{
  "mcp": {
    "slow-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "timeout": 30000
    }
  }
}
```

## Solucao de Problemas

- **Servidor nao inicia** — verifique se o primeiro elemento de `command` existe e e executavel, e que suas dependencias estao instaladas. Inspecione a conexao com `cyberstrike mcp debug <name>`.
- **Timeout de conexao** — aumente o `timeout`, ou verifique se o servidor responde a `tools/list` rapidamente.
- **Configuracao rejeitada** — o schema `mcp` e estrito; certifique-se de usar o mapa plano com `type` + `command` (array) e sem chaves desconhecidas.
