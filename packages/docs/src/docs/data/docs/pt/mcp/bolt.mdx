O Bolt e um servidor MCP containerizado que fornece ferramentas de seguranca. Ele executa em um container Docker (Ubuntu 24.04) e expoe cada ferramenta diretamente — sem meta-ferramentas, sem carregamento dinamico, apenas chame a ferramenta que voce precisa.

## Por Que o Bolt?

O Bolt resolve o problema de executar ferramentas de seguranca que precisam de um ambiente Linux. Em vez de instalar ferramentas localmente, o Bolt as executa em um container isolado.

| Recurso | Sem o Bolt | Com o Bolt |
|---------|------------|------------|
| Instalacao de ferramentas | Manual para cada ferramenta | Pre-instalado |
| Suporte a plataformas | Apenas Linux para a maioria das ferramentas | Qualquer plataforma com Docker |
| Isolamento | Ferramentas executam no seu sistema | Sandboxed no container |
| Atualizacoes | Manual | `docker pull` |

## O Que Ha Dentro

O Bolt (`bolt.config.json`, porta `3001`) expoe ferramentas de duas formas:

- **7 plugins nativos** — `subfinder`, `nmap`, `nuclei`, `httpx`, `ffuf`, `run-command`, `wordlist`
- **~26 servidores MCP stdio agregados** — ex: `dnsx`, `amass`, `katana`, `sqlmap`, `wpscan`, `gobuster`, `masscan`, `hydra`, `hashcat`, `john`, `impacket` e mais

Cada uma e uma ferramenta diretamente invocavel — o agente a chama em um unico turno, sem etapa de busca/carregamento.

## Inicio Rapido

### 1. Inicie o container Bolt

```bash
docker run -d \
  --name bolt \
  --restart unless-stopped \
  -p 3001:3001 \
  -v bolt-data:/data \
  -e MCP_ADMIN_TOKEN=$(openssl rand -hex 32) \
  --cap-add NET_RAW \
  --cap-add NET_ADMIN \
  ghcr.io/cyberstrikeus/bolt:latest

# Veja o token de administrador (usado uma vez, para parear)
docker logs bolt | grep -i token
```

### 2. Pareie com o Cyberstrike

Abra o dialogo `/bolt` na TUI, pressione **a** para adicionar, insira a URL `http://localhost:3001` e forneca o token de administrador. O Cyberstrike pareia com o servidor (veja [Autenticacao](#autenticacao)) e armazena as credenciais — o token em si **nao** e escrito na sua configuracao.

### 3. Use as ferramentas

```
> Run nmap against 192.168.1.1 with service detection
> Use subfinder to enumerate subdomains of example.com
```

## Configuracao

Servidores Bolt sao configurados sob sua **propria chave de nivel superior `bolt`** — nao sob `mcp`. Cada entrada precisa apenas de uma `url` (o Cyberstrike adiciona o caminho `/mcp` automaticamente):

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true,
      "timeout": 30000
    }
  }
}
```

| Campo | Tipo | Descricao |
|-------|------|-----------|
| `url` | string | Obrigatorio. URL base do servidor Bolt (ex: `http://localhost:3001`). |
| `enabled` | boolean | Opcional. Conectar no lancamento (padrao: true). |
| `timeout` | number | Opcional. Timeout de requisicao em ms (padrao: 30000). |

<Aside variant="caution">
  O Bolt **nao** e uma entrada `mcp`. Nao ha `type: "remote"`, nenhuma flag `bolt: true` e nenhum header `Authorization` na configuracao — a autenticacao e feita por pareamento Ed25519, e o token de administrador existe apenas na etapa de pareamento.
</Aside>

## Autenticacao

O Bolt usa **assinatura de requisicao Ed25519**, iniciada por um pareamento unico com o token de administrador:

1. `POST /pair` com o token de administrador → um codigo de pareamento
2. O Cyberstrike gera um par de chaves Ed25519
3. `POST /pair/exchange` com o codigo + chave publica do cliente → chave publica do servidor + ID do cliente
4. A partir de entao, cada requisicao e **assinada** com a chave privada do cliente

O token de administrador e usado apenas durante o passo 1 — nao e uma credencial bearer persistente e nunca e armazenado em `cyberstrike.json`.

## Gerenciamento na TUI

Dois dialogos separados:

- **`/bolt`** — gerencia servidores Bolt (adicionar/parear, alternar, remover).
- **`/mcps`** — gerencia servidores MCP locais/remotos regulares.

No dialogo `/bolt`: **a** para adicionar, **espaco** para alternar um servidor, **esc** para fechar.

## Exemplos de Uso

```
> Use bolt to scan 192.168.1.0/24 for open ports and services   # nmap
> Find all subdomains of example.com                            # subfinder
> Scan https://target.com with nuclei                           # nuclei
> Fuzz directories on https://target.com                        # ffuf
> Run "dig +short example.com"                                  # run-command escape hatch
```

Cada um mapeia para uma chamada direta de ferramenta — sem etapa de carregamento.

## Configuracao do Container

### Variaveis de ambiente

| Variavel | Padrao | Descricao |
|----------|--------|-----------|
| `PORT` | 3001 | Porta do servidor HTTP |
| `HOST` | 0.0.0.0 | Endereco de bind |
| `MCP_ADMIN_TOKEN` | — | Token de administrador usado para pareamento |
| `DATA_DIR` | /data | Diretorio de dados persistentes |

### Capacidades Docker

| Capacidade | Proposito |
|------------|-----------|
| `NET_RAW` | Sockets raw para scans SYN do nmap |
| `NET_ADMIN` | Configuracao de rede para ferramentas que precisam de acesso elevado |

## Referencia da API

| Endpoint | Proposito |
|----------|-----------|
| `GET /health` | Verificacao de saude — retorna `{ "status": "ok" }` (requisicoes admin autenticadas recebem informacoes detalhadas, incluindo contagem de ferramentas) |
| `POST /mcp` | Endpoint MCP JSON-RPC (requisicoes assinadas) |
| `POST /pair` | Iniciar pareamento Ed25519 com o token de administrador |
| `POST /pair/exchange` | Trocar o codigo de pareamento + chaves publicas |

```bash
curl http://localhost:3001/health
```

## Solucao de Problemas

- **Conexao recusada** — verifique se o container esta ativo (`docker ps`), a porta esta mapeada (`docker port bolt`) e `curl http://localhost:3001/health` responde.
- **Re-pareamento necessario** — se a URL do Bolt mudar, o Cyberstrike descarta as credenciais armazenadas e voce deve parear novamente via `/bolt`.
- **Ferramentas nao disponiveis** — confirme que o servidor esta conectado em `/bolt`, e use um modelo de API direta (ex: `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`).
