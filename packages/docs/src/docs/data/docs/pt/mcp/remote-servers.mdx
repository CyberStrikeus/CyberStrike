Servidores MCP remotos conectam via HTTP/HTTPS, habilitando acesso a servicos hospedados e infraestrutura compartilhada. O transporte e StreamableHTTP (com fallback SSE).

<Aside variant="tip">
  **Procurando ferramentas de seguranca?** Consulte [Bolt](/docs/mcp/bolt) para ferramentas de seguranca pre-instaladas. Note que o Bolt e configurado sob sua propria chave de nivel superior `bolt`, nao sob `mcp`.
</Aside>

## Schema de Configuracao

Um servidor remoto e uma entrada no mapa plano `mcp`, indexado por nome do servidor:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "Bearer {env:MY_TOKEN}" },
      "enabled": true,
      "timeout": 5000
    }
  }
}
```

| Campo | Tipo | Descricao |
|-------|------|-----------|
| `type` | `"remote"` | Obrigatorio. Seleciona um servidor baseado em HTTP. |
| `url` | string | Obrigatorio. O endpoint do servidor. |
| `headers` | object | Opcional. Headers enviados com cada requisicao (ex: uma chave de API). |
| `oauth` | object \| `false` | Opcional. Configuracao OAuth; defina `false` para desabilitar deteccao automatica de OAuth. Veja [OAuth](/docs/mcp/oauth). |
| `enabled` | boolean | Opcional. Conectar no lancamento (padrao: true). |
| `timeout` | number | Opcional. Timeout de requisicao em ms (padrao: 5000). |

<Aside variant="caution">
  O objeto `mcp` e um **mapa plano** indexado por nome do servidor — nao ha wrapper `servers`. O transporte e apenas StreamableHTTP/SSE (nao ha transporte WebSocket), e o schema e estrito: campos `retry`, `keepalive`, `proxy`, TLS/`ca`/`cert` e balanceamento de carga **nao** existem.
</Aside>

## Adicionando via TUI

Digite `/mcps` para abrir o gerenciador MCP, pressione `a` para adicionar e escolha **Remote**. Insira a **URL** do servidor; o **nome** do servidor e derivado automaticamente do hostname (pontos se tornam hifens). O Cyberstrike testa a conexao antes de salvar. Isso escreve exatamente o schema mostrado acima.

## Autenticacao

### Chave de API via header

Envie um token estatico ou chave de API como header de requisicao. Use `{env:VAR}` para que o segredo nao seja armazenado no arquivo de configuracao:

```json
{
  "mcp": {
    "github-remote": {
      "type": "remote",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer {env:GITHUB_TOKEN}" }
    }
  }
}
```

### OAuth

Para servidores que usam OAuth, adicione um bloco `oauth` (ou deixe o Cyberstrike detectar automaticamente). Quando `clientId` e omitido, registro dinamico de cliente (RFC 7591) e tentado:

```json
{
  "mcp": {
    "oauth-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": { "scope": "read write" }
    }
  }
}
```

Autorize com `cyberstrike mcp auth <name>`. Consulte [OAuth](/docs/mcp/oauth) para o fluxo completo. Defina `"oauth": false` para desabilitar a deteccao automatica de OAuth.

## Habilitando, Desabilitando e Timeouts

Defina `enabled: false` para manter um servidor configurado mas desconectado (ou alterne em `/mcps`). Aumente o `timeout` (ms) para endpoints lentos:

```json
{
  "mcp": {
    "slow-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "enabled": false,
      "timeout": 30000
    }
  }
}
```

## Solucao de Problemas

- **Falhas de autenticacao** — verifique o header ou execute `cyberstrike mcp auth <name>` para servidores OAuth; inspecione com `cyberstrike mcp debug <name>`.
- **Timeouts** — aumente o `timeout`, ou confirme que o endpoint e alcancavel.
- **Configuracao rejeitada** — o schema e estrito; use o mapa plano com `type: "remote"` + `url`, e apenas os campos listados acima.
