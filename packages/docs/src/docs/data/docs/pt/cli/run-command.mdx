`cyberstrike run` executa um unico prompt de forma nao interativa — ideal para automacao e scripts. Neste modo nao ha ninguem para responder prompts de permissao, entao qualquer ferramenta que solicitaria aprovacao e auto-rejeitada (veja [Automacao](/docs/permissions/automation)).

## Uso Basico

```bash
cyberstrike run "your prompt here"
```

O prompt tambem e lido do stdin quando a entrada e redirecionada:

```bash
echo "summarize the findings in report.json" | cyberstrike run
```

## Opcoes

| Flag | Alias | Descricao |
|------|-------|-----------|
| `--model` | `-m` | Modelo a usar, como `provider/model` |
| `--agent` | | Agente primario a usar (apenas `cyberstrike` vem integrado) |
| `--format` | | Formato de saida: `default` ou `json` (padrao: `default`) |
| `--file` | `-f` | Arquivo(s) a anexar a mensagem (repetivel) |
| `--continue` | `-c` | Continuar a ultima sessao |
| `--session` | `-s` | ID da sessao a continuar |
| `--fork` | | Bifurcar a sessao antes de continuar (necessita `--continue`/`--session`) |
| `--share` | | Compartilhar a sessao |
| `--title` | | Titulo para a sessao |
| `--variant` | | Variante do modelo / esforco de raciocinio (ex: `high`, `max`, `minimal`) |
| `--thinking` | | Mostrar blocos de pensamento |
| `--attach` | | Conectar a um servidor em execucao (ex: `http://localhost:4096`) |
| `--dir` | | Diretorio para executar (caminho remoto ao conectar) |
| `--port` | | Porta para o servidor local |
| `--command` | | Executar um comando nomeado; usar a mensagem para seus argumentos |

<Aside variant="caution">
  Nao existem flags `--output`, `--permission`, `--timeout`, `--verbose` ou `--quiet`. O controle de saida e `--format` (`default` | `json`); a exibicao de raciocinio e `--thinking`.
</Aside>

## Exemplos

### Saida JSON para scripts

```bash
cyberstrike run "scan example.com for OWASP Top 10 issues" --format json > report.json
```

### Escolher um modelo e anexar arquivos

```bash
cyberstrike run "review this code for auth bugs" \
  -m anthropic/claude-sonnet-4-20250514 \
  -f src/auth.ts -f src/session.ts
```

### Continuar ou bifurcar uma sessao

```bash
cyberstrike run "now test the admin endpoints" --continue
cyberstrike run "try a different payload" --session <id> --fork
```

## Permissoes no `run`

Como prompts nao podem ser respondidos de forma nao interativa, pre-aprove as ferramentas que um script precisa com a variavel de ambiente `CYBERSTRIKE_PERMISSION` ou o campo `permission` na configuracao:

```bash
CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow"}' \
  cyberstrike run "enumerate services on the host" --format json
```

Veja [Automacao](/docs/permissions/automation) para padroes de CI.

## Codigos de Saida

`cyberstrike run` retorna `0` em sucesso e um codigo diferente de zero em erro (ex: argumentos invalidos) ou interrupcao.
