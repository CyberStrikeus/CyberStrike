Os comandos `cyberstrike auth` gerenciam credenciais de provedores de IA. Existem exatamente tres subcomandos — `login`, `logout` e `list` — e nenhum deles aceita flags; cada um e interativo.

## `auth login`

```bash
cyberstrike auth login [url]
```

Inicia um login interativo. O Cyberstrike mostra uma lista de provedores (construida a partir do catalogo de modelos) e solicita a chave de API ou fluxo OAuth. O `url` posicional opcional pre-seleciona uma URL de provedor well-known; o provedor e de outra forma escolhido no menu — voce **nao** passa o provedor como flag.

```
? Select provider
❯ cyberstrike (recommended)
  anthropic (Claude Max or API key)
  github-copilot
  openai (ChatGPT Plus/Pro or API key)
  google
  openrouter
  …
```

As credenciais sao armazenadas no diretorio de dados (`~/.local/share/cyberstrike/auth.json`).

## `auth list`

```bash
cyberstrike auth list   # alias: ls
```

Lista os provedores para os quais voce tem credenciais.

## `auth logout`

```bash
cyberstrike auth logout
```

Selecione interativamente uma credencial armazenada para remover.

<Aside variant="caution">
  Nao existe comando `auth status`, `auth verify`, `auth refresh` ou `auth switch`, nem flags `--key`/`--oauth`/`--json`/`--all`. O login e sempre o fluxo interativo `auth login`.
</Aside>

## Variaveis de Ambiente

Em vez de armazenar credenciais, voce pode fornecer chaves de provedor via variaveis de ambiente — veja [Provedores de IA](/docs/providers) e [Variaveis de Ambiente](/docs/configuration/environment-variables). Por exemplo:

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."
export GOOGLE_GENERATIVE_AI_API_KEY="AI..."
```
