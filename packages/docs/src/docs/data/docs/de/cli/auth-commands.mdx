Die `cyberstrike auth`-Befehle verwalten KI-Anbieter-Anmeldedaten. Es gibt genau drei Unterbefehle — `login`, `logout` und `list` — und keiner davon akzeptiert Flags; jeder ist interaktiv.

## `auth login`

```bash
cyberstrike auth login [url]
```

Startet eine interaktive Anmeldung. Cyberstrike zeigt eine Anbieterliste (aus dem Modellkatalog erstellt) und fragt nach dem API-Schluessel oder dem OAuth-Ablauf. Die optionale positionelle `url` waehlt eine Well-Known-Provider-URL vor; der Anbieter wird andernfalls aus dem Menue gewaehlt — Sie uebergeben den Anbieter **nicht** als Flag.

```
? Select provider
❯ cyberstrike (recommended)
  anthropic (Claude Max or API key)
  github-copilot
  openai (ChatGPT Plus/Pro or API key)
  google
  openrouter
  …
```

Anmeldedaten werden im Datenverzeichnis gespeichert (`~/.local/share/cyberstrike/auth.json`).

## `auth list`

```bash
cyberstrike auth list   # Alias: ls
```

Listet die Anbieter auf, fuer die Sie Anmeldedaten haben.

## `auth logout`

```bash
cyberstrike auth logout
```

Waehlen Sie interaktiv gespeicherte Anmeldedaten zum Entfernen aus.

<Aside variant="caution">
  Es gibt keinen `auth status`-, `auth verify`-, `auth refresh`- oder `auth switch`-Befehl und keine `--key`/`--oauth`/`--json`/`--all`-Flags. Die Anmeldung erfolgt immer ueber den interaktiven `auth login`-Ablauf.
</Aside>

## Umgebungsvariablen

Anstatt Anmeldedaten zu speichern, koennen Sie Provider-Schluessel ueber Umgebungsvariablen bereitstellen — siehe [KI-Anbieter](/docs/providers) und [Umgebungsvariablen](/docs/configuration/environment-variables). Zum Beispiel:

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."
export GOOGLE_GENERATIVE_AI_API_KEY="AI..."
```
