## Read-Werkzeug

Liest Dateiinhalte mit Zeilennummern.

### Grundlegende Verwendung

```
> Read the contents of src/auth/login.ts
```

### Teilweises Lesen

```
> Read lines 50-100 of src/auth/login.ts
```

### Mehrere Dateien

```
> Read both config.json and package.json
```

### Bildanalyse

Das Read-Werkzeug kann Bilder analysieren:

```
> Read the screenshot at ./evidence/vuln-poc.png
```

### PDF-Analyse

```
> Read the security report at ./reports/pentest.pdf
```

## Write-Werkzeug

Erstellt oder ueberschreibt Dateien.

### Neue Datei erstellen

```
> Write a Python script to exploit the SQL injection to exploit.py
```

### Datei ueberschreiben

```
> Replace the contents of config.json with the secure configuration
```

<Aside variant="caution">
  Das Write-Werkzeug ueberschreibt bestehende Dateien ohne Warnung. Verwenden Sie Edit fuer partielle Aenderungen.
</Aside>

## Edit-Werkzeug

Nimmt praezise Aenderungen an bestehenden Dateien vor.

### Zeichenkettenersetzung

```
> Edit src/auth/login.ts to replace "SELECT * FROM users WHERE id = " + userId with parameterized query
```

### Mehrzeilige Bearbeitung

```
> Edit the vulnerable function in auth.ts to add input validation
```

### Alle ersetzen

```
> Replace all instances of "http://" with "https://" in config files
```

### Best Practices

1. Datei zuerst lesen, um den Kontext zu verstehen
2. Spezifisch angeben, was geaendert werden soll
3. Genuegend umgebenden Kontext fuer eindeutige Treffer einbeziehen
4. Aenderungen nach der Bearbeitung ueberpruefen

## Glob-Werkzeug

Findet Dateien durch Musterabgleich.

### Grundlegende Muster

```
> Find all TypeScript files in the project
```

Muster: `**/*.ts`

### Mehrere Erweiterungen

```
> Find all JavaScript and TypeScript files
```

Muster: `**/*.{js,ts}`

### Bestimmte Verzeichnisse

```
> Find all config files in the src directory
```

Muster: `src/**/config.*`

### Gaengige Muster

| Muster | Trifft zu |
|--------|-----------|
| `**/*.ts` | Alle TypeScript-Dateien |
| `src/**/*.test.ts` | Testdateien in src |
| `**/package.json` | Alle package.json-Dateien |
| `**/.env*` | Umgebungsdateien |
| `**/secret*` | Dateien mit "secret" im Namen |

### Sicherheits-Scan-Muster

```
> Find files that might contain credentials

Muster:
- **/*.env*
- **/secrets.*
- **/*credentials*
- **/*password*
- **/config.json
```

## Grep-Werkzeug

Durchsucht Dateiinhalte mit Regex.

### Grundlegende Suche

```
> Search for "password" in all files
```

### Regex-Suche

```
> Search for API key patterns in the codebase
```

Muster: `(api[_-]?key|apikey)\s*[:=]\s*['"][^'"]+['"]`

### Gross-/Kleinschreibung ignorieren

```
> Search for "SELECT" case insensitively
```

### Dateitypfilter

```
> Search for "eval(" only in JavaScript files
```

### Kontextzeilen

```
> Search for "TODO" with 2 lines of context before and after
```

### Sicherheitsorientierte Suchen

| Zweck | Muster |
|-------|--------|
| SQL Injection | `(SELECT|INSERT|UPDATE|DELETE).*\+.*\$` |
| Command Injection | `(exec|spawn|system)\s*\(` |
| Hartcodierte Geheimnisse | `(password\|secret\|key)\s*=\s*['"][^'"]&#123;8,&#125;` |
| Unsichere Deserialisierung | `(pickle|marshal|yaml\.load)` |
| XSS-Senken | `(innerHTML|outerHTML|document\.write)` |

## Dateianalyse-Workflow

### 1. Dateien entdecken

```
> Find all files that might handle user input
```

### 2. Nach Mustern suchen

```
> Search these files for SQL query construction
```

### 3. Verdaechtige Dateien lesen

```
> Read the files that matched the SQL pattern
```

### 4. Ergebnisse dokumentieren

```
> Write a summary of the SQL injection findings to findings.md
```

## Berechtigungsaspekte

Dateioperationen erfordern moeglicherweise Berechtigungen:

| Operation | Berechtigungsschluessel | Standardverhalten |
|-----------|------------------------|-------------------|
| Read | `read` | Erlaubt (nur-lesen) |
| Glob | `glob` | Erlaubt (nur-lesen) |
| Grep | `grep` | Erlaubt (nur-lesen) |
| Write | `edit` | Erfordert Berechtigung |
| Edit | `edit` | Erfordert Berechtigung |

Sowohl das Write- als auch das Edit-Werkzeug werden durch den einzelnen Berechtigungsschluessel `edit` gesteuert.

### Schreibvorgaenge automatisch genehmigen

Fuer Automatisierung ordnen Sie Dateipfad-Globs unter `edit` Aktionen zu:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "permission": {
    "edit": {
      "reports/**": "allow",
      "findings/**": "allow"
    }
  }
}
```

Nur `*` und `?` werden als Platzhalter unterstuetzt. Siehe [Berechtigungen](/docs/configuration/permissions) fuer das vollstaendige Modell.

### Paginierung

Fuer grosse Dateien:

```
> Read the first 100 lines of large-log.txt

```

### Binaerdateien

Das Read-Werkzeug behandelt Binaerdateien:

```
> Read the binary at ./malware.exe and analyze its strings
```

## Integration mit Sicherheitstests

### Code-Review

```
> Analyze all authentication-related files for security issues

1. Auth-Dateien finden: Glob **/*auth*.{ts,js}
2. Nach Schwachstellen suchen: Grep-Muster
3. Treffer lesen und analysieren
4. Ergebnisse dokumentieren
```

### Konfigurationsaudit

```
> Review all configuration files for security misconfigurations

1. Configs finden: Glob **/{config,settings}*.{json,yaml,yml}
2. Jede Datei lesen
3. Auf Offenlegung sensibler Daten pruefen
4. Sichere Standardwerte ueberpruefen
```

### Geheimniserkennung

```
> Scan the codebase for hardcoded secrets

1. Alle Quelldateien per Glob finden
2. Nach Geheimnis-Mustern per Grep suchen
3. Treffer zur Verifizierung lesen
4. Ergebnisse berichten
```

<Aside variant="tip">
  Kombinieren Sie Glob und Grep fuer effizientes Codebasis-Scanning. Beginnen Sie breit, dann grenzen Sie ein.
</Aside>
