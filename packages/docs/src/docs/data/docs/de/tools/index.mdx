## Werkzeugkategorien

| Kategorie | Werkzeuge | Zweck |
|-----------|-----------|-------|
| **Dateioperationen** | Read, Write, Edit, Glob, Grep | Dateien lesen, schreiben, bearbeiten und durchsuchen |
| **Befehlsausfuehrung** | Bash | Shell-Befehlsausfuehrung |
| **Web-Tests** | [Hacker Browser](/docs/tools/hacker-browser).
| **Speicher** | Memory Search, Memory Write, Memory Read, Memory Context | Persistenter Speicher ueber Sitzungen hinweg |
| **Werkzeug-Erkennung** | ToolSearch, LoadTools, UnloadTools | Dynamisches Laden von MCP-Werkzeugen |
| **Aufgaben** | Task, TodoWrite | Delegation und Aufgabenverfolgung |
| **Web** | WebFetch, WebSearch, CodeSearch | Web-Inhalte abrufen und durchsuchen |

## Dateioperationen

### Read

Liest Dateiinhalte mit Zeilennummern. Unterstuetzt Textdateien, Bilder und PDFs.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `filePath` | string | Ja | Pfad zur Datei (absolut oder relativ) |
| `offset` | number | Nein | Startzeile (1-indiziert) |
| `limit` | number | Nein | Anzahl zu lesender Zeilen (Standard: 2000) |

#### Beispiel

```json
{
  "filePath": "/path/to/file.txt",
  "offset": 100,
  "limit": 500
}
```

#### Ausgabeformat

```
00001| Erste Zeile des Inhalts
00002| Zweite Zeile des Inhalts
00003| Dritte Zeile des Inhalts

(End of file - total 3 lines)
```

#### Funktionen

- Automatische Erkennung von Binaerdateien
- Bild- und PDF-Unterstuetzung (gibt base64-kodierten Inhalt zurueck)
- Zeilenbegrenzung bei 2000 Zeichen
- Maximal 50KB pro Leseoperation
- Intelligente Dateivorschlaege bei Nicht-gefunden-Fehlern

---

### Write

Erstellt oder ueberschreibt eine Datei mit neuem Inhalt.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `filePath` | string | Ja | Absoluter Pfad zur Datei |
| `content` | string | Ja | Zu schreibender Inhalt |

#### Beispiel

```json
{
  "filePath": "/path/to/new-file.txt",
  "content": "Dateiinhalt hier"
}
```

#### Funktionen

- Erstellt uebergeordnete Verzeichnisse bei Bedarf
- Erzeugt Unified Diff zur Ueberpruefung
- LSP-Diagnose nach dem Schreiben
- Dateizeitverfolgung zur Konflikterkennung

---

### Edit

Fuehrt Such-und-Ersetz-Operationen an Dateien mit intelligentem Matching durch.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `filePath` | string | Ja | Absoluter Pfad zur Datei |
| `oldString` | string | Ja | Zu findender und ersetzender Text |
| `newString` | string | Ja | Ersetzungstext |
| `replaceAll` | boolean | Nein | Alle Vorkommen ersetzen (Standard: false) |

#### Beispiel

```json
{
  "filePath": "/path/to/file.ts",
  "oldString": "function oldName(",
  "newString": "function newName(",
  "replaceAll": false
}
```

#### Intelligentes Matching

Das Edit-Werkzeug verwendet mehrere Matching-Strategien:

1. **Einfache Ersetzung**: Exakte Zeichenkettensuche
2. **Zeilengetrimmt**: Ignoriert fuehrende/nachfolgende Leerzeichen pro Zeile
3. **Block-Anker**: Stimmt erste und letzte Zeile ab, unscharfe Mitte
4. **Leerzeichen-normalisiert**: Fasst mehrere Leerzeichen zusammen
5. **Einrueckungsflexibel**: Ignoriert Einrueckungsunterschiede
6. **Escape-normalisiert**: Behandelt Escape-Sequenzen
7. **Kontextbewusst**: Verwendet umgebenden Kontext fuer das Matching

#### Funktionen

- Unified Diff-Generierung
- LSP-Diagnose nach Bearbeitung
- Erkennung mehrfacher Vorkommen
- Konfliktvermeidung durch Dateizeitverfolgung

---

### Glob

Findet Dateien anhand eines Glob-Musters.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `pattern` | string | Ja | Glob-Muster (z.B. `**/*.ts`) |
| `path` | string | Nein | Zu durchsuchendes Verzeichnis (Standard: aktuelles Verzeichnis) |

#### Beispiel

```json
{
  "pattern": "**/*.{ts,tsx}",
  "path": "/path/to/project"
}
```

#### Ausgabe

Gibt Dateipfade zurueck, sortiert nach Aenderungszeitpunkt (neueste zuerst), begrenzt auf 100 Ergebnisse.

#### Musterbeispiele

| Muster | Trifft zu |
|--------|-----------|
| `*.ts` | TypeScript-Dateien im aktuellen Verzeichnis |
| `**/*.ts` | TypeScript-Dateien rekursiv |
| `src/**/*.{ts,tsx}` | TS/TSX-Dateien im src-Verzeichnis |
| `!**/node_modules/**` | node_modules ausschliessen |

---

### Grep

Durchsucht Dateiinhalte mit Regex-Mustern. Basiert auf ripgrep.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `pattern` | string | Ja | Zu suchendes Regex-Muster |
| `path` | string | Nein | Zu durchsuchendes Verzeichnis (Standard: aktuelles Verzeichnis) |
| `include` | string | Nein | Dateifilter (z.B. `*.js`) |

#### Beispiel

```json
{
  "pattern": "password|secret|api_key",
  "path": "/path/to/project",
  "include": "*.{js,ts,py}"
}
```

#### Ausgabeformat

```
Found 5 matches

/path/to/file.ts:
  Line 42: const apiKey = process.env.API_KEY
  Line 85: // TODO: remove hardcoded secret

/path/to/config.js:
  Line 12: password: "changeme"
```

#### Funktionen

- Regex-Unterstuetzung (ripgrep-Syntax)
- Suche in versteckten Dateien
- Symlink-Verfolgung
- Ergebnisse nach Aenderungszeitpunkt sortiert
- Maximal 100 Ergebnisse

## Befehlsausfuehrung

### Bash

Fuehrt Shell-Befehle mit Timeout und Ausgabeerfassung aus.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `command` | string | Ja | Auszufuehrender Befehl |
| `timeout` | number | Nein | Timeout in Millisekunden (Standard: 120000) |
| `workdir` | string | Nein | Arbeitsverzeichnis |
| `description` | string | Ja | Kurze Beschreibung des Befehlszwecks |

#### Beispiel

```json
{
  "command": "nmap -sV -sC target.com",
  "timeout": 300000,
  "workdir": "/path/to/project",
  "description": "Scan target for open ports and services"
}
```

#### Funktionen

- Shell-Erkennung (bash/zsh/sh)
- Prozessbaum-Beendigung bei Timeout
- Integration des Berechtigungssystems
- Echtzeit-Ausgabestreaming
- Zugangskontrolle fuer externe Verzeichnisse

#### Sicherheitsaspekte

Befehle werden mit tree-sitter analysiert, um Folgendes zu erkennen:
- Verzeichniszugriff ausserhalb des Projekts
- Gefaehrliche Befehlsmuster
- Dateisystemmodifikationen

## Speichersystem

Cyberstrike umfasst ein persistentes Speichersystem zum Speichern von Kontext ueber Sitzungen hinweg.

### Memory Write

Speichert Informationen im persistenten Speicher.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `content` | string | Ja | Zu speichernder Inhalt |
| `type` | string | Nein | `long_term` fuer MEMORY.md, `daily` fuer datierte Notizen |
| `title` | string | Nein | Optionale Ueberschrift fuer den Eintrag |

#### Beispiel

```json
{
  "content": "Target uses PostgreSQL 14.2 on port 5432",
  "type": "long_term",
  "title": "Database Configuration"
}
```

#### Speichertypen

| Typ | Speicherort | Zweck |
|-----|-------------|-------|
| `long_term` | `.cyberstrike/MEMORY.md` | Entscheidungen, Praeferenzen, wichtige Fakten |
| `daily` | `.cyberstrike/memory/YYYY-MM-DD.md` | Sitzungsnotizen, temporaerer Kontext |

---

### Memory Search

Durchsucht den gespeicherten Speicher.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `query` | string | Ja | Suchbegriffe oder Phrasen |

#### Beispiel

```json
{
  "query": "database credentials"
}
```

---

### Memory Read

Liest bestimmte Speicherdateien.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `file` | string | Ja | Dateibezeichner |

#### Dateibezeichner

| Bezeichner | Beschreibung |
|------------|-------------|
| `long_term` | Langzeitspeicher (MEMORY.md) |
| `today` | Heutige Tagesnotizen |
| `yesterday` | Gestrige Notizen |
| `YYYY-MM-DD` | Notizen eines bestimmten Datums |
| `list` | Alle Speicherdateien auflisten |

---

### Memory Context

Ruft den vollstaendigen Speicherkontext fuer die Sitzung ab.

#### Parameter

Keine erforderlich.

#### Beispiel

```json
{}
```

Gibt kombinierten Langzeitspeicher und aktuelle Tagesnotizen zurueck.

## Dynamisches Laden von Werkzeugen

<img src="/docs/images/diagrams/tool-interaction-flow.svg" alt="Wie ein Werkzeug verfuegbar wird: eingebaute Werkzeuge werden direkt aufgerufen; MCP-Werkzeuge werden mit tool_search gefunden, mit load_tools geladen, dann aufrufbar, und mit unload_tools freigegeben" className="my-6 mx-auto max-w-sm" />

Cyberstrike unterstuetzt dynamisches Laden von Werkzeugen fuer MCP-Server (Model Context Protocol). Dies ermoeglicht den Zugriff auf Hunderte von Werkzeugen, ohne das Kontextfenster zu ueberlasten.

### Tool Search

Durchsucht verfuegbare MCP-Werkzeuge nach Faehigkeiten.

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `query` | string | Ja | Faehigkeitsbeschreibung |
| `limit` | number | Nein | Maximale Ergebnisse (Standard: 5) |

#### Beispiel

```json
{
  "query": "sql injection testing",
  "limit": 10
}
```

#### Ausgabe

```
Found 3 tools:

1. sqlmap_scan
   SQL injection scanner using sqlmap
   Estimated tokens: ~500

2. nuclei_sqli
   Nuclei templates for SQL injection
   Estimated tokens: ~300

3. manual_sqli
   Manual SQL injection payloads
   Estimated tokens: ~200
```

---

## Aufgabenverwaltung

#### Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|-----|--------------|-------------|
| `description` | string | Ja | Eine kurze (3-5 Woerter) Aufgabenbeschreibung |
| `prompt` | string | Ja | Die vom Subagenten auszufuehrende Aufgabe |
| `subagent_type` | string | Ja | Welcher Subagent versendet wird (z.B. `web-application`, `general`) |

---

## Werkzeugberechtigungen

Jedes Werkzeug erfordert bestimmte Berechtigungen, die konfiguriert werden koennen:

| Berechtigung | Werkzeuge | Standard |
|-------------|-----------|---------|
| `read` | Read | ask |
| `edit` | Write, Edit | ask |
| `glob` | Glob | allow |
| `grep` | Grep | allow |
| `bash` | Bash | ask |
| `websearch` | WebSearch | ask |
| `webfetch` | WebFetch | ask |
| `codesearch` | CodeSearch | ask |
| `task` | Task | ask |
| `external_directory` | Zugriff ausserhalb des Projekts | ask |

### Konfiguration

```json
{
  "permission": {
    "bash": "ask",
    "edit": "allow",
    "read": "allow",
    "glob": "allow",
    "grep": "allow"
  }
}
```

### Berechtigungsaktionen

| Aktion | Beschreibung |
|--------|-------------|
| `ask` | Benutzer um Genehmigung bitten |
| `allow` | Automatisch genehmigen |
| `deny` | Werkzeugnutzung blockieren |

Siehe [Berechtigungen](/docs/configuration/permissions) fuer das vollstaendige Modell und Glob-Muster.

## Benutzerdefinierte Werkzeuge erstellen

Fuegen Sie benutzerdefinierte Werkzeuge hinzu, indem Sie Dateien in `.cyberstrike/tools/` erstellen:

```typescript title=".cyberstrike/tools/custom-scanner.ts"
import { z } from "zod"

export default {
  description: "Custom vulnerability scanner",
  args: {
    target: z.string().describe("Target URL to scan"),
    depth: z.number().default(3).describe("Scan depth"),
  },
  async execute(args, ctx): Promise<string> {
    const { target, depth } = args
    // Custom scanning logic
    return `Scanned ${target} to depth ${depth}`
  },
}
```

Dateien in einem `tool/`- oder `tools/`-Verzeichnis innerhalb eines `.cyberstrike/`-Ordners werden automatisch geladen.

### Werkzeugdefinitions-Schema

| Feld | Typ | Beschreibung |
|------|-----|-------------|
| `description` | string | Werkzeugbeschreibung, die dem Modell angezeigt wird |
| `args` | object | Zuordnung von Parametername → Zod-Schema |
| `execute` | function | `async (args, ctx) => string` |

## MCP-Server-Werkzeuge

Cyberstrike kann Werkzeuge von MCP-Servern laden. Der empfohlene Ansatz ist [Bolt](/docs/features/bolt), der Sicherheitswerkzeuge ueber einen Docker-Container mit Plugin-System bereitstellt:

```json title="cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true
    }
  }
}
```

MCP-Werkzeuge werden als direkte Werkzeugaufrufe verfuegbar — jedes Plugin wird direkt ueber seinen Namen aufgerufen (z.B. `nmap`, `nuclei`, `ffuf`).

<Aside variant="tip">
  Siehe [Bolt](/docs/features/bolt) fuer die empfohlene Einrichtung der Sicherheitswerkzeuge — 7 Plugins plus ~26 aggregierte MCP-Server, alle als direkte Werkzeugaufrufe verfuegbar.
</Aside>
