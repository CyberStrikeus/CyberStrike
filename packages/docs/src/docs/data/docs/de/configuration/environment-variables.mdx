Umgebungsvariablen konfigurieren Anbieter-Anmeldedaten und schalten Laufzeitverhalten um — nuetzlich fuer CI/CD und containerisierte Umgebungen.

<Aside variant="info">
  Cyberstrike liest Einstellungen wie Modell, Agent oder Theme **nicht** aus Umgebungsvariablen. Diese befinden sich in der Konfigurationsdatei (siehe [Konfigurationsreferenz](/docs/configuration)). Die unten aufgefuehrten `CYBERSTRIKE_*`-Variablen sind auf Anmeldedaten, Konfigurationspfade und Verhaltens-Flags beschraenkt.
</Aside>

## Anbieter-API-Schluessel

Anbieter-Schluessel verwenden die Standard-Variablennamen des SDKs. Siehe [KI-Anbieter](/docs/providers) fuer die vollstaendige Liste.

### Anthropic

```bash
export ANTHROPIC_API_KEY="sk-ant-api03-..."
```

### OpenAI

```bash
export OPENAI_API_KEY="sk-proj-..."
```

### Google (Gemini)

```bash
export GOOGLE_GENERATIVE_AI_API_KEY="AI..."
# GEMINI_API_KEY wird ebenfalls akzeptiert
```

### OpenRouter

```bash
export OPENROUTER_API_KEY="sk-or-..."
```

### Groq

```bash
export GROQ_API_KEY="gsk_..."
```

### Azure OpenAI

```bash
export AZURE_RESOURCE_NAME="your-resource"
export AZURE_API_KEY="..."
```

### AWS Bedrock

```bash
export AWS_ACCESS_KEY_ID="AKIA..."
export AWS_SECRET_ACCESS_KEY="..."
export AWS_REGION="us-east-1"
# oder ein Bearer-Token:
export AWS_BEARER_TOKEN_BEDROCK="..."
```

## Konfigurationspfad-Variablen

| Variable | Beschreibung |
|----------|--------------|
| `CYBERSTRIKE_CONFIG` | Vollstaendiger Pfad zu einer benutzerdefinierten Konfigurationsdatei |
| `CYBERSTRIKE_CONFIG_DIR` | Zusaetzliches `.cyberstrike`-Verzeichnis zum Scannen |
| `CYBERSTRIKE_CONFIG_CONTENT` | Inline-JSON-Konfiguration (ueberschreibt Dateiquellen) |
| `CYBERSTRIKE_DISABLE_PROJECT_CONFIG` | Auf wahr setzen, um Projektkonfiguration zu ueberspringen |
| `CYBERSTRIKE_PERMISSION` | Berechtigungsueberschreibung als JSON-String |

## Verhaltens-Flags

Diese Variablen schalten Laufzeitverhalten um. Boolesche Flags sind aktiviert, wenn sie auf einen wahren Wert gesetzt sind (`1`, `true`).

| Variable | Beschreibung |
|----------|--------------|
| `CYBERSTRIKE_AUTO_SHARE` | Neu erstellte Sitzungen automatisch teilen |
| `CYBERSTRIKE_DISABLE_AUTOUPDATE` | Automatische Updates deaktivieren |
| `CYBERSTRIKE_DISABLE_AUTOCOMPACT` | Automatische Kontext-Komprimierung deaktivieren |
| `CYBERSTRIKE_DISABLE_PRUNE` | Bereinigung alter Werkzeugausgaben deaktivieren |
| `CYBERSTRIKE_DISABLE_TERMINAL_TITLE` | Terminal-Titel nicht aktualisieren |
| `CYBERSTRIKE_DISABLE_DEFAULT_PLUGINS` | Eingebaute Plugins nicht laden |
| `CYBERSTRIKE_DISABLE_LSP_DOWNLOAD` | LSP-Server nicht herunterladen |
| `CYBERSTRIKE_DISABLE_MODELS_FETCH` | Remote-Modellkatalog nicht abrufen |
| `CYBERSTRIKE_DISABLE_EXTERNAL_SKILLS` | Externe Skills nicht laden |
| `CYBERSTRIKE_ENABLE_EXA` | Exa-basierte Websuche aktivieren |
| `CYBERSTRIKE_MODELS_URL` | Modellkatalog-URL ueberschreiben |
| `CYBERSTRIKE_MODELS_PATH` | Modellkatalog von einem lokalen Pfad laden |

### Server-Anmeldedaten

Verwendet von `cyberstrike serve` und `cyberstrike web`:

```bash
export CYBERSTRIKE_SERVER_PASSWORD="..."   # erforderlich, um den Server zu starten
export CYBERSTRIKE_SERVER_USERNAME="admin" # optional, Standards existieren
```

## Variablen in der Konfiguration referenzieren

Konfigurationsdateien unterstuetzen zwei Ersetzungen — und nur diese zwei:

### Umgebungsvariablen — `{env:VAR}`

```jsonc title="~/.config/cyberstrike/cyberstrike.jsonc"
{
  "provider": {
    "anthropic": {
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

`{env:VAR}` wird durch den Wert von `VAR` ersetzt, oder einen leeren String, wenn nicht gesetzt. Shell-Syntax `${VAR}`, `$VAR` und Standardwert-Syntax (`{env:VAR:-default}`) werden **nicht** unterstuetzt.

### Dateiinhalte — `{file:path}`

```json
{
  "instructions": ["{file:./SECURITY.md}"]
}
```

Pfade koennen relativ zur Konfigurationsdatei, absolut oder mit `~/` fuer das Home-Verzeichnis beginnen.

## Berechtigungsueberschreibungen fuer Automatisierung

`cyberstrike run` (nicht-interaktiv) lehnt automatisch jeden Werkzeugaufruf ab, der andernfalls eine Abfrage ausloesen wuerde. Um Werkzeuge in CI vorab zu genehmigen, uebergeben Sie eine JSON-Berechtigungszuordnung ueber `CYBERSTRIKE_PERMISSION`:

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","edit":"allow","read":"allow"}'
```

Der Wert folgt der gleichen Struktur wie das Konfigurationsfeld `permission`. Siehe [Berechtigungen](/docs/permissions).

## Shell-Konfiguration

### Bash / Zsh

```bash title="~/.bashrc / ~/.zshrc"
export ANTHROPIC_API_KEY="sk-ant-..."
export CYBERSTRIKE_AUTO_SHARE=1
```

### Fish

```fish title="~/.config/fish/config.fish"
set -gx ANTHROPIC_API_KEY "sk-ant-..."
set -gx CYBERSTRIKE_AUTO_SHARE 1
```

## .env-Dateien

```bash title=".env"
ANTHROPIC_API_KEY=sk-ant-...
CYBERSTRIKE_PERMISSION={"bash":"allow"}
```

```bash
# Vor dem Start laden
source .env && cyberstrike
```

<Aside variant="caution">
  Committen Sie niemals `.env`-Dateien in die Versionskontrolle. Fuegen Sie `.env` zu `.gitignore` hinzu.
</Aside>

## CI/CD-Integration

### GitHub Actions

```yaml
env:
  ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
  CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":"allow"}'

steps:
  - name: Security Scan
    run: cyberstrike run "scan for vulnerabilities"
```

### GitLab CI

```yaml
variables:
  CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'

security_scan:
  script:
    - cyberstrike run "analyze code for security issues"
```

## Docker

### Docker Run

```bash
docker run -it \
  -e ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  -e CYBERSTRIKE_PERMISSION='{"bash":"allow"}' \
  cyberstrike/cyberstrike
```

### Docker Compose

```yaml title="docker-compose.yml"
services:
  cyberstrike:
    image: cyberstrike/cyberstrike
    environment:
      - ANTHROPIC_API_KEY
      - CYBERSTRIKE_AUTO_SHARE=1
    env_file:
      - .env
```

## Prioritaetsreihenfolge

Konfigurationsquellen werden in dieser Reihenfolge zusammengefuehrt (hoechste gewinnt):

```
1. Kommandozeilenargumente
2. Enterprise-verwaltete Konfiguration
3. CYBERSTRIKE_CONFIG_CONTENT (Inline-JSON)
4. .cyberstrike/-Verzeichniskonfiguration
5. Projektkonfiguration (cyberstrike.json / .jsonc)
6. CYBERSTRIKE_CONFIG (benutzerdefinierte Datei)
7. Globale Konfiguration (~/.config/cyberstrike/)
8. Remote .well-known/cyberstrike
9. Standardwerte
```

Siehe die [Konfigurationsreferenz](/docs/configuration#configuration-hierarchy) fuer Details.

## Variablen ueberpruefen

```bash
# Aktive Cyberstrike-Variablen auflisten
env | grep CYBERSTRIKE

# Pruefen, ob ein Anbieterschluessel gesetzt ist (ohne ihn vollstaendig anzuzeigen)
echo "${ANTHROPIC_API_KEY:0:12}..."
```

## Sicherheit

1. Geben Sie niemals vollstaendige API-Schluessel aus
2. Verwenden Sie Secrets-Management in CI/CD
3. Rotieren Sie Schluessel regelmaessig
4. Beschraenken Sie `.env`-Berechtigungen: `chmod 600 .env`

<Aside variant="tip">
  Verwenden Sie einen Secrets-Manager wie HashiCorp Vault, AWS Secrets Manager oder 1Password CLI fuer Produktionsumgebungen.
</Aside>
