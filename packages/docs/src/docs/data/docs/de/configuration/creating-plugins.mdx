Ein Cyberstrike-Plugin ist ein Modul, das eine Funktion exportiert, die eine Reihe von [Hooks](/docs/configuration/plugin-hooks) zurueckgibt. Diese Anleitung behandelt das Schreiben, Registrieren und Veroeffentlichen eines Plugins.

## Ein Plugin schreiben

Ein Plugin ist `(input: PluginInput) => Promise<Hooks>`. Importieren Sie die Typen aus `@cyberstrike-io/plugin`:

```typescript title=".cyberstrike/plugin/guard.ts"
import type { Plugin } from "@cyberstrike-io/plugin"

export const GuardPlugin: Plugin = async ({ project, directory, $ }) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash" && /rm\s+-rf/.test(output.args.command)) {
        throw new Error("blocked: rm -rf")
      }
    },
    "permission.ask": async (input, output) => {
      if (input.type === "read") output.status = "allow"
    },
  }
}
```

Die `input`-Eigenschaft der Funktion gibt Ihnen Kontext — `client`, `project`, `directory`, `worktree`, `serverUrl` und `$` (eine Bun-Shell). Geben Sie ein Objekt zurueck, dessen Schluessel Hook-Namen sind; siehe die [Hook-Referenz](/docs/configuration/plugin-hooks) fuer jeden Hook und seine Signatur.

## Ein Plugin registrieren

Es gibt zwei Moeglichkeiten, ein Plugin zu laden.

### 1. Lokale Datei (ohne Veroeffentlichung)

Legen Sie eine `.ts`/`.js`-Datei in einem `plugin/`- (oder `plugins/`-)Verzeichnis innerhalb eines beliebigen `.cyberstrike/`-Ordners ab — im Projekt oder in `~/.cyberstrike/`:

```
.cyberstrike/
└── plugin/
    └── guard.ts
```

Cyberstrike erkennt es automatisch und installiert `@cyberstrike-io/plugin` fuer Sie, damit lokale Plugins die Typen importieren koennen.

### 2. Das `plugin`-Konfigurationsarray

Referenzieren Sie ein npm-Paket oder einen Pfad im `plugin`-Array (Werte werden ueber Konfigurationsquellen hinweg per Union zusammengefuehrt):

```json title="cyberstrike.json"
{
  "plugin": [
    "@myorg/cyberstrike-guard",
    "./local/guard.ts"
  ]
}
```

## Testen & Debuggen

Starten Sie Cyberstrike mit Debug-Protokollierung, um das Laden von Plugins und das Ausloesen von Hooks zu sehen:

```bash
cyberstrike --log-level DEBUG --print-logs
```

(Oder setzen Sie `"logLevel": "DEBUG"` in Ihrer Konfiguration.)

Da Hooks `output` mutieren (oder werfen), koennen Sie sie unit-testen, indem Sie den Hook mit einem simulierten `input`/`output` aufrufen und das mutierte `output` pruefen.

## Veroeffentlichen

Paketieren Sie Ihr Plugin wie jedes npm-Modul und veroeffentlichen Sie es, dann lassen Sie Benutzer es zu ihrem `plugin`-Array hinzufuegen:

```json title="package.json"
{
  "name": "@myorg/cyberstrike-guard",
  "type": "module",
  "main": "./index.ts",
  "peerDependencies": { "@cyberstrike-io/plugin": "*" }
}
```

```bash
npm publish --access public
```

<Aside variant="caution">
  Plugins laufen mit vollem Zugriff auf Ihren Rechner und Cyberstrike-Interna. Installieren Sie nur Plugins, denen Sie vertrauen, und halten Sie Hooks schnell — sie laufen inline mit Tool-Aufrufen und LLM-Anfragen.
</Aside>
