Ein Skill ist eine Markdown-Datei mit wiederverwendbarer Methodik, die der Agent bei Bedarf einbinden kann. Skills werden nach Dateiname erkannt — jeder Skill befindet sich in einer Datei namens **`SKILL.md`**.

## Datei & Speicherort

Die Datei muss `SKILL.md` heissen. Cyberstrike sucht nach `**/SKILL.md` unter einem `skill/`- oder `skills/`-Verzeichnis innerhalb von `.cyberstrike/` und unter `skills/` (Claude Code-Layout):

```
.cyberstrike/
└── skills/
    └── sql-injection/
        └── SKILL.md
```

## Frontmatter

Nur `name` und `description` sind erforderlich. Der Rest sind optionale Metadaten fuer Kategorisierung und Kill-Chain-Verknuepfung:

```markdown title="SKILL.md"
---
name: sql-injection
description: Methodology for testing SQL injection
version: "1.0.0"
author: you
tags: [injection, database]
category: injection
owasp_id: WSTG-INPV-05
tech_stack: [postgres, mysql]
cwe_ids: [CWE-89]
chains_with: [auth-bypass]
prerequisites: [request-capture]
---

Walk the tester through boolean-, error-, time-, and union-based SQLi:
1. Identify injectable parameters …
2. …
```

<Aside variant="caution">
  Der Body ist reines Markdown — es gibt **kein** Templating (kein `{{target}}`, `{% if %}`, `{% for %}` oder `$ARGUMENTS`). Frontmatter unterstuetzt **keine** `args`-, `model`-, `agent`- oder `permission`-Felder, und die Datei muss woertlich `SKILL.md` heissen (beliebige Namen wie `my-skill.md` werden nicht geladen).
</Aside>

Der `name` im Frontmatter muss mit der Identitaet des Skills uebereinstimmen — eine Abweichung wird als Fehler gemeldet.

## Skills verwenden

Geladene Skills stehen dem Agenten zur Verfuegung und koennen mit dem `/skills`-Befehl durchsucht werden. Der Agent bindet die Methodik eines Skills in den Kontext ein, wenn sie fuer die Aufgabe relevant ist.
