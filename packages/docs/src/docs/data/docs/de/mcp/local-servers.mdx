Lokale MCP-Server laufen auf Ihrem Rechner als Kindprozesse und kommunizieren ueber stdio. Dies ist eine Alternative zu [Bolt](/docs/mcp/bolt) fuer Benutzer, die Werkzeuge lieber direkt auf ihrem System ausfuehren.

<Aside variant="tip">
  **Bevorzugen Sie Bolt fuer Sicherheitswerkzeuge.** Lokales MCP erfordert die manuelle Installation jedes Werkzeugs. Siehe [Bolt](/docs/mcp/bolt) fuer den empfohlenen Ansatz mit vorinstallierten Sicherheitswerkzeug-Plugins.
</Aside>

## Wann lokales MCP verwenden

- **Offline-Umgebungen** — kein Netzwerkzugang erforderlich
- **Niedrige Latenz** — direkte Prozesskommunikation ueber stdio
- **Benutzerdefinierte Werkzeuge** — Ihre eigenen MCP-Server
- **Datenschutz** — Daten verlassen niemals Ihren Rechner

Cyberstrike liefert ausserdem einige standardmaessig aktivierte lokale MCP-Server mit: `github-security`, `cve` und `osint`. Ihre Konfiguration wird darueber zusammengefuehrt.

## Konfigurationsschema

Ein lokaler Server ist ein Eintrag in der flachen `mcp`-Map, nach Servername geschluesselt:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["npx", "-y", "my-mcp-server"],
      "environment": { "API_KEY": "{env:MY_API_KEY}" },
      "enabled": true,
      "timeout": 5000
    }
  }
}
```

| Feld | Typ | Beschreibung |
|------|-----|--------------|
| `type` | `"local"` | Erforderlich. Waehlt einen stdio-Kindprozess-Server. |
| `command` | `string[]` | Erforderlich. Der Befehl **und seine Argumente** als ein Array. |
| `environment` | object | Optional. Zusaetzliche Umgebungsvariablen fuer den Prozess. |
| `enabled` | boolean | Optional. Server beim Start starten (Standard: true). |
| `timeout` | number | Optional. Anfrage-Timeout in ms (Standard: 5000). |

<Aside variant="caution">
  Das `mcp`-Objekt ist eine **flache Map**, nach Servername geschluesselt — es gibt keinen `servers`-Wrapper. `command` ist ein einzelnes Array (Befehl + Argumente zusammen); es gibt kein separates `args`-, `cwd`-, `autoStart`- oder `restart`-Feld. Unbekannte Schluessel werden abgelehnt.
</Aside>

## Ueber die TUI hinzufuegen

Der einfachste Weg, einen lokalen Server hinzuzufuegen, ist ueber die TUI mit dem `/mcps`-Befehl.

Geben Sie `/mcps` ein, um den MCP-Manager zu oeffnen. Er listet konfigurierte Server mit ihrem Status auf (`✓` aktiviert / `○` deaktiviert). Druecken Sie `Leertaste` zum Umschalten eines Servers, `a` zum Hinzufuegen, `Enter` zum Handeln.

Um einen lokalen Server hinzuzufuegen: Druecken Sie `a` → waehlen Sie **Local** → geben Sie den **Befehl** ein (z.B. `npx my-mcp-server`) → fuegen Sie optional **Umgebungsvariablen** hinzu (`KEY=VALUE, KEY2=VALUE2`) → bestaetigen Sie den automatisch abgeleiteten **Namen**. Cyberstrike testet die Verbindung vor dem Speichern; schlaegt sie fehl, wird der Server nicht hinzugefuegt.

Die TUI schreibt exakt das oben gezeigte Schema.

## Beispiele

### Node.js-Server

```json
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/path/to/allow"]
    }
  }
}
```

### Python-Server

```json
{
  "mcp": {
    "python-tools": {
      "type": "local",
      "command": ["python", "-m", "mcp_server"]
    }
  }
}
```

### Binary oder Docker

Da `command` das vollstaendige argv ist, koennen Sie ein Binary direkt ausfuehren oder es in Docker einbetten — keine speziellen Felder noetig:

```json
{
  "mcp": {
    "docker-tools": {
      "type": "local",
      "command": ["docker", "run", "-i", "--rm", "--network=none", "mcp-tools:latest"]
    }
  }
}
```

## Umgebungsvariablen

Uebergeben Sie Variablen an den Serverprozess mit `environment`. Verwenden Sie `{env:VAR}`, um eine Variable aus Ihrer Shell zu referenzieren, anstatt Geheimnisse hart zu codieren:

```json
{
  "mcp": {
    "api-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "environment": {
        "API_KEY": "{env:MY_API_KEY}",
        "DEBUG": "mcp:*"
      }
    }
  }
}
```

## Aktivieren & Deaktivieren

Setzen Sie `enabled: false`, um einen Server konfiguriert, aber inaktiv zu halten (oder schalten Sie ihn im `/mcps`-Dialog um):

```json
{
  "mcp": {
    "heavy-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "enabled": false
    }
  }
}
```

## Langsam startende Server

Erhoehen Sie `timeout` (Millisekunden) fuer Server, die laenger als die standardmaessigen 5 Sekunden zum Antworten brauchen:

```json
{
  "mcp": {
    "slow-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "timeout": 30000
    }
  }
}
```

## Fehlerbehebung

- **Server startet nicht** — ueberpruefen Sie, ob das erste Element von `command` existiert und ausfuehrbar ist und ob dessen Abhaengigkeiten installiert sind. Pruefen Sie die Verbindung mit `cyberstrike mcp debug <name>`.
- **Verbindungs-Timeout** — erhoehen Sie `timeout` oder pruefen Sie, ob der Server schnell auf `tools/list` antwortet.
- **Konfiguration abgelehnt** — das `mcp`-Schema ist streng; stellen Sie sicher, dass Sie die flache Map mit `type` + `command` (Array) und keinen unbekannten Schluesseln verwenden.
