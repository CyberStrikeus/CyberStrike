Remote-MCP-Server verbinden sich ueber HTTP/HTTPS und ermoeglichen den Zugriff auf gehostete Dienste und gemeinsame Infrastruktur. Der Transport ist StreamableHTTP (mit SSE-Fallback).

<Aside variant="tip">
  **Suchen Sie Sicherheitswerkzeuge?** Siehe [Bolt](/docs/mcp/bolt) fuer vorinstallierte Sicherheitswerkzeuge. Beachten Sie, dass Bolt unter seinem eigenen Top-Level-Schluessel `bolt` konfiguriert wird, nicht unter `mcp`.
</Aside>

## Konfigurationsschema

Ein Remote-Server ist ein Eintrag in der flachen `mcp`-Map, nach Servername geschluesselt:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "Bearer {env:MY_TOKEN}" },
      "enabled": true,
      "timeout": 5000
    }
  }
}
```

| Feld | Typ | Beschreibung |
|------|-----|--------------|
| `type` | `"remote"` | Erforderlich. Waehlt einen HTTP-basierten Server. |
| `url` | string | Erforderlich. Der Server-Endpunkt. |
| `headers` | object | Optional. Header, die mit jeder Anfrage gesendet werden (z.B. ein API-Schluessel). |
| `oauth` | object \| `false` | Optional. OAuth-Konfiguration; setzen Sie `false`, um die OAuth-Autoerkennung zu deaktivieren. Siehe [OAuth](/docs/mcp/oauth). |
| `enabled` | boolean | Optional. Beim Start verbinden (Standard: true). |
| `timeout` | number | Optional. Anfrage-Timeout in ms (Standard: 5000). |

<Aside variant="caution">
  Das `mcp`-Objekt ist eine **flache Map**, nach Servername geschluesselt — es gibt keinen `servers`-Wrapper. Der Transport ist ausschliesslich StreamableHTTP/SSE (es gibt keinen WebSocket-Transport), und das Schema ist streng: `retry`, `keepalive`, `proxy`, TLS/`ca`/`cert` und Load-Balancing-Felder existieren **nicht**.
</Aside>

## Ueber die TUI hinzufuegen

Geben Sie `/mcps` ein, um den MCP-Manager zu oeffnen, druecken Sie `a` zum Hinzufuegen und waehlen Sie **Remote**. Geben Sie die Server-**URL** ein; der Server-**Name** wird automatisch vom Hostnamen abgeleitet (Punkte werden zu Bindestrichen). Cyberstrike testet die Verbindung vor dem Speichern. Dies schreibt exakt das oben gezeigte Schema.

## Authentifizierung

### API-Schluessel ueber Header

Senden Sie ein statisches Token oder einen API-Schluessel als Anfrage-Header. Verwenden Sie `{env:VAR}`, damit das Geheimnis nicht in der Konfigurationsdatei gespeichert wird:

```json
{
  "mcp": {
    "github-remote": {
      "type": "remote",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer {env:GITHUB_TOKEN}" }
    }
  }
}
```

### OAuth

Fuer Server, die OAuth verwenden, fuegen Sie einen `oauth`-Block hinzu (oder lassen Sie Cyberstrike ihn automatisch erkennen). Wenn `clientId` weggelassen wird, wird die dynamische Client-Registrierung (RFC 7591) versucht:

```json
{
  "mcp": {
    "oauth-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": { "scope": "read write" }
    }
  }
}
```

Autorisieren Sie mit `cyberstrike mcp auth <name>`. Siehe [OAuth](/docs/mcp/oauth) fuer den vollstaendigen Ablauf. Setzen Sie `"oauth": false`, um die OAuth-Autoerkennung zu deaktivieren.

## Aktivieren, Deaktivieren & Timeouts

Setzen Sie `enabled: false`, um einen Server konfiguriert, aber getrennt zu halten (oder schalten Sie ihn in `/mcps` um). Erhoehen Sie `timeout` (ms) fuer langsame Endpunkte:

```json
{
  "mcp": {
    "slow-remote": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "enabled": false,
      "timeout": 30000
    }
  }
}
```

## Fehlerbehebung

- **Authentifizierungsfehler** — ueberpruefen Sie den Header oder fuehren Sie `cyberstrike mcp auth <name>` fuer OAuth-Server aus; pruefen Sie mit `cyberstrike mcp debug <name>`.
- **Timeouts** — erhoehen Sie `timeout` oder bestaetigen Sie, dass der Endpunkt erreichbar ist.
- **Konfiguration abgelehnt** — das Schema ist streng; verwenden Sie die flache Map mit `type: "remote"` + `url` und nur die oben aufgefuehrten Felder.
