Bolt ist ein containerisierter MCP-Server, der Sicherheitswerkzeuge bereitstellt. Er laeuft in einem Docker-Container (Ubuntu 24.04) und stellt jedes Werkzeug direkt bereit — keine Meta-Tools, kein dynamisches Laden, rufen Sie einfach das benoetigte Werkzeug auf.

## Warum Bolt?

Bolt loest das Problem, Sicherheitswerkzeuge auszufuehren, die eine Linux-Umgebung benoetigen. Anstatt Werkzeuge lokal zu installieren, fuehrt Bolt sie in einem isolierten Container aus.

| Funktion | Ohne Bolt | Mit Bolt |
|----------|-----------|----------|
| Werkzeug-Installation | Manuell fuer jedes Werkzeug | Vorinstalliert |
| Plattformunterstuetzung | Nur Linux fuer die meisten Werkzeuge | Jede Plattform mit Docker |
| Isolation | Werkzeuge laufen auf Ihrem System | Sandboxed im Container |
| Aktualisierungen | Manuell | `docker pull` |

## Was enthalten ist

Bolt (`bolt.config.json`, Port `3001`) stellt Werkzeuge auf zwei Arten bereit:

- **7 native Plugins** — `subfinder`, `nmap`, `nuclei`, `httpx`, `ffuf`, `run-command`, `wordlist`
- **Ca. 26 aggregierte stdio-MCP-Server** — z.B. `dnsx`, `amass`, `katana`, `sqlmap`, `wpscan`, `gobuster`, `masscan`, `hydra`, `hashcat`, `john`, `impacket` und mehr

Jedes ist ein direkt aufrufbares Werkzeug — der Agent ruft es in einem einzigen Schritt auf, kein Such-/Ladeschritt.

## Schnellstart

### 1. Bolt-Container starten

```bash
docker run -d \
  --name bolt \
  --restart unless-stopped \
  -p 3001:3001 \
  -v bolt-data:/data \
  -e MCP_ADMIN_TOKEN=$(openssl rand -hex 32) \
  --cap-add NET_RAW \
  --cap-add NET_ADMIN \
  ghcr.io/cyberstrikeus/bolt:latest

# Admin-Token anzeigen (wird einmalig zum Pairing verwendet)
docker logs bolt | grep -i token
```

### 2. Mit Cyberstrike pairen

Oeffnen Sie den `/bolt`-Dialog in der TUI, druecken Sie **a** zum Hinzufuegen, geben Sie die URL `http://localhost:3001` ein und stellen Sie das Admin-Token bereit. Cyberstrike pairt sich mit dem Server (siehe [Authentifizierung](#authentifizierung)) und speichert die Anmeldedaten — das Token selbst wird **nicht** in Ihre Konfiguration geschrieben.

### 3. Die Werkzeuge verwenden

```
> Run nmap against 192.168.1.1 with service detection
> Use subfinder to enumerate subdomains of example.com
```

## Konfiguration

Bolt-Server werden unter ihrem **eigenen Top-Level-Schluessel `bolt`** konfiguriert — nicht unter `mcp`. Jeder Eintrag benoetigt nur eine `url` (Cyberstrike haengt den `/mcp`-Pfad selbst an):

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": {
      "url": "http://localhost:3001",
      "enabled": true,
      "timeout": 30000
    }
  }
}
```

| Feld | Typ | Beschreibung |
|------|-----|--------------|
| `url` | string | Erforderlich. Basis-URL des Bolt-Servers (z.B. `http://localhost:3001`). |
| `enabled` | boolean | Optional. Beim Start verbinden (Standard: true). |
| `timeout` | number | Optional. Anfrage-Timeout in ms (Standard: 30000). |

<Aside variant="caution">
  Bolt ist **kein** `mcp`-Eintrag. Es gibt kein `type: "remote"`, kein `bolt: true`-Flag und keinen `Authorization`-Header in der Konfiguration — die Authentifizierung wird durch Ed25519-Pairing gehandhabt, und das Admin-Token existiert nur im Pairing-Schritt.
</Aside>

## Authentifizierung

Bolt verwendet **Ed25519-Anfragensignierung**, eingeleitet durch ein einmaliges Pairing mit dem Admin-Token:

1. `POST /pair` mit dem Admin-Token → ein Pairing-Code
2. Cyberstrike generiert ein Ed25519-Schluesselpaar
3. `POST /pair/exchange` mit dem Code + oeffentlichem Client-Schluessel → oeffentlicher Server-Schluessel + Client-ID
4. Von da an wird jede Anfrage mit dem privaten Schluessel des Clients **signiert**

Das Admin-Token wird nur waehrend Schritt 1 verwendet — es ist kein dauerhaftes Bearer-Credential und wird niemals in `cyberstrike.json` gespeichert.

## TUI-Verwaltung

Zwei separate Dialoge:

- **`/bolt`** — verwaltet Bolt-Server (hinzufuegen/pairen, umschalten, entfernen).
- **`/mcps`** — verwaltet regulaere lokale/Remote-MCP-Server.

Im `/bolt`-Dialog: **a** zum Hinzufuegen, **Leertaste** zum Umschalten eines Servers, **esc** zum Schliessen.

## Anwendungsbeispiele

```
> Use bolt to scan 192.168.1.0/24 for open ports and services   # nmap
> Find all subdomains of example.com                            # subfinder
> Scan https://target.com with nuclei                           # nuclei
> Fuzz directories on https://target.com                        # ffuf
> Run "dig +short example.com"                                  # run-command Notausstieg
```

Jedes wird einem direkten Tool-Aufruf zugeordnet — kein Ladeschritt.

## Container-Konfiguration

### Umgebungsvariablen

| Variable | Standard | Beschreibung |
|----------|----------|--------------|
| `PORT` | 3001 | HTTP-Server-Port |
| `HOST` | 0.0.0.0 | Bind-Adresse |
| `MCP_ADMIN_TOKEN` | — | Admin-Token fuer das Pairing |
| `DATA_DIR` | /data | Persistentes Datenverzeichnis |

### Docker-Capabilities

| Capability | Zweck |
|------------|-------|
| `NET_RAW` | Raw-Sockets fuer nmap-SYN-Scans |
| `NET_ADMIN` | Netzwerkkonfiguration fuer Werkzeuge mit erhoehtem Zugriff |

## API-Referenz

| Endpunkt | Zweck |
|----------|-------|
| `GET /health` | Gesundheitspruefung — gibt `{ "status": "ok" }` zurueck (authentifizierte Admin-Anfragen erhalten detaillierte Informationen, einschliesslich Tool-Anzahl) |
| `POST /mcp` | MCP-JSON-RPC-Endpunkt (signierte Anfragen) |
| `POST /pair` | Ed25519-Pairing mit dem Admin-Token beginnen |
| `POST /pair/exchange` | Pairing-Code + oeffentliche Schluessel austauschen |

```bash
curl http://localhost:3001/health
```

## Fehlerbehebung

- **Verbindung verweigert** — pruefen Sie, ob der Container laeuft (`docker ps`), der Port gemappt ist (`docker port bolt`) und `curl http://localhost:3001/health` antwortet.
- **Erneutes Pairing erforderlich** — wenn sich die Bolt-URL aendert, verwirft Cyberstrike die gespeicherten Anmeldedaten und Sie muessen ueber `/bolt` erneut pairen.
- **Werkzeuge nicht verfuegbar** — bestaetigen Sie, dass der Server in `/bolt` verbunden ist, und verwenden Sie ein Direct-API-Modell (z.B. `anthropic/claude-sonnet-4-20250514`, `openai/gpt-4o`).
