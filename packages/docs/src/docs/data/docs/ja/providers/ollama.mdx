## 概要

Ollamaの利点:

- 完全なデータプライバシー
- API費用なし
- オフライン動作
- レート制限なし
- モデルの完全な制御

## インストール

### macOS

```bash
brew install ollama
```

### Linux

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### Windows

[ollama.com/download](https://ollama.com/download)からダウンロード

## Ollamaの起動

### サーバーの起動

```bash
ollama serve
```

サーバーはデフォルトで`http://localhost:11434`で動作します。

### インストールの確認

```bash
ollama --version
```

## 利用可能なモデル

### 推奨モデル

| モデル | サイズ | 最適な用途 |
|-------|------|----------|
| llama3.3:70b | 40GB | 最高品質、ハイエンドGPUが必要 |
| llama3.3 | 4.7GB | 品質と速度のバランス |
| codellama:34b | 19GB | コード分析 |
| mistral | 4.1GB | 高速な汎用 |
| mixtral:8x7b | 26GB | 高品質、効率的 |
| deepseek-coder:33b | 19GB | コードセキュリティレビュー |
| qwen2.5:72b | 41GB | 優秀な推論 |

### モデルのプル

```bash
# セキュリティテストに推奨
ollama pull llama3.3

# コードレビュー用
ollama pull codellama:34b

# 軽量オプション
ollama pull mistral
```

### インストール済みモデルの一覧

```bash
ollama list
```

## 設定

Ollamaは組み込みプロバイダー**ではありません** -- カスタムOpenAI互換プロバイダーとして定義します。キーはトップレベルの`api`フィールド(ベースURL、`/v1`サフィックス付き)です。`api` URLと共に`provider`の下にリストすることで、Cyberstrikeがロードします(認証は不要)。プルしたモデルを`models`の下に定義します:

### 基本セットアップ

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "provider": {
    "ollama": {
      "name": "Ollama",
      "api": "http://localhost:11434/v1",
      "models": {
        "llama3.3": { "name": "Llama 3.3" }
      }
    }
  },
  "model": "ollama/llama3.3"
}
```

`npm`はデフォルトで`@ai-sdk/openai-compatible`になるため、設定する必要はありません。

### カスタムホスト

リモートOllamaサーバーの場合、`api` URLを変更:

```json
{
  "provider": {
    "ollama": {
      "name": "Ollama",
      "api": "http://192.168.1.100:11434/v1",
      "models": { "llama3.3": { "name": "Llama 3.3" } }
    }
  }
}
```

## 使い方

TUIで`/models`を使用してOllamaモデルを選択するか、設定でデフォルトとして指定してください。

## モデル設定

### コンテキスト長

コンテキストウィンドウの拡大:

```bash
ollama run llama3.3 --num-ctx 8192
```

またはModelfileで:

```
FROM llama3.3
PARAMETER num_ctx 8192
```

### GPUレイヤー

GPU使用量の制御:

```bash
OLLAMA_NUM_GPU=999 ollama serve  # すべてのGPUレイヤーを使用
OLLAMA_NUM_GPU=0 ollama serve    # CPUのみ
```

### メモリ管理

```bash
# VRAM使用量を制限
OLLAMA_MAX_VRAM=8G ollama serve
```

## カスタムモデル

### Modelfileの作成

```dockerfile title="Modelfile"
FROM llama3.3

SYSTEM """
You are a security testing assistant specialized in:
- Web application vulnerabilities
- Code security review
- Network penetration testing

Always follow OWASP guidelines and report findings with:
- Vulnerability name
- Severity (Critical/High/Medium/Low)
- Evidence
- Remediation steps
"""

PARAMETER temperature 0.7
PARAMETER num_ctx 8192
```

### カスタムモデルのビルド

```bash
ollama create security-assistant -f Modelfile
```

### カスタムモデルの使用

設定にカスタムモデルを追加し、`/models`で選択:

```json
{
  "provider": {
    "ollama": {
      "models": {
        "security-assistant": { "name": "Security Assistant" }
      }
    }
  }
}
```

## パフォーマンス最適化

### ハードウェア要件

| モデルサイズ | 最小RAM | 推奨GPU |
|------------|---------|-----------------|
| 7B | 8GB | 8GB VRAM |
| 13B | 16GB | 12GB VRAM |
| 34B | 32GB | 24GB VRAM |
| 70B | 64GB | 48GB VRAM |

### 量子化

メモリを削減するために量子化モデルを使用:

```bash
ollama pull llama3.3:q4_0  # 4ビット量子化
ollama pull llama3.3:q8_0  # 8ビット量子化
```

### 並列リクエスト

同時リクエストを有効化:

```bash
OLLAMA_NUM_PARALLEL=4 ollama serve
```

## オフライン使用

### モデルの事前ダウンロード

```bash
ollama pull llama3.3
ollama pull codellama
```

### エアギャップシステム

1. 接続されたシステムでモデルをダウンロード
2. `~/.ollama/models/`をエアギャップシステムにコピー
3. インターネットなしでOllamaを実行

## Dockerデプロイメント

### コンテナで実行

```bash
docker run -d \
  --gpus all \
  -v ollama:/root/.ollama \
  -p 11434:11434 \
  --name ollama \
  ollama/ollama
```

### コンテナ内でモデルをプル

```bash
docker exec -it ollama ollama pull llama3.3
```

## API互換性

Ollamaは`http://localhost:11434/v1`でOpenAI互換APIを公開しています -- 上記のカスタムプロバイダー設定が動作するのはまさにそのためです(`npm`はデフォルトで`@ai-sdk/openai-compatible`)。`api`フィールドをそのURLに向ければ、CyberstrikeはOpenAIプロトコルでOllamaと通信します。

## トラブルシューティング

### 接続拒否

```
Error: Connection refused
```

Ollamaが実行中であることを確認:

```bash
ollama serve
```

### メモリ不足

```
Error: CUDA out of memory
```

解決策:
- より小さいモデルを使用
- 量子化バージョンを使用
- コンテキスト長を短くする
- CPU用に`OLLAMA_NUM_GPU=0`を設定

### パフォーマンスが遅い

- GPUアクセラレーションを有効化
- 量子化モデルを使用
- `num_parallel`を増やす
- サーマルスロットリングを確認

<Aside variant="tip">
  最良の結果を得るには、ハイエンドGPUでllama3.3:70bを使用してください。リソースが限られたシステムでは、mistralがより低い要件で良好な品質を提供します。
</Aside>
