## プラグインを書く

プラグインは `(input: PluginInput) => Promise<Hooks>` です。`@cyberstrike-io/plugin` から型をインポートします：

```typescript title=".cyberstrike/plugin/guard.ts"
import type { Plugin } from "@cyberstrike-io/plugin"

export const GuardPlugin: Plugin = async ({ project, directory, $ }) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash" && /rm\s+-rf/.test(output.args.command)) {
        throw new Error("blocked: rm -rf")
      }
    },
    "permission.ask": async (input, output) => {
      if (input.type === "read") output.status = "allow"
    },
  }
}
```

関数の `input` は現在の環境のコンテキストを提供します — `client`、`project`、`directory`、`worktree`、`serverUrl`、`$`（Bunシェル）。キーがフック名であるオブジェクトを返します。各フックとそのシグネチャは[フックリファレンス](/docs/configuration/plugin-hooks)を参照してください。

## プラグインの登録

プラグインを読み込む方法は2つあります。

### 1. ローカルファイル（公開不要）

`.cyberstrike/` フォルダ — プロジェクトまたは `~/.cyberstrike/` — 内の `plugin/`（または `plugins/`）ディレクトリに `.ts`/`.js` ファイルを配置します：

```
.cyberstrike/
└── plugin/
    └── guard.ts
```

Cyberstrikeが自動的に検出し、ローカルプラグインが型をインポートできるように `@cyberstrike-io/plugin` をインストールします。

### 2. `plugin` 設定配列

`plugin` 配列でnpmパッケージまたはパスを参照します（値は設定ソース間でユニオンマージされます）：

```json title="cyberstrike.json"
{
  "plugin": [
    "@myorg/cyberstrike-guard",
    "./local/guard.ts"
  ]
}
```

## テストとデバッグ

デバッグログを有効にしてCyberstrikeを実行し、プラグインの読み込みとフックの発火を確認します：

```bash
cyberstrike --log-level DEBUG --print-logs
```

（設定で `"logLevel": "DEBUG"` を設定することもできます。）

フックは `output` を変更（またはスロー）するため、フェイクの `input`/`output` でフックを呼び出し、変更された `output` をアサートすることでユニットテストできます。

## 公開

プラグインを通常のnpmモジュールとしてパッケージ化して公開し、ユーザーに `plugin` 配列に追加してもらいます：

```json title="package.json"
{
  "name": "@myorg/cyberstrike-guard",
  "type": "module",
  "main": "./index.ts",
  "peerDependencies": { "@cyberstrike-io/plugin": "*" }
}
```

```bash
npm publish --access public
```

<Aside variant="caution">
  プラグインはあなたのマシンとCyberstrike内部への完全なアクセス権限を持って実行されます。信頼できるプラグインのみをインストールし、フックは高速に保ってください — ツールコールやLLMリクエストとインラインで実行されます。
</Aside>
