非対話的実行(`cyberstrike run`)では、権限プロンプトに応答する人がいないため、プロンプトが*表示される*ツールは**自動的に拒否**されます。パイプラインが実際の作業を行えるようにするには、必要なツールを事前に承認してください。

<img src="/docs/images/diagrams/cicd-workflow.svg" alt="ヘッドレス実行の権限フロー: CYBERSTRIKE_PERMISSIONまたは設定で事前承認されたツールは実行される。プロンプトが表示されるはずのツールは自動拒否。結果はJSON形式でstdoutに出力" className="my-6 mx-auto max-w-sm" />

## ツールの事前承認

「自動モード」フラグはありません。権限を2つの方法で付与します:

**1. `CYBERSTRIKE_PERMISSION`環境変数** -- JSON権限マップ(設定の`permission`フィールドと同じ形式):

```bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
cyberstrike run "scan this codebase for security issues" --format json > report.json
```

**2. 設定の`permission`** -- 安全なデフォルトをコミットし、危険な部分を拒否([パターン](/docs/permissions/patterns)を参照):

```json title="cyberstrike.json"
{
  "permission": {
    "read": "allow",
    "bash": { "*": "allow", "rm -rf *": "deny", "sudo *": "deny" },
    "edit": { "reports/**": "allow", ".env*": "deny" }
  }
}
```

出力はstdoutに出力されます。マシンリーダブルな結果には`--format json`を使用してください。

## CI/CD統合

### GitHub Actions

```yaml title=".github/workflows/security-scan.yml"
name: Security Scan
on:
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @cyberstrike-io/cyberstrike@latest
      - name: Run Security Scan
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow","edit":{"reports/**":"allow"}}'
        run: cyberstrike run "scan this codebase for security vulnerabilities" --format json > security-report.json
      - uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: security-report.json
```

### GitLab CI

```yaml title=".gitlab-ci.yml"
security-scan:
  image: node:20
  variables:
    CYBERSTRIKE_PERMISSION: '{"bash":"allow","read":"allow"}'
  script:
    - npm install -g @cyberstrike-io/cyberstrike@latest
    - cyberstrike run "analyze code for vulnerabilities" --format json > report.json
  artifacts:
    paths:
      - report.json
```

## バッチおよびスケジュール実行

ターゲットをループ処理するか、cronから実行します -- 同じ`CYBERSTRIKE_PERMISSION`(または設定)のルールが適用されます:

```bash title="scan-targets.sh"
#!/bin/bash
export CYBERSTRIKE_PERMISSION='{"bash":"allow"}'
while read -r target; do
  cyberstrike run "scan $target for open ports and services" --format json > "reports/${target}.json"
done < targets.txt
```

```bash
# 毎日02:00にスキャン
0 2 * * * CYBERSTRIKE_PERMISSION='{"bash":"allow"}' /usr/local/bin/cyberstrike run "daily security scan" >> /var/log/cyberstrike.log 2>&1
```

## 終了コードと出力

`cyberstrike run`は結果をstdoutに出力し(JSON形式には`--format json`)、成功時に`0`を返し、エラーまたは中断時に非ゼロコードを返します。JSONを解析して検出結果を取得:

```bash
cyberstrike run "scan target" --format json | jq '.'
```

## セキュリティに関する考慮事項

- **最小権限** -- ジョブに必要なツールのみを`allow`し、`rm -rf *`、`sudo *`、シークレットパスに対しては明示的な`deny`を維持してください。
- **シークレット** -- CIのシークレットストアからAPIキーを注入し、コミットしないでください。
- **分離** -- 可能な限りネットワークが制限されたコンテナ内で実行してください。

<Aside variant="caution">
  自動化で`bash`を事前承認する場合は、破壊的なコマンドに対するdenyルールを常に維持してください。
</Aside>
