権限パターンは、ツールの引数(コマンド文字列、ファイルパス)をGlobにマッチングし、アクションにマッピングすることで、きめ細かい制御を提供します。

## 形式

権限エントリは、単一のアクションまたは**Glob --> アクション**のマップです。`Tool(pattern)`構文やallow/deny配列はありません -- ツールキーがパターンをグループ化します:

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "ls *": "allow",
      "git status": "allow",
      "rm -rf *": "deny"
    },
    "edit": {
      "reports/**": "allow",
      ".env*": "deny"
    }
  }
}
```

Globはツールの引数にマッチします: `bash`の場合はコマンド文字列、`edit`/`read`の場合はファイルパスです。

## ワイルドカード

サポートされるワイルドカードは2つのみです:

| トークン | マッチ対象 |
|-------|---------|
| `*` | 任意の文字列(`/`を含む) |
| `?` | 任意の1文字 |

<Aside variant="caution">
  `*`と`?`が**唯一の**ワイルドカードです。`[`、`]`、`{`、`}`、`(`、`)`、`|`のような文字は**リテラル**としてマッチされます。`**`はありません(`*`と同じ動作)。否定(`!pattern`)もサポートされていません。
</Aside>

スペース + `*`で終わるパターンは、引数なしの単純なコマンドにもマッチします -- つまり`"ls *"`は`ls`と`ls -la`の両方にマッチします。

## 優先順位

複数のパターンがマッチする場合、**より具体的(長い)パターンが優先**されます。パターンは最短から評価され、最後のマッチが適用されます -- つまり広い`"*": "ask"`を長い`"git status": "allow"`で上書きできます:

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "npm *": "allow",
      "npm publish*": "deny"
    }
  }
}
```

ここで`npm test`は許可されますが、`npm publish`は拒否されます。

## 例

### ツールチェーンを許可し、危険な部分をブロック

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git push*": "ask",
      "rm -rf *": "deny"
    }
  }
}
```

### 編集をディレクトリに制限

```json
{
  "permission": {
    "edit": {
      "*": "deny",
      "src/**": "allow",
      "src/secrets/**": "deny"
    }
  }
}
```
