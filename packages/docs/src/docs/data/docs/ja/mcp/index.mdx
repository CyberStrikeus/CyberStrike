Cyberstrikeは外部ツールを統合するためにModel Context Protocol (MCP)を使用します。**Bolt**は大規模なセキュリティツールセットを搭載するコンテナ化されたツールサーバーです。また、任意のローカルまたはリモートMCPサーバーにも接続できます。

## ツールを追加する2つの方法

| アプローチ | トランスポート | メリット | デメリット |
|----------|-----------|------|------|
| **Bolt** (推奨) | StreamableHTTP | プリインストールされたツール、コンテナ分離、簡単なセットアップ | Dockerが必要、ネットワーク遅延 |
| **ローカル / リモート MCP** | stdio / StreamableHTTP | 任意のMCPサーバー対応、ローカルならゼロレイテンシ | サーバーのインストールと実行が必要 |

Cyberstrikeはデフォルトで有効な3つのMCPサーバーも搭載しています: `github-security`、`cve`、`osint`。ユーザーの設定はこれらの上にマージされます。

## Bolt

BoltはセキュリティツールをDockerコンテナ内(Ubuntu 24.04、ポート3001)で実行します。**7つのネイティブプラグイン**(`subfinder`、`nmap`、`nuclei`、`httpx`、`ffuf`、`run-command`、`wordlist`)に加え、**約26の集約MCPサーバー**(`dnsx`、`amass`、`katana`、`sqlmap`、`wpscan`、`hydra`、`hashcat`など)を公開します。すべてのツールは直接呼び出し可能で、エージェントが1ターンで実行します。

Boltは**独自のトップレベル`bolt`キー**(`mcp`ではなく)で設定され、Ed25519ペアリングで認証されます:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "bolt": {
    "local": { "url": "http://localhost:3001" }
  }
}
```

セットアップとペアリングについては[Bolt](/docs/mcp/bolt)ページを参照してください。

## ローカル / リモート MCP

その他のMCPサーバーは、名前をキーとするフラットな`mcp`マップの下に配置します:

```json title="cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["your-mcp-server"]
    }
  }
}
```

- [ローカルサーバー](/docs/mcp/local-servers) -- stdioの子プロセス
- [リモートサーバー](/docs/mcp/remote-servers) -- StreamableHTTP/SSE、オプションの[OAuth](/docs/mcp/oauth)対応

## TUI管理

2つの別々のダイアログがあります:

- **`/bolt`** -- Boltサーバーの管理(追加・ペアリング、切り替え、削除)。
- **`/mcps`** -- ローカル/リモートMCPサーバーの管理。

両方で: **a** で追加、**space** でサーバーを切り替え、**esc** で閉じます。

## モデルの互換性

<Aside variant="caution">
  サブプロセスベースのモデルはMCPツールにアクセスできません。完全なBolt/MCP統合にはダイレクトAPIモデルを使用してください。
</Aside>

ダイレクトAPIモデル(例: `anthropic/claude-sonnet-4-20250514`、`openai/gpt-4o`)はCyberstrike内部で動作し、完全なMCPアクセスが可能です。別のCLIプロセスにシェルアウトするモデルはアクセスできません。

## 設定の優先順位

MCPとBoltのエントリは標準的な[設定の階層](/docs/configuration#configuration-hierarchy)に従います: プロジェクトの`.cyberstrike/`ディレクトリがプロジェクトの`cyberstrike.json`を上書きし、それがグローバルな`~/.config/cyberstrike/`設定を上書きし、さらにそれが組み込みサーバーを上書きします。
