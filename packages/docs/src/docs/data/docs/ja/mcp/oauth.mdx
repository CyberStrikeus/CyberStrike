OAuthを使用すると、長期間有効な資格情報を保存せずにCyberstrikeがリモートMCPサーバーで認証できます。CyberstrikeはサーバーのOAuthエンドポイントを自動検出するため、サーバーが要求する場合にのみクライアント詳細を提供します。

<img src="/docs/images/diagrams/oauth-flow.svg" alt="MCP OAuthフロー: OAuth検出、clientIdがない場合は動的クライアント登録、ブラウザ認可、コードをトークンに交換、トークン保存と自動リフレッシュ" className="my-6 mx-auto max-w-xs" />

## 設定スキーマ

OAuthは**リモート**MCPサーバーのオプションブロックです。完全なスキーマは3つのオプションフィールドのみです:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "clientId": "{env:OAUTH_CLIENT_ID}",
        "clientSecret": "{env:OAUTH_CLIENT_SECRET}",
        "scope": "read write"
      }
    }
  }
}
```

| フィールド | 型 | 説明 |
|-------|------|-------------|
| `clientId` | string | 任意。省略した場合、**動的クライアント登録(RFC 7591)**が試行されます。 |
| `clientSecret` | string | 任意。認可サーバーがコンフィデンシャルクライアントを必要とする場合のみ。 |
| `scope` | string | 任意。認可時にリクエストするスコープ。 |

<Aside variant="caution">
  認可URLとトークンURLはここでは設定**しません** -- CyberstrikeはサーバーのOAuthメタデータから自動検出します。`authorizationUrl`、`tokenUrl`、`pkce`、`deviceAuthorizationUrl`、`grantType`、`callbackPort`/`callbackPath`のようなフィールドはスキーマに**存在しません**(`clientId`、`clientSecret`、`scope`のみ)。
</Aside>

## 仕組み

1. Cyberstrikeはリモートサーバーがメタデータを通じてOAuthを必要とすることを検出します。
2. `clientId`が設定されていない場合、動的にクライアントを登録します(RFC 7591)。
3. ブラウザで認可URLを開き、ログインしてアクセスを許可します。
4. 内部で処理されるローカルコールバックで認可コードがトークンに交換されます。
5. トークンはCyberstrikeに保存され、有効期限が切れると自動的にリフレッシュされます。

OAuthの自動検出を完全にオプトアウトするには、サーバーに`"oauth": false`を設定します。

## サーバーの認可

CLIから認可をトリガーします:

```bash
cyberstrike mcp auth <name>       # サーバーを認可
cyberstrike mcp auth list         # OAuth認可済みサーバーを一覧表示
cyberstrike mcp logout <name>     # 保存されたOAuth資格情報を削除
```

Cyberstrikeは、OAuth保護されたサーバーがセッションで初めて使用されるときにも自動的に認可を要求します。トークンのリフレッシュは自動です -- 手動リフレッシュコマンドはありません。

## 例: スコープ付きサーバー

```json
{
  "mcp": {
    "example-mcp": {
      "type": "remote",
      "url": "https://mcp.example.com/mcp",
      "oauth": {
        "scope": "openid profile email"
      }
    }
  }
}
```

`clientId`がない場合、Cyberstrikeは動的にクライアントを登録し、リクエストされたスコープで認可します。

## セキュリティに関する注意

- シークレットは`{env:VAR}`で参照してください -- `clientSecret`をバージョン管理にコミットしないでください。
- サーバーが必要とする最小限のスコープをリクエストしてください。
- 不要になった資格情報は`cyberstrike mcp logout <name>`で削除してください。

## トラブルシューティング

- **認可に失敗** -- サーバーURLが到達可能であること、(サーバーがコンフィデンシャルクライアントを必要とする場合)  `clientId`/`clientSecret`が正しいことを確認してください。
- **認可プロンプトの繰り返し** -- 保存されたトークンがサーバー側で失効した可能性があります。`cyberstrike mcp auth <name>`を再度実行してください。
- **コールバックタイムアウト** -- ブラウザでログインが完了したこと、ローカルファイアウォールがループバックコールバックをブロックしていないことを確認してください。
- `cyberstrike mcp debug <name>`でサーバー接続を検査できます。
