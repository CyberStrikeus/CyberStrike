ローカルMCPサーバーは、マシン上で子プロセスとして動作し、stdioで通信します。これは、システム上で直接ツールを実行することを好むユーザー向けの[Bolt](/docs/mcp/bolt)の代替手段です。

<Aside variant="tip">
  **セキュリティツールにはBoltを推奨します。** ローカルMCPでは各ツールを自分でインストールする必要があります。プリインストール済みセキュリティツールプラグインを含む推奨アプローチについては[Bolt](/docs/mcp/bolt)を参照してください。
</Aside>

## ローカルMCPを使用するケース

- **オフライン環境** -- ネットワークアクセス不要
- **低レイテンシ** -- stdio経由の直接プロセス通信
- **カスタムツール** -- 独自のMCPサーバー
- **プライバシー** -- データがマシンの外に出ない

Cyberstrikeはデフォルトで有効ないくつかのローカルMCPサーバーも搭載しています: `github-security`、`cve`、`osint`。設定はこれらの上にマージされます。

## 設定スキーマ

ローカルサーバーは、サーバー名をキーとするフラットな`mcp`マップの1エントリです:

```json title="~/.config/cyberstrike/cyberstrike.json"
{
  "mcp": {
    "my-tools": {
      "type": "local",
      "command": ["npx", "-y", "my-mcp-server"],
      "environment": { "API_KEY": "{env:MY_API_KEY}" },
      "enabled": true,
      "timeout": 5000
    }
  }
}
```

| フィールド | 型 | 説明 |
|-------|------|-------------|
| `type` | `"local"` | 必須。stdioの子プロセスサーバーを選択します。 |
| `command` | `string[]` | 必須。コマンド**とその引数**を1つの配列として指定します。 |
| `environment` | object | 任意。プロセスの追加環境変数。 |
| `enabled` | boolean | 任意。起動時にサーバーを開始する(デフォルト: true)。 |
| `timeout` | number | 任意。リクエストタイムアウト(ミリ秒)(デフォルト: 5000)。 |

<Aside variant="caution">
  `mcp`オブジェクトはサーバー名をキーとする**フラットマップ**です -- `servers`ラッパーはありません。`command`は1つの配列(コマンド + 引数)です。`args`、`cwd`、`autoStart`、`restart`フィールドはありません。不明なキーは拒否されます。
</Aside>

## TUIでの追加

ローカルサーバーを追加する最も簡単な方法は、TUIの`/mcps`コマンドです。

`/mcps`と入力してMCPマネージャーを開きます。設定済みサーバーがステータス付きで一覧表示されます(`✓` 有効 / `○` 無効)。**space**でサーバーを切り替え、**a**で追加、**Enter**で選択項目を操作します。

ローカルサーバーを追加するには: **a**を押す --> **Local**を選択 --> **コマンド**を入力(例: `npx my-mcp-server`) --> 必要に応じて**環境変数**を追加(`KEY=VALUE, KEY2=VALUE2`) --> 自動生成された**名前**を確認。Cyberstrikeは保存前に接続をテストします。失敗した場合、サーバーは追加されません。

TUIは上記のスキーマと完全に同じ形式で書き込みます。

## 例

### Node.jsサーバー

```json
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/path/to/allow"]
    }
  }
}
```

### Pythonサーバー

```json
{
  "mcp": {
    "python-tools": {
      "type": "local",
      "command": ["python", "-m", "mcp_server"]
    }
  }
}
```

### バイナリまたはDocker

`command`は完全なargvなので、バイナリを直接実行したり、Dockerでラップしたりできます -- 特別なフィールドは不要です:

```json
{
  "mcp": {
    "docker-tools": {
      "type": "local",
      "command": ["docker", "run", "-i", "--rm", "--network=none", "mcp-tools:latest"]
    }
  }
}
```

## 環境変数

`environment`でサーバープロセスに変数を渡します。シークレットをハードコードする代わりに、`{env:VAR}`でシェルの変数を参照できます:

```json
{
  "mcp": {
    "api-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "environment": {
        "API_KEY": "{env:MY_API_KEY}",
        "DEBUG": "mcp:*"
      }
    }
  }
}
```

## 有効化と無効化

`enabled: false`を設定してサーバーを設定済みだが非アクティブに保つことができます(または`/mcps`ダイアログで切り替え):

```json
{
  "mcp": {
    "heavy-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "enabled": false
    }
  }
}
```

## 起動が遅いサーバー

デフォルトの5秒より応答に時間がかかるサーバーには、`timeout`(ミリ秒)を増やしてください:

```json
{
  "mcp": {
    "slow-tools": {
      "type": "local",
      "command": ["node", "server.js"],
      "timeout": 30000
    }
  }
}
```

## トラブルシューティング

- **サーバーが起動しない** -- `command`の最初の要素が存在し実行可能であること、依存関係がインストールされていることを確認してください。`cyberstrike mcp debug <name>`で接続を検査できます。
- **接続タイムアウト** -- `timeout`を増やすか、サーバーが`tools/list`に迅速に応答するか確認してください。
- **設定が拒否される** -- `mcp`スキーマは厳格です。`type` + `command`(配列)のフラットマップを使用し、不明なキーがないことを確認してください。
