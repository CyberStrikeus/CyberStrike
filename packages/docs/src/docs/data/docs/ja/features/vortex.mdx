VortexはCyberstrikeのHTTPトラフィックエンジンです。[HackBrowser](/docs/features/hackbrowser)、[Chrome拡張機能](/docs/tools/chrome-extension)、またはAPIを通じてシステムを流れるHTTPリクエストを傍受、保存、分析します。

## Vortexの機能

| 機能 | 説明 |
|------|------|
| **トラフィックキャプチャ** | 完全なヘッダーとボディを含むすべてのHTTPリクエスト/レスポンスペアを保存 |
| **DSLエンジン** | 専用の式言語でトラフィックをフィルタおよびクエリ |
| **ルールマッチング** | キャプチャされたトラフィックに対してルールをデータとして適用（検出、カナリア、変換） |
| **リプレイ** | テスト用にキャプチャされたリクエストを変更して再送信 |
| **シグナル相関** | リクエスト横断で発見事項を相互参照し、連鎖脆弱性を検出 |

## DSLクエリ

VortexにはHTTPトラフィックをフィルタリングするための式エンジンが含まれています。メソッド、パス、ステータス、ヘッダー、ボディ内容などでクエリできます：

```
method == "POST" && path contains "/api/" && status >= 400
```

```
header["content-type"] contains "json" && body contains "token"
```

DSLはブーリアンロジック、文字列マッチング、数値比較、ネストされたフィールドアクセスをサポートします。

## ルール

Vortexルールは宣言型のデータです — コードではありません。3つのルール形状が一般的なパターンをカバーします：

| 形状 | 目的 | 例 |
|------|------|-----|
| **Detect** | パターンにマッチするトラフィックをフラグ | レスポンスボディ内の機密データ |
| **Canary** | マーカーを注入し、その反映を監視 | SSRF、オープンリダイレクト、ヘッダーインジェクション |
| **Transform** | リプレイ前にリクエストを変更 | 認証ヘッダーの除去、パラメータ値の入れ替え |

ルールは組み込みパックからロードするか、プロジェクトごとに定義できます。

## HackBrowserとの連携

HackBrowserがトラフィックをキャプチャすると、Vortexが自動的に処理します：

1. `POST /session/ingest`経由でリクエストが到着
2. Vortexがリクエストを保存し、アクティブなルールを適用
3. マッチしたルールがシグナルを生成
4. シグナルがproxy-agentの分析パイプラインにフィード

## 使い方

VortexはCyberstrikeバックエンドの一部として実行されます — 別途セットアップは不要です。HackBrowser、Chrome拡張機能、またはWSTGパイプラインを使用する際に、トラフィックが自動的にVortexを通過します。

TUIで`/web`を使用して蓄積されたVortexデータを確認できます：キャプチャされたリクエスト、マッチしたルール、生成されたシグナル。関連コマンド：

| コマンド | 表示内容 |
|---------|---------|
| `/web` | キャプチャされたエンドポイント、ロール、認証情報 |
| `/vulnerabilities` | Vortexシグナル + WSTGテストからの発見事項 |
| `/methodology` | カバレッジとメソドロジーのステータス |

<Aside variant="tip">
  Vortexは無料枠に含まれています。AI分析レイヤー（proxy-agentの推論、シグナル相関）がVortexを強力にする部分であり、それは設定されたAIプロバイダーで実行されます。
</Aside>
