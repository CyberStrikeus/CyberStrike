# What's New in CyberStrike 2.0

> The first fully public, open-core release. **1,400+ commits since v1.1.16.**
> The web pipeline, the HTTP engine, the browser tooling, and the cloud workflows were all rebuilt, and every execution tool ships under **AGPL-3.0-only**.

This page is the long-form tour. For the terse, versioned list see [`CHANGELOG.md`](../../CHANGELOG.md).

---

1.1.16 was a capable CLI agent with a monolithic web-testing agent and a bolt-on proxy. 2.0 is a platform. The sections below walk through the major changes.

---

`@cyberstrike-io/vortex` (AGPL-3.0-only) is a new, ownable Caido/Burp-class HTTP traffic engine. It replaces the old ad-hoc proxy store with a durable, queryable, rule-driven corpus.

Vortex ships one expression language (`expr.ts`) used for **both** rule conditions and agent queries — it subsumes the former HTTPQL query syntax rather than sitting beside it.

- **Operators:** logical `||` `&&` `!`; comparison `==` `!=` `>` `<` `>=` `<=`; arithmetic `+` `-` `*` `/`; postfix index `[…]`; parenthesised grouping; literal types (number / string / `true` / `false` / `null`); dotted field paths.
- **Function library (24):** `contains`, `icontains`, `starts_with`, `ends_with`, `regex`, `len`, `lower`, `upper`, `trim`, `split`, `replace`, `base64_decode`, `url_decode`, `hex_decode`, `md5`, `sha256`, `compare_versions`, `is_json`, `jwt_header`, `jwt_payload`, `jwt_alg`, `count_header`, and the group quantifiers `any` / `all` / `count` / `countDistinct` for corpus-level `having` clauses.
- **ReDoS safety:** `regex()` is *full-scope only* — the narrower agent query scope rejects it (and bare "grep-everywhere" fields) recursively through arguments. Patterns over 2,000 chars are rejected, subjects are scanned to a 1 MB ceiling, and compiled regexes are cached.

Rules are declarative data (zod-validated, `{field}` interpolation), compiled to engine primitives. Four shapes ship:

| Shape | Compiles to | Purpose |
|---|---|---|
| **DeclarativeRule** `{when}` | per-transaction `Rule` | passive match on one response |
| **AggregateRule** `{when, aggregate}` | corpus `CorpusRule` | collapse many matches into one finding (`{count}`, `{endpoints}`) |
| **ChainRule** `{steps, link/reuses}` | corpus `CorpusRule` | multi-step cross-request correlation |
| **ProbeRule** `{select, inject, detect}` | `ActiveRule` | *active* — pick candidates, inject `{canary}`, detect reflected/evaluated |

Every rule carries selection metadata (tags, `requires.tech`) so the engine can prune tech-gated rules at scale — the reverse-index prefilter is built for 20k × 20k rule/request workloads.

- **~24 technology-detection packs** (`cdn`, `cms`, `databases`, `js-frameworks`, `ui-frameworks`, `web-frameworks`, `web-servers`, `reverse-proxies`, `languages`, `paas`, `auth-providers`, `os`, and more) — **~650 fingerprint rules** in total, authored as TS-embedded declarative data.
- **106 security & bot-management fingerprints** — CAPTCHAs, WAFs, bot protection, fraud prevention (Cloudflare, Akamai, Incapsula, ModSecurity, F5, …).
- An extended passive security catalog (info-disclosure / injection-signature / auth-session / API-security groups) plus a baseline catalog of DSL and TS-native rules.

- **Canary correlation** (`canary.ts`): same-request reflection is caught at send time; Vortex additionally scans for **stored / second-order** reflection — a canary surfacing in a *different* transaction than its origin. Reflection context is classified (`html-text` / `attribute` / `attribute-unquoted` / `script` / `comment`) and mapped to severity, with a "broke out of context" structural check and an SSTI template-canary (unique-product marker) variant.
- **Value-correlation / taint chains** (`taint.ts`, `chain.ts`): correlation by *value*, not field name — so a token that appears as `uid` in one request and `account` in another still chains. Entropy/length heuristics filter noise; an inverted value index bounds the join; `distinctIdentity` supports IDOR/privilege-escalation chains.

- **`SqliteStore`** (backed by `bun:sqlite`) for durable, session-scoped traffic + signals; `MemoryStore` for ephemeral use.
- **HAR import/export** — interoperates with browsers, Burp, and Caido.
- **Signal triage lifecycle:** `new → reviewed → confirmed → dismissed → escalated`, with summary counts and API endpoints.
- **Injection-point inventory** — enumerates injectable locations (`query` / `body` / `path` / `header`) with value typing (string/number/uuid/objectid/bool/json), and **coverage tracking** (one row per parameter × payload class) so the engine knows what it has and hasn't tested.

---

Two agent tools — **`http_replay`** (structured) and **`http_replay_raw`** (byte-exact) — sit on a new lossless HTTP engine (`packages/cyberstrike/src/replay/`).

- **Lossless message model:** ordered, case- and duplicate-preserving headers; the request target is *not* normalised (`..`, `%2e`, `//` survive) so path-confusion and smuggling tests mean what they say.
- **Field-level mutation:** `set/add/remove-query`, `set/add/remove-header`, `set-body`, `body-merge`, `body-set-field` / `body-remove-field` (JSON dot-path), `set/remove-cookie`, `set-path-param`, `set-method`, `set-target` — each value optionally run through an encoding pipeline first.
- **Dual backend:** backend A is a structured/normalised `fetch`; backend B is a byte-exact raw TCP/TLS socket (with SNI override for vhost/host-confusion, and Content-Length/chunked body-completion detection).
- **Governed batch runner:** bounded concurrency (fixed or AIMD-adaptive), token-bucket rate pacing, per-host circuit breaker (open/half-open/closed), retry limited to transient + idempotent requests, and a hard per-session **global budget (5,000 requests)** as an anti-self-DoS guard. One failed item never fails the batch.
- **Baseline diff:** sends baseline + exploit in one call and reports status/length/timing/byte-identity deltas — the raw material for the impact gate.
- **Encoding toolkit (11 codecs):** `url`, `url-all`, `url-double`, `base64`, `base64url`, `hex`, `html-dec`, `html-hex`, `unicode`, `upper`, `lower`, chainable into pipelines — the basis for WAF-bypass encoding.
- **curl export:** every replay returns a single-quoted, copy-pasteable `curl` equivalent as evidence.
- **Scope guard:** a replay can only target an already-captured host (SSRF guard), and constructed-target responses are persisted for retest and verification tokens.

The single biggest change. The old monolithic web-application agent (and its per-transaction "proxy agents") is gone. In its place: a roster of **WSTG-aligned specialist agents**, driven by a **deterministic dispatcher**, gated by **evidence**.

Defined in `@cyberstrike-io/web` (`provider-web.ts`), each mapping 1:1 to a WSTG top-level category (routing throws if two agents claim the same class):

| Agent | WSTG section |
|---|---|
| `wstg-info-gathering` | 4.1 Information Gathering |
| `wstg-config-deploy` | 4.2 Configuration & Deployment Management |
| `wstg-identity-mgmt` | 4.3 Identity Management |
| `wstg-authentication` | 4.4 Authentication |
| `wstg-authorization` | 4.5 Authorization |
| `wstg-session-mgmt` | 4.6 Session Management |
| `wstg-input-validation` | 4.7 Input Validation (injection, SSRF, file-upload, mass-assignment, header injection) |
| `wstg-error-handling` | 4.8 Error Handling |
| `wstg-cryptography` | 4.9 Cryptography |
| `wstg-business-logic` | 4.10 Business Logic |
| `wstg-client-side` | 4.11 Client-side (DOM-XSS, CORS, open-redirect, postMessage, clickjacking) |
| `wstg-api` | 4.12 API Testing + OWASP API Top 10 |
| `wstg-llm` | Custom LLM/AI-security lane |

Above them sit `wstg-agent` (the orchestrator, whose prompt is composed in code from a live signal-routing table and agent roster) and the cross-cutting `escalation-hunter`.

Each specialist owns deterministic, read-first probe tools — the LLM decides *what* to test, the tool performs the test:

- **`access_probe`** — replays a captured request under every *other* session credential plus unauthenticated, and reports who got the owner's response (IDOR / BOLA / BFLA / missing authorization).
- **`session_probe`** — JWT `alg:none`, signature-not-validated, weak-HMAC dictionary, `kid` path-traversal, RS256→HS256 confusion, expired-token acceptance, `jku`/`x5u`/`jwk` SSRF surface; cookie entropy/structure.
- **`crypto_probe`** — cleartext sensitive data, missing/weak HSTS, credentials/PII in URL, mixed content; optional live TLS handshake (protocol/cipher/legacy-version/cert).
- **`error_probe`** — debug pages, stack traces, path & internal-address disclosure, verbose DB errors; active structural malformation (broken JSON, type confusion, bad content-type).
- **`identity_probe`** — predictable/sequential account identifiers, username-policy weaknesses incl. reserved names and unicode-homoglyph impersonation.
- **`login_probe`** — default-credentials, lockout, and username-enumeration modes against a captured login POST.
- **`inject_probe`** — the injection battery (below).

Fifteen vulnerability classes, each a dedicated probe module: **XSS** (reflected tag-survival + self-submitting-page PoC), **blind/time-based SQLi**, **NoSQL / LDAP / XPath** error-and-boolean differentials, **SSTI** (arithmetic-eval), **command injection** (read-only `id`/`ver`), **LFI**, **CRLF / response-splitting**, **Host-header**, **mass-assignment** (injects `role`/`isAdmin`/`owner`), **HTTP verb tampering**, **file-upload bypass** (extension/content-type/magic-byte spoof, classifies *stored* vs *executed*), and **HPP**. WAF/challenge detection plus percent-encoding mutation drive **WAF-bypass encoding**; a blocked payload is reported as "not proof of safety — escalate with evasion," never as a pass.

**SSRF** and **open-redirect** are handled out of band — SSRF through the OOB server (below), open-redirect through a dedicated impact oracle.

`InspectionDispatcher` is the engine that makes "LLM only where it matters" real:

- A transaction with no owning specialist is marked examined immediately and **never spawns a model session**. A specialist is spawned only for a transaction carrying a routed signal/credential/role/object-value, or matching the injection-surface rule. Only medium-and-above signals auto-spawn (technology signals always route, just to tag the stack).
- A continuous, event-driven **worker pool** keeps up to `CONCURRENCY` (default **3**) specialists in flight with push wakeups off the signal bus — no serializing behind one slow specialist.
- **Recovery is built in:** per-dispatch timeout cancels and retries a hung child; stale leases left by a crashed dispatcher are reclaimed; retries are bounded, after which the target is marked examined; a `.finally` re-arm re-drains on any lost wakeup.

- **Evidence gate** (`verification.ts`): `http_replay` records a SHA-256 token over session + request-id + status + body-prefix. A finding cannot move draft → triaged unless such a token exists *and* was produced from one of the finding's own evidence request-ids.
- **Impact oracle** (`impact-oracle.ts`): verdicts `proven / downgraded / insufficient / unmodeled`. Open-redirect is only proven on a realized off-site non-IdP 302; reflected XSS is downgraded until a browser canary executes; access/IDOR/authz require a success-vs-baseline-denial differential or they fall to "insufficient."
- **Severity caps** (`vuln-scope.ts`): per-pattern and per-class ceilings (CORS → medium, missing-headers → low, authorization → critical, input-validation → critical, …). The gate is ceiling-only — it never raises a severity.
- **Dedup fence** (`vulnerability.ts`): report-time similar-finding detection upgrades a weak candidate in place instead of duplicating it, and merges one-issue-across-many-endpoints into a single aggregate.

- **`escalation-hunter`** runs after the specialists, across all WSTG lanes, with a **loadable chain catalog** (`escalation-catalog.ts`): built-in patterns (`ssrf-internal`, `idor-mass`, `redirect-oauth`, `cors-token`, `bfla-privesc`, `jwt-authz`, …) plus zod-validated external packs loaded from a directory. A deterministic frontier seeds hypotheses before the model, with hard budgets on proposals.
- **Assessment completion supervisor** (`supervisor.ts`): a watchdog on the `session.idle` event that re-wakes the deterministic runners first, and only re-prompts the root model (`[auto-resume]`) when coverage is genuinely incomplete — then automatically resumes when new browser traffic arrives. Bounded by debounce, recheck interval, and max-wake caps so it can never loop.
- **Self-hosted OOB interaction server** (`cyberstrike oob`): a DNS + HTTP callback server for `*.<domain>` that confirms blind vulnerabilities — blind SSRF, blind command injection, blind XXE, OOB SQLi/SSTI, DNS exfiltration — via `oob_generate` / `oob_check` tools. No third-party interaction service required.

- **Discovery engine:** crawl, JS-bundle route & secret mining, source-map parsing, OpenAPI import, well-known path probing, and API endpoint probing feed a per-session endpoint-template normalization cache.
- **Per-role credential capture:** authentication is now captured **per origin/host** (tracking `authorization`, `cookie`, `x-api-key`, `x-csrf-token`, and friends), fixing the old flat-blob capture that replayed the wrong identity across hosts. Roles carry a privilege `level`, are scheduled through a role queue, and each spawns its own browser profile — which is what makes cross-identity `access_probe` meaningful.

HackBrowser was rebuilt around AI-driven navigation and a real browser extension.

- **`LlmNavigator`** — "the system observes, the LLM interprets": the main model plans over rich page-state and falls back to a `DeterministicNavigator` on any model failure. Works with thinking/reasoning models.
- **Framework fingerprinting** (`tech.ts`) classifies client/meta-framework/server and SPA-vs-SSR rendering, feeding the navigator's reasoning; a **framework-adaptive executor** acts accordingly.
- **DataCollector** records every ingested request and classifies it (`api` / `html` / `js` / `static` / `realtime` / `noise`), decoupled from AI coverage.
- **JS-bundle route mining, secret scanning, and source-map parsing** recover endpoints and leaked secrets (AWS keys, Google API keys, GitHub/Slack tokens, JWTs — values redacted `first4…last4`) from minified bundles and their source maps.
- The old 1,859-line crawl monolith was split into ~17 focused modules with a shared probe runner (the **R0–R2** refactor).
- **Crash safety:** browser-death detection ends the crawl instead of hanging, a worker-crash net stops one throw from killing the crawl, spawned browsers are `SIGKILL`'d on teardown, and frontier URLs are marked visited on navigate so redirects can't spin the crawl.

A real MV3 extension (**CyberStrike – HackBrowser**) now ships with the appliance and desktop app:

- A draggable **CyberStrike panel** and **co-driving overlay** (each in a closed shadow root): a logo disc that cycles the driver **AI → Human → Idle** with a viewport tint, a HUD showing live stats and the last few lines of AI reasoning, a synthetic cursor with a reason bubble, role-colored badges for spawned credential profiles, and a settings panel (server connect, capture, session, roles, stats, reasoning).
- A **direct control channel to the CyberStrike server** — the intermediate receiver is gone. The service worker talks straight to the server over HTTP plus a `/web/control` WebSocket for click/type/navigate relaying, and self-closes if the control channel drops.
- A **multi-profile credential launcher**: "+ add credential" in the panel registers a role, and each role spawns its own Chrome-for-Testing profile with a colored badge.

Three cloud domain packages (`@cyberstrike-io/aws`, `@cyberstrike-io/azure`, `@cyberstrike-io/gcp` — all AGPL, free tier) plug into one provider-agnostic orchestrator.

- **AWS — 174 programs** across recon, credential harvesting, privilege escalation, persistence, lateral movement, defense evasion, exfiltration, compliance, identity, and impact.
- **Azure — 156 programs** (incl. an M365 lane).
- **GCP — 34 programs** across a 4-phase assessment (identity, infrastructure, privesc, compliance).

Every offensive program is **detection-mapped** — it appends the CloudTrail event and GuardDuty finding it would trigger — so an operator always knows the blast radius on the blue-team side. AWS actions are gated by an **IAM policy pre-flight** (`aws iam simulate-principal-policy`) before anything privileged or destructive runs, including a 21-vector automated privilege-escalation-path scan.

One engine (`cloud/orchestrate.ts`), driven through the `AssessmentProvider` interface, serves all three clouds. Over the Layer-1 scan findings it runs a Layer-2 agentic pipeline: `identity → triage → parallel → sync → followup → verify → complete`, with a watchdog that self-spawns helper analysts on scale signals or stuck agents.

- **Analyst subagents** (one per service group): **AWS 9** (identity/compute/network/data/serverless/privesc/persistence/compliance/exposure), **Azure 9** (adds a security/access/specialized split), **GCP 6**.
- **Shared agents** on every cloud: `cloud-orchestrator`, `cloud-batch-verifier`, `cloud-followup` (link-by-link chain verification), `cloud-verify` (final validation), and the red `escalation-hunter` (chains confirmed findings toward account takeover / cross-account pivot / mass exfil).
- Agents are no longer hardcoded — a **`specsToAgents` bridge** turns each provider's declarative `AgentSpec`s into host agents at registry-build time, which is how the web, cloud, mobile, and internal-network specialists are all collected from the domain registry rather than baked into core.

A provider-agnostic inventory graph — **`CloudAsset`** (resources & principals), **`CloudEdge`** (RBAC assignments, managed identities, key/secret access, peering, group membership, data flow), **`CloudExposure`** (public IPs, open NSG rules, public buckets/snapshots, wildcard policies, privilege-escalation paths, cross-account trust, stale credentials, dangling DNS) — is traversed deterministically by `detectCloudChains`. **7 chain patterns** (privilege-escalation, lateral-movement, data-exfiltration, subdomain-takeover, credential-harvest, identity-pivot, network-path) emit candidates with a testing plan and a confidence score; high-confidence chains are queued directly, lower-confidence ones go to an LLM pass. This replaces the old LLM-guessed follow-up detection.

2.0 turns CyberStrike into an extensible platform. The cloud and web packages above are just the first consumers of a public authoring contract.

- **Native domain plugins (not MCP):** a domain package default-exports `(input) => Promise<Hooks>`. The host injects a live runtime as `input.core` (typed `CoreRuntime`); packages import only *types* from `cyberstrike/public`, which are erased at build — no host module resolution, no version coupling beyond the Core API.
- **Core API versioning:** `CORE_API_VERSION = "2.0.0"`. A plugin calls `requireCoreApi("x.y.z")` in its factory and fails fast into the health report if the host is too old. Adding a surface member is a minor bump; removing or changing one is a major bump. (2.0.0's major bump removed the old built-in signal fabric — Vortex is now the sole signal producer.)
- **Custom tools:** a plugin contributes tools through the `tool` hook (`tool({ description, args: {…zod…}, execute })`); the host registers them into the same registry its own tools use, and agents allow them by name.
- **Hooks:** the contract exposes a broad event surface — `event`, `config`, `tool`, `provider`, `auth`, `chat.message`, `chat.params`, `chat.headers`, `permission.ask`, `command.execute.before`, `tool.execute.before/after`, `shell.env`, `tool.definition`, plus experimental transforms for chat messages, system prompt, compaction, and completion.
- **The `web` building-block kit** (`input.core.web`): a "Lego" surface for building web security tools — the governed-send seam, the lossless `HttpMessage` model and pure `Mutate`/`Apply`/`Observe`/`Encode` transforms, the replay engine (`Send`/`Batch`/`Governor`), the captured-traffic store, and webhook-tool shells — so a third-party web tool gets the same governed, in-scope request machinery the first-party probes use.
- **Static manifest + auto-discovery:** each package declares a `cyberstrike` field (`coreApi`, `domains`, `tools`, `tier`) in its `package.json`; the host discovers installed domains from `node_modules` with a static Core-API pre-flight — no import needed to know what's there. Inspect it all with `cyberstrike domains list` / `cyberstrike domains info <name>`.

- **Tabbed multi-session v2 shell** is now the default on Web and Desktop — tabs, a home page, a command palette, and session avatars with live progress.
- **Electron desktop app** (macOS / Windows / Linux) with a bundled server sidecar and CyberStrike branding; Windows MSI and macOS pkg managed-deploy targets with signing/notarization.

New/unified slash commands: `/pin` (Alt+1–9 quick-switch), `/timestamps`, `/thinking`, `/web` (context viewer), `/skills` (browser), `/rename`, `/copy`, `/timeline`, `/status`, `/help`, plus real Methodology and Report dialogs on the web app.
- **Canonical severity colors everywhere** (crit+high = red, medium = orange, low = yellow, info = gray) and a unified vulnerability display format across TUI/Web/Desktop, with a vulnerability detail panel (severity badges, triage lifecycle, Bugcrowd-format export) and a Vortex Signals sidebar.
- **21 palette themes** with automatic v2 token derivation, and a log viewer under Settings → Help → Logs.
- The web/desktop model selector now persists server-side, so the model you pick is the model every out-of-band action (navigator, compaction, idle resume) actually uses.

- Migrated Anthropic OAuth/subscription to **LanguageModelV3**; `@ai-sdk/*` pins aligned to v6-native.
- Claude models route through the Anthropic **Messages API**; GPT-5 Copilot models through the **Responses API**; GitHub OAuth tokens are exchanged for Copilot session tokens with a one-shot 403 retry.
- Stalled provider streams are aborted instead of hanging the loop forever; LLM retry is capped at 5 with `undefined` `finishReason` handled.

---

- **2.0 is a major version.** Domain plugins must target `CORE_API_VERSION 2.0.0`; the built-in signal fabric that older plugins may have used was removed in favor of Vortex — read a plugin's signals from `input.core.web.signal` (Vortex) instead.
- **Web testing is now dispatcher-driven.** If you scripted against the old monolithic web agent or the `hunt-*` / per-vuln agents, those are retired; drive assessments through the WSTG roster and let the dispatcher route.
- **The OOB server is opt-in infrastructure.** Blind-vulnerability confirmation needs `cyberstrike oob` reachable (set `CYBERSTRIKE_OOB_DOMAIN` / `CYBERSTRIKE_OOB_IP`); without it, blind classes degrade gracefully rather than failing.
- **Model selection is server-side now.** Picking a model in the web/desktop UI persists it for the whole session, including background actions — no more silent fallback to the catalog default.
